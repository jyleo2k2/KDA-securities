## 한 줄 정의

**"DC형 퇴직연금·IRP·연금저축계좌를 보유했지만 계좌별 차이와 운용 방법을 모르는 이용자에게, 각 계좌의 역할·제약과 전체 자산구성을 쉽게 설명하고 투자 뉴스·정보·자문형 콘텐츠를 함께 전달하는 AI 연금계좌 운용 가이드."**

핵심 차별화: 자동으로 운용하는 일임 서비스가 아니라, 계좌 진단·랭킹·포트폴리오 참고·챗봇 Q&A로 근거를 제공하고 **실제 주문 실행은 이용자가 직접** 하는 자문·정보 제공형 서비스. (2026-07-14 교육형 → 자문형 전환)

## 확정된 핵심 결정 (2026-07 기준)

- **아이템**: 온보딩·계좌 선택 → 내 연금 포트폴리오 홈(원그래프·일일/주간 가이드) → 연금가이드 챗봇(용어·상품 정보·전략) → 공개 포트폴리오 벤치마킹 → 실행은 이용자가 금융사 공식 채널에서 직접. 화면 상세: [화면_유저플로우.md](./docs/10_기획/화면_유저플로우.md)
- **페르소나**: 세 연금계좌 중 하나 이상을 보유했지만 계좌별 역할과 운용 방법을 몰라 납입 후 방치하거나 전체 자산구성을 파악하지 못하는 직장인
- **차별화(재정의, 2026-07-14)**: **3계좌 통합 포트폴리오 × 출처 기반 일일·주간 투자정보 × 설명 가능한 연금가이드 × 익명 공개 포트폴리오 벤치마킹**. 전망은 외부 출처와 시나리오로 구분하고, 실제 주문·자동운용은 하지 않는다.
- **AI 설계**: 규칙 기반 엔진이 계산, LLM은 서술·Q&A만 (Explainable by Design) + 하네스 엔지니어링
- **계좌 투자 규칙(엔진 근거, 2026-07-13)**: DC형·IRP에는 퇴직연금 위험자산 한도와 예외 규칙을 적용하고, 연금저축계좌에는 별도의 상품 적격성·제한 규칙을 적용한다. 계좌별 규칙을 혼합하지 않는다.
- **확정 스택**: React + TypeScript + Vite 기반 모바일 PWA → FastAPI → Supabase PostgreSQL/pgvector. Python 규칙 엔진이 계산·판단하고 Claude API 하네스는 설명·Q&A만 담당
- **데이터**: 통합연금포털(FSS) OpenAPI 실호출 공시(+KRX 보조) + NAVER 검색 API 뉴스 메타데이터 + 공식 문서 RAG + 세 연금계좌 시나리오 목데이터 3종
- **저장 경계**: 공시·목계좌·실행 이력·뉴스 메타데이터는 PostgreSQL, 공식 지식 문서 청크는 pgvector, 개인 계좌 데이터는 RAG에 넣지 않음
- **개발 도구**: Claude Code + Codex 병행(진입점 `CLAUDE.md`/`AGENTS.md` 동기화). 데이터 기반 1~7 코드·로컬 계약 검증 완료, 원격 PostgreSQL 통합검증 대기
