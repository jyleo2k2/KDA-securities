## 한 줄 정의

**"DC형 퇴직연금·IRP·연금저축계좌를 보유했지만 계좌별 차이와 운용 방법을 모르는 이용자에게, 각 계좌의 역할과 제약을 구분해 알려주는 AI 연금계좌 운용 가이드."**

핵심 차별화: 상품을 대신 골라주거나 자동으로 운용하는 서비스가 아니라, 세 연금계좌의 개별 상태와 전체 자산구성을 함께 이해하고 스스로 운용 결정을 내리도록 돕는 설명형 서비스.

## 확정된 핵심 결정 (2026-07 기준)

- **아이템**: DC형·IRP·연금저축계좌 역할 비교 → 계좌별 진단 → 전체 연금자산 통합 보기 → 교육용 운용 예시·시뮬레이션 → 계좌별 다음 행동 선택
- **페르소나**: 세 연금계좌 중 하나 이상을 보유했지만 계좌별 역할과 운용 방법을 몰라 납입 후 방치하거나 전체 자산구성을 파악하지 못하는 직장인
- **차별화(재정의, 2026-07-13)**: **3개 연금계좌 구분 × 개별·통합 진단 × 설명 가능한 시뮬레이션**. 자동운용·상품제시 기능과 경쟁하기보다 이용자가 계좌별 규칙과 전체 자산배분을 이해하게 만드는 연금 운용 학습 레이어로 포지셔닝한다.
- **AI 설계**: 규칙 기반 엔진이 계산, LLM은 서술·Q&A만 (Explainable by Design) + 하네스 엔지니어링
- **계좌 투자 규칙(엔진 근거, 2026-07-13)**: DC형·IRP에는 퇴직연금 위험자산 한도와 예외 규칙을 적용하고, 연금저축계좌에는 별도의 상품 적격성·제한 규칙을 적용한다. 계좌별 규칙을 혼합하지 않는다.
- **산출물**: 모바일 중심 PWA + FastAPI + Claude API 하네스, 팀 ~5명(미정)
- **데이터**: 고용노동부·금융위원회·통합연금포털·KRX·금융회사 공개 데이터 + 세 연금계좌 시나리오 목데이터 3종
- **개발 도구**: Claude Code + Codex 병행(진입점 `CLAUDE.md`/`AGENTS.md` 동기화). 도구별 로컬 강제(`.claude/settings.json` 등)는 서로 호환 안 됨 → **공용 강제는 CI로** (코드 생기면)
