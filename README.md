> 최종 갱신: 2026-07-10

> **진입점**: 세션 시작 시 [CLAUDE.md](./CLAUDE.md)(Claude Code) / [AGENTS.md](./AGENTS.md)(Codex)가 자동 로드된다(30초 오리엔테이션, 두 파일 내용 동기화). 이 README는 전체 지도.

## 한 줄 정의

**"방치된 3층연금을 통합 진단하고, 근거를 설명하는 AI가 리밸런싱을 제안하면, 유저가 원탭으로 실행하는 모바일 연금 코파일럿."**

핵심 차별화: 경쟁사는 *대신 굴려주는* AI(일임), 우리는 *스스로 굴리게 돕는* AI(자문형 + 설명가능).

## 확정된 핵심 결정 (2026-07 기준)

- **아이템**: 3층연금 통합 진단 → 설명가능 AI 리밸런싱 제안 → 원탭 실행 (자문형, 일임 아님)
- **페르소나**: 연금 방치형 3040 직장인
- **차별화(재정의, 2026-07-10)**: **3층통합 × 설명가능 × 자문형 실행**이 겹치는 빈칸을 차지. 키움 기존 AI 스택 **키우GO(굴리기) ↔ 키우Me(챗봇) 사이의 "연금 특화 설명 레이어"**로 포지셔닝. 방어점은 기술(RA·MPT는 업계 표준, 해자 아님)이 아니라 **① 포지셔닝 ② 설명=규제대응(금소법 설명의무·적합성) + 통합연금포털 실공시 근거**. → 현직자 검증 예정.
- **AI 설계**: 규칙 기반 엔진이 계산, LLM은 서술·Q&A만 (Explainable by Design) + 하네스 엔지니어링
- **계좌 투자 규칙(엔진 근거, 2026-07-10)**: 연금계좌(DC·IRP·연금저축)는 **개별주식 불가·국내상장 ETF/펀드만·해외직구 불가·파생형 제한** → 스코어링 후보 풀 한정 + 한도검사 1차 게이트 ([pension-basics.md §4-1](./pension-basics.md))
- **산출물**: 모바일 중심 PWA + FastAPI + Claude API 하네스, 팀 ~5명(미정)
- **데이터**: 공개 데이터 전부(통합연금포털·KRX/OpenAPI), 사용자 계좌는 시나리오 목데이터 3종
- **개발 도구**: Claude Code + Codex 병행(진입점 `CLAUDE.md`/`AGENTS.md` 동기화). 도구별 로컬 강제(`.claude/settings.json` 등)는 서로 호환 안 됨 → **공용 강제는 CI로** (코드 생기면)
