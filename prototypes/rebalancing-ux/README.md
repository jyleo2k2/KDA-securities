# 리밸런싱 답변 UX 검토 프로토타입

챗봇 "리밸런싱 점검해줘" 답변이 길고 한눈에 안 들어온다는 문제를 눈으로 비교하기
위한 정적 화면이다. 왼쪽은 현재 배포된 렌더 순서를 그대로 옮긴 기준선, 오른쪽은
제안 6건을 개별로 켜고 끌 수 있는 비교 대상이다.

실제 앱 코드는 건드리지 않는다. 이 폴더 안에서만 동작하는 독립 화면이다.

## 여는 방법

`index.html`은 `type="module"` 스크립트를 쓴다. 파일을 더블클릭해서 `file://`로
열면 CORS 때문에 화면이 비어 보인다. 정적 서버로 띄운다.

```powershell
cd prototypes/rebalancing-ux
python -m http.server 8777
```

그다음 `http://127.0.0.1:8777/index.html`로 접속한다.

## 화면 구성

상단 바에서 폭을 390px과 360px로 바꾼다. 왼쪽 목록의 제안 6건은 서로 독립이라
어떤 조합으로도 켤 수 있고, `제안 전부 적용`과 `초기화` 버튼이 있다.

측정값 3개는 프레임을 다시 그릴 때마다 실제 DOM을 재서 갱신한다. 결론
(`먼저 볼 내용`)이 보이기까지 필요한 스크롤 px, 표의 가로 스크롤 발생 여부,
답변 블록 전체 높이다. 각 프레임 아래 캡션에 기준선 대비 개선폭을 함께 적는다.

## 제안 6건

| 키 | 우선순위 | 내용 |
|---|---|---|
| `lead` | P1 | `먼저 볼 내용`을 헤더 직후로 승격하고, 첫 줄을 전략 이름이 아니라 발견으로 바꾼다 |
| `bars` | P1 | 자산배분 표를 0 기준 좌우 드리프트 바로 바꾸고 원래 표는 `숫자로 보기` 안에 넣는다 |
| `nest` | P1 | 카드 3겹 중 바깥 하나만 남기고 안쪽 둘은 구분선 밴드로 바꾼다 |
| `defer` | P2 | 성향별 섹터 도넛과 점검 주기를 접기 안으로 옮긴다 |
| `hedge` | P2 | 쏠림 확인 문단을 한 줄로 줄이고 나머지는 `어떻게 계산했나요?` 안에 넣는다 |
| `type` | P3 | 8~10px 글자를 11px 이상으로 올리고 부족·초과 금액을 함께 보여준다 |

## 측정 결과 (2026-07-27, 로컬 Chromium)

390px에서 제안 6건을 모두 켰을 때다.

| 지표 | 기준선 | 전부 적용 |
|---|---|---|
| 결론까지 스크롤 | 561px | 0px |
| 가로 스크롤 | 있음 | 없음 |
| 답변 높이 | 1,629px | 1,312px (19% 감소) |

360px도 575px에서 0px, 1,643px에서 1,346px(18% 감소)로 같은 방향이다.

개별로 보면 기여도가 갈린다. `defer`가 높이 감축이 가장 크고(단독 25%),
`lead`는 높이에는 영향이 없지만 결론까지의 스크롤을 없애는 유일한 항목이며,
`bars`는 가로 스크롤을 없애는 유일한 항목이다. `type`은 단독으로 켜면 글자가
커진 만큼 높이가 오히려 157px 늘어나므로 다른 제안과 함께 켜야 상쇄된다.

## 기준선을 만든 근거

`frontend/src/components/PortfolioHoldingsPanel.tsx`의 `EducationalPortfolioReview`
렌더 순서를 그대로 옮겼다. 색·치수·자산군 라벨·상태 배지는
`frontend/src/index.css`의 `.portfolio-review` 계열 값과 `.guide-tab` 스코프
토큰을 따랐고, 상단 상태바는 `frontend/src/components/StatusBar.tsx`의 마크업과
SVG path를 복제했다. 프레임 치수는 `index.css`의 `--phone-frame-*` 값을 쓴다.

표는 이전 검토 메모에 7열로 적혀 있었으나 PR #396에서 이미 4열로 줄었다. 기준선은
실제 배포 상태와 맞추기 위해 4열로 재현했다. 4열이어도 `min-width: 320px` 때문에
가로 스크롤은 그대로 발생한다.

화면에 쓰인 숫자는 비교용 입력값이며 특정 상품 권유나 미래 성과 예측이 아니다.
