# 핸드오프: 팀에 "하네스 엔지니어링" 도입하기

## 0. 이 문서를 받은 Claude에게 (먼저 읽어줘)
너는 지금 다른 Claude 세션의 작업을 이어받았어. 사용자는 **AI를 거의 안 써본 팀원들**에게
"하네스 엔지니어링"을 설명하고, 팀 프로젝트에 도입하려는 개발자다.
- 톤: 전문용어 최소화, 비유 위주, 한국어, 짧고 직설적.
- 네 임무: ①아래 개념을 팀원 눈높이로 더 풀어주거나 ②팀 상황에 맞춰 도입 계획을 구체화.
- 먼저 물어볼 것: "팀 규모? 어떤 도구 쓰나(Cursor/Claude Code/ChatGPT)? 코드베이스 언어?"
  → 답에 따라 아래 5계층을 그 팀에 맞게 재작성해줘.

---

## 1. 한 문장 정의 (비전문가용)
**AI 모델은 '천재 신입사원'이고, 하네스는 그 신입에게 주는 '사내 규정집 + 권한 카드 + 체크리스트'다.**
- 신입(모델)은 똑똑하지만 우리 회사 규칙·맥락을 모른다.
- 하네스 엔지니어링 = 그 신입이 사고 안 치고 일 잘하도록 **환경을 설계하는 일**.
- 핵심 공식: **에이전트 = 모델 + 하네스.** 모델은 우리가 못 바꾸니, 우리가 손댈 건 하네스다.

## 2. 왜 팀에 필요한가 (3줄)
1. 같은 AI라도 하네스만 잘 짜면 성능이 크게 오른다 (벤치마크상 +10%p 이상 사례 흔함).
2. AI가 한 실수를 **규칙으로 박제**하면 팀 전체가 두 번 다시 안 겪는다.
3. "각자 알아서 AI 쓰기" → "팀 공통 규칙으로 AI 쓰기"로 바뀌어 결과가 일정해진다.

## 3. 5계층 — 일상 비유로
| 계층 | 한 줄 | 비유 |
|---|---|---|
| **메모리** | 프로젝트 규칙·함정을 적은 파일 (예: `CLAUDE.md`) | 신입 책상에 붙여둔 사내 매뉴얼 |
| **도구** | AI가 쓸 수 있는 명령·외부 연결 | 신입에게 주는 사번·시스템 접근권 |
| **권한** | 해도 되는 것 / 막는 것 | "이 폴더는 건드리지 마" 출입 통제 |
| **훅(Hook)** | 특정 순간 **자동 강제** 실행 | 퇴근 전 무조건 돌아가는 보안 점검 |
| **관측** | 무엇을 했는지 로그·테스트 | CCTV + 작업 검수 |

**가장 중요한 한 줄**: 규칙을 '부탁(프롬프트)'이 아니라 '강제(훅·권한)'로 만들면 진짜 하네스다.
> 예: "코드 고치면 테스트 돌려줘"(부탁) → 코드 저장 시 테스트가 **자동으로** 돌아 실패하면 막힘(강제).

## 4. 팀 도입 4단계 (실행안)
1. **공통 메모리 파일 1개 만들기** — 프로젝트 규칙·자주 나는 실수·하지 말 것을 적는다.
   팀원 누구나 PR로 한 줄씩 추가 (= "래칫": 실수 1건 = 규칙 1줄 영구 추가).
2. **자동 검증 훅 1개** — 코드 저장/커밋 시 테스트·린트 자동 실행. AI 추측을 원천 차단.
3. **권한 공유 설정** — 위험한 명령은 막고, 자주 쓰는 안전한 명령은 미리 허용해 마찰 줄이기.
4. **반복 작업은 슬래시 명령으로** — "새 기능 추가 절차" 같은 의식을 `/명령` 하나로 표준화.

> 처음엔 1·2번만. 3·4번은 팀이 익숙해진 뒤. (과설계 금지)

## 5. 비전문가 팀원이 자주 하는 질문 (미리 답)
- **Q. AI가 알아서 잘하는데 왜 규칙이 필요?**
  → 알아서 잘하지만 '우리 방식'은 모른다. 규칙이 없으면 사람마다 결과가 다르다.
- **Q. 어렵지 않나?**
  → 새 도구 학습이 아니라 '메모 파일 관리'에 가깝다. 코드보다 글쓰기다.
- **Q. AI가 또 같은 실수를 한다.**
  → 그게 정상. 실수를 메모리 파일에 적는 순간 다음부터 안 한다. 그게 핵심 작동방식.

## 6. 다음 액션 (Claude가 이어서 할 일)
사용자에게 팀 정보를 물은 뒤, 위 5계층과 4단계를 **그 팀의 실제 스택에 맞춘 버전**으로 다시 써줘.
산출물 목표: 팀이 그대로 따라 할 수 있는 "하네스 도입 1페이지 가이드" + 첫 메모리 파일 템플릿.
