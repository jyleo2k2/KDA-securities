# AI 팀 부트스트랩 플레이북 — 새 프로젝트를 맨땅에서 시작하기

> **이 문서를 읽는 대상 = AI(Claude 또는 Codex)다.**
> 사람(주로 팀장)이 이 문서를 너에게 통째로 준다. 너는 이 플레이북을 따라,
> 그 팀의 **새 프로젝트를 맨땅에서** 다음 순서로 세운다:
>
> **① 코드/아키텍처 설계 초안 → ② 역할 배분(폴더=경계) → ③ 협업 하네스 구축**
> **(헌장 + 팀원별 복붙 프롬프트팩 + `CLAUDE.md`/`AGENTS.md` 진입점 + `settings.json` 권한·자동검증 훅)**
>
> **전제:** 대상 팀은 코드·레포·PR이 있는 개발/IT 프로젝트지만, **팀원 다수가 AI를 거의 안 써봤고
> IT 도메인도 약하다.** 그래서 모든 산출물은 **"팀원은 복붙만 하면 되고, 판단·검증은 하네스가,
> 생성은 AI가"** 라는 원칙을 따른다.
>
> **이 문서는 특정 프로젝트에 묶이지 않는다.** 프로젝트 고유값(제품 정의·스택·팀원 등)은
> 네가 §1에서 **사람에게 물어** 채운다. 절대 지어내지 마라.

---

## 0. 하네스란 무엇인가 — 네가 만드는 것의 정체

먼저 네가 무엇을 만드는지 정확히 알아야 한다. **에이전트 = 모델 + 하네스.** 모델(너의 두뇌)은 우리가
못 바꾼다. 우리가 손대는 건 **하네스 = 모델을 둘러싼 환경**이다. 하네스는 5계층으로 이뤄진다:

| 계층 | 한 줄 | 이 플레이북이 만드는 산출물 |
|------|-------|------------------------------|
| **메모리** | 프로젝트 규칙·함정을 적은 파일 | 헌장 · `CLAUDE.md`/`AGENTS.md` · 팀원 문서 |
| **도구** | AI가 쓸 수 있는 명령·연결 | (스택에 내장 — 실행/테스트 명령) |
| **권한** | 해도 되는 것 / 막는 것 | `settings.json` allow/deny |
| **훅(Hook)** | 특정 순간 **자동 강제** 실행 | `settings.json` PostToolUse 자동검증 |
| **관측** | 무엇을 했는지 로그·테스트 | 테스트 실행 결과·git |

> **🔑 가장 중요한 원칙: 규칙을 '부탁'이 아니라 '강제'로 만들어라.**
> "코드 고치면 테스트 돌려줘"(부탁 = 프롬프트)는 잊히고 무시된다.
> "코드를 저장하면 테스트가 **자동으로** 돌아 실패 시 막힌다"(강제 = 훅·권한)가 진짜 하네스다.
> 이 플레이북의 §3은 **문서(메모리)뿐 아니라 권한·훅(강제)까지** 깐다 — 그게 핵심이다.

## 0-1. 너(AI)가 이 문서를 쓰는 법

너는 다음 루프를 **단계마다 사람 승인을 받으며** 돈다. 한 번에 전부 쏟지 마라.

1. **묻는다** — §1 입력 체크리스트 중 빠진 게 있으면 추측 말고 먼저 물어라.
2. **설계한다** — §3 절차를 순서대로 실행한다. 각 Step 끝에서 산출물을 보여주고 "이대로 진행할까요?"를 묻는다.
3. **파일로 굳힌다** — 승인되면 그 Step 산출물을 **즉시 파일로 저장한다.** 다음 Step은 머릿속 기억이 아니라
   **그 파일을 다시 읽고** 시작한다. (대화가 길어지면 초반 결정이 흐려진다 — 파일이 항상 기준이다.)
4. **검증한다** — 마지막에 §6 자가검증 + 기계적 게이트로 점검하고 정직하게 보고한다.

> 핵심 마인드셋: 너는 단순히 "코드를 짜는 AI"가 아니라 **"AI를 못 쓰는 팀원도 AI를 잘 부리게 만드는
> 협업 골격과 사용설명서를 깔아주는 AI"**다. 산출물의 독자는 둘 — ① 비전문 팀원(사람) ② 그 팀원이 부릴 AI.

## 1. 입력 체크리스트 (사람에게 받을 것)

시작 전 아래를 확보한다. 모르면 묻는다. **하나라도 비면 그 칸은 표류한다.**

| 항목 | 왜 필요한가 | 없을 때 |
|------|-------------|---------|
| **제품 한 줄 정의** | 헌장 §0(정체성)에 박제 | 반드시 물어라. 이게 없으면 전부 표류 |
| **확정 결정 / 바꾸면 안 되는 것 3~7개** | 범위 확장·임의 변경 차단 | "절대 바뀌면 안 되는 규칙"을 물어라 |
| **기술 스택** | 아키텍처·실행환경·git 규칙 | 언어/프레임워크/빌드·실행 명령을 물어라 |
| **테스트·린트 명령** | 자동검증 훅(§3 Step7)에 필수 | 물어라. 없으면 "나중에 추가" 표시 |
| **팀원 명단 + 강점/약점** | 폴더 경계·역할 배정 | 이름·인원·각자 잘하는 것 물어라 |
| **단일 진실 소스(SSOT) 우선순위** | 문서 충돌 시 판단 기준 | "충돌하면 무엇을 따르나?"를 물어 정해라 |
| **레포 구조 / 모노레포 여부** | 폴더=경계 분할·진입점 위치 | 물어라. 신규면 §3 Step 2에서 네가 제안 |
| **사용 AI 도구** | 진입점 파일 결정 | "Claude를 쓰나, Codex를 쓰나, 둘 다인가?" 물어라 |

### 1-1. 입력이 비거나 비정형일 때 (실패 경로 — 반드시 처리)

해피패스만 가정하지 마라. 아래 상황이면 그 자리에서 멈추고 분기한다:

- **확정 결정을 "모르겠다"** → 지어내지 말고, 흔한 후보 3~4개를 *예시로* 제시해 고르게 하라.
  (예: "결제는 외부 PG만 쓴다 / 데이터는 로컬에만 저장 / MVP에 회원가입 없음" 같은 후보)
- **테스트·린트가 없다** → 자동검증 훅을 비워두지 말고, 최소한 **placeholder 미치환 검사**나
  lint라도 훅에 건다(§3 Step7). "테스트는 골든패스 생긴 뒤 추가"로 헌장 함정에 적어라.
- **팀원 1명** → 폴더=경계가 무의미하다. 역할 배분 대신 **작업 영역별 폴더**(예: `app/`·`infra/`)로 나누고
  팀원 문서는 1개만 만든다.
- **역할이 폴더로 안 잘린다**(풀스택 1인 + 디자이너 등) → 폴더 대신 **계약(인터페이스) 경계**로 나누고,
  공유 파일은 "변경 시 PR에 계약 변경 명시 + 머지 담당 1인 지정"으로 묶어라.
- **멀티레포** → 진입점(`CLAUDE.md`/`AGENTS.md`)을 **레포마다** 둔다. 공통 헌장은 한 곳에 두고 각 레포에서 링크.

## 2. 최종 산출물 (무엇을 만드나)

절차가 끝나면 아래가 레포에 깔린다. **이 이상 만들지 마라** — 문서 비대화는 비전문 팀원 이탈 1순위 원인이다.

```
프로젝트루트/
├── CLAUDE.md                   ← ⑤ Claude 자동로드 진입점 (30초 오리엔테이션)
├── AGENTS.md                   ← ⑤ Codex 등 자동로드 진입점 (내용 동기화)
├── .claude/settings.json       ← ⑥ 권한(allow/deny) + 자동검증 훅 ★강제 장치
├── docs/ARCHITECTURE.md        ← ① 코드/아키텍처 설계 초안
└── docs/team/
    ├── _공통_AI규칙.md          ← ③ 헌장: 모든 AI가 처음 읽는 고정 규칙(가드레일)
    ├── README_팀장용.md         ← 배포·체크포인트 안내
    └── {이름}/
        ├── {이름}-담당업무.md        ← ② 무엇을(폴더 경계 + 할 일 체크리스트)
        └── {이름}-AI명령프롬프트.md   ← ④ 어떻게 AI를 시킬지(복붙 프롬프트팩) ★핵심
```

| # | 산출물 | 한 줄 | 하네스 계층 |
|---|--------|-------|-------------|
| ① | **아키텍처 설계** `docs/ARCHITECTURE.md` | 무엇을 어떤 구조로 만드나 | 메모리 |
| ② | **담당업무** `{이름}-담당업무.md` | 폴더 경계 + 할 일 목록 | 메모리 |
| ③ | **헌장** `_공통_AI규칙.md` | 모든 AI가 처음 읽는 고정 규칙 = 가드레일 | 메모리 |
| ④ | **AI명령프롬프트** `{이름}-AI명령프롬프트.md` | **복사·붙여넣기만 하면 되는 프롬프트 모음** | 메모리 |
| ⑤ | **자동로드 진입점** `CLAUDE.md`·`AGENTS.md` | 세션 시작 시 도구가 자동으로 읽는 30초 안내 | 메모리 |
| ⑥ | **권한·자동검증** `.claude/settings.json` | 위험 명령 차단 + 수정 시 테스트 **자동 강제** | 권한·훅 |

> **④와 ⑥이 이 방법론의 두 축이다.** ④(복붙 프롬프트팩)는 AI·IT에 약한 팀원이 "프롬프트 능력" 없이도
> 결과를 내게 하고, ⑥(권한·훅)은 그 결과가 **검증 없이 새어나가지 못하게** 강제로 막는다.
> 팀원의 역할은 **복붙 + '진행해' 한마디**로 축소되고, 안전은 하네스가 맡는다.

## 3. 절차 (순서대로, 단계마다 승인 → 파일로 굳히기)

### Step 1 — 제품 정체성 + 충돌 우선순위(SSOT) 잠금

가장 먼저 **"바뀌면 안 되는 것"**을 못 박는다. 비전문 팀(+AI)은 작업 중 범위를 멋대로 늘리거나
핵심을 흔드는 실수를 한다. 이를 원천 차단한다.

- §1에서 받은 **한 줄 정의**와 **확정 결정 N개**를 헌장 §0·§1의 "절대 규칙"으로 명시.
- **충돌 우선순위(SSOT)**를 한 줄로 정한다. 예) `구현 코드 > 기능명세서 > 설계문서`. 누구든 헷갈리면 이 순서로 판단.

### Step 2 — 코드/아키텍처 설계 초안

역할을 나누기 **전에** 무엇을 만드는지의 골격을 잡는다. 경계를 어디서 자를지는 구조가 정해져야 나온다.

- §1의 제품 정의·스택을 바탕으로 **주요 컴포넌트, 데이터 흐름, 폴더 구조**를 초안한다.
- **의존은 단방향으로** 정한다(예: 오케스트레이션 → 비즈니스 로직 → 도메인 모델, 역방향 import 금지).
- 외부 의존(API·DB·인증 등)과 컴포넌트 간 **계약(인터페이스)**을 명시한다 — 여기가 나중에 팀원 간 충돌 지점이다.
- 결정적인 부분과 불확실한 부분을 구분해 적는다(불확실은 `TODO: 확인 필요`). **모르는 스택 세부를 지어내지 마라.**
- 산출: `docs/ARCHITECTURE.md` 초안. 길게 쓰지 말고 한눈에 보이게(다이어그램은 텍스트/Mermaid).

> 이 단계는 "완벽한 설계"가 목적이 아니다. **역할을 겹치지 않게 자르기 위한 지도**를 만드는 것이다.

### Step 3 — 역할 배분 (폴더 = 담당 경계)

**한 사람 = 한 폴더.** 폴더 경계가 곧 책임 경계이자 충돌 방지선이다. 비전문 팀원이
"내가 어디까지 건드려도 되나"를 고민할 필요가 없어진다. (※ 팀원 1명·풀스택 등 예외는 §1-1 분기를 따른다.)

- Step 2 구조를 기준으로 각 팀원에게 폴더 1개를 배정(예: `backend/`·`frontend/`·`data/`·`infra/`).
- §1의 **강점에 맞춰** 배정하되, **경계가 겹치지 않게** 한다.
- 공유 영역(API 계약·데이터 스키마·공통 타입)은 따로 묶어 규칙을 건다:
  "변경 시 PR에 **계약 변경** 명시 + 영향받는 사람 공지 + **머지 담당 1인** 지정."

### Step 4 — 헌장(`_공통_AI규칙.md`) 작성

모든 AI가 **가장 먼저 읽는 고정 규칙**. §4-A 골격을 따른다. 반드시 포함:

- **§0 너(AI)는 누구인가** — 제품 정의 + 톤("설명은 쉽게, 용어는 풀어서").
- **§1 절대 규칙** — Step 1의 확정 결정 + 도메인 가드레일(금지 표현·금지 동작).
- **§2 작업 환경** — 인코딩 규칙·실행/테스트 명령·스택·git(브랜치→PR, main 직접 push 금지).
- **§3 일하는 방식(메타 규칙)** — "먼저 읽어라 → 계획 먼저 → 작게 쪼개라 → 모르면 표시(환각 금지) → 검증·정직 보고".
- **§4 함정 노트 (래칫)** — 처음엔 비어 있다. **같은 실수가 2번 나오면 여기에 규칙 1줄을 PR로 영구 추가한다.**
  이게 헌장을 "죽은 문서"가 아니라 **자라는 하네스**로 만든다.
- **§5 공통 READ-FIRST** — 모든 AI가 처음 읽을 파일 목록(진입점·아키텍처·헌장).

### Step 5 — 팀원별 2문서 생성 (★ 가장 중요한 단계)

각 팀원마다 `담당업무.md`(②) + `AI명령프롬프트.md`(④)를 만든다. ④는 §4-B 골격을 **반드시** 따른다:

1. **§0 사용법(사람이 읽는 부분)** — "새 대화에서 §1 보내기 → AI가 계획 보이면 '진행해' → §5로 검증".
2. **§1 온보딩 프롬프트** — READ-FIRST 파일 목록 + "아직 만들지 마, 읽고 요약만 해." (맥락 주입)
3. **§2 고정 규칙 블록** — 그 역할이 작업 중 지킬 규칙(헌장 발췌 + 역할 특화).
4. **§3 작업별 복붙 블록** — 각 블록이 `[작업]→[제약]→[검증]→[산출물]` 구조. **한 번에 하나씩**.
5. **§4 막힐 때 문장집** — "쉽게 설명해줘", "추측이면 TODO로 바꿔줘" 등 그대로 보낼 문장.
6. **§5 자가검증 프롬프트** — PR 전 AI가 스스로 점검하는 체크리스트("아니오면 고쳐서 다시 보고").

### Step 6 — 자동로드 진입점 (`CLAUDE.md` + `AGENTS.md`)

세션 시작 시 AI 도구가 **자동으로** 읽는 파일. **30초 오리엔테이션 + READ-FIRST 링크 + 절대 규칙 요약**만 담고,
상세는 헌장으로 링크한다. **내용을 중복하지 마라**(중복 = 갱신 누락 → 규칙 표류).

- **`CLAUDE.md` = Claude(Claude Code)가 자동 로드.** · **`AGENTS.md` = Codex 등이 자동 로드.**
- ⚠️ **두 파일은 서로 자동으로 안 읽는다.** Codex는 `CLAUDE.md`를 읽지 않는다. 그러니
  "한쪽만 만들고 다른 쪽이 그걸 링크" 같은 꼼수는 쓰지 마라 — 자동로드가 깨진다.
- 팀이 두 도구를 다 쓰면 **두 파일을 다 두고 내용을 동기화**한다(짧으니 사실상 복제). 한 도구만 쓰면 그쪽만.
- §1에서 "어떤 AI를 쓰나"를 받아 필요한 것만 만든다.

### Step 7 — 권한 + 자동검증 훅 (`.claude/settings.json`) ★강제 장치

여기가 **"부탁"을 "강제"로 바꾸는 단계**다. §4-D 골격으로 만든다.

- **권한(allow/deny):** 위험 명령(`rm -rf`·`git push --force`·`git reset --hard`)은 deny, 자주 쓰는 안전한
  명령(테스트·git status/diff/add/commit)은 allow로 미리 풀어 마찰을 줄인다.
- **자동검증 훅(PostToolUse):** AI가 파일을 수정(`Edit`/`Write`)할 때마다 **테스트·린트를 자동 실행**한다.
  실패하면 결과가 AI에게 되먹임되어 스스로 고친다. "테스트 돌려줘(부탁)"가 아니라 "안 돌면 진행 못 함(강제)".
- ⚠️ **테스트가 느리면**(수십 초+) 매 수정마다 돌면 거슬린다 → 빠른 단위 테스트/lint만 훅에 걸고,
  전체 회귀는 커밋 직전에 한 번만. **테스트가 아직 없으면**(§1-1) 최소 placeholder 미치환 검사라도 건다.

### Step 8 — 검증 루프

§6 자가검증 + 기계적 게이트로 산출물 전체를 점검한다. **자기 낭독으로 끝내지 마라** — 아래 기계적 검사를
실제로 돌려 결과로 보고한다(§6 참조). 막히는 지점이 있으면 그 문서가 아직 덜 된 것이다.

## 0. 사용법 (사람이 읽는 부분)

### 4-D. `.claude/settings.json` 골격 (권한 + 자동검증 훅)

> `{테스트/린트 명령}`을 프로젝트 값으로 바꾼다. 테스트가 없으면 placeholder 검사 명령으로 대체.

```json
{
  "permissions": {
    "allow": [
      "Bash({실행 명령} *)",
      "Bash(git add *)",
      "Bash(git commit *)",
      "Bash(git status)",
      "Bash(git diff *)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Bash(git push --force*)",
      "Bash(git reset --hard*)"
    ]
  },
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "{테스트/린트 명령}" }
        ]
      }
    ]
  }
}
```

## 5. 비전문 팀(저AI·저IT)을 위한 설계 원칙 (모든 산출물에 관통)

1. **복붙 우선.** 팀원이 "프롬프트를 직접 작문"하게 만들지 마라. 항상 완성된 블록을 준다.
2. **한 번에 하나.** 작업을 잘게 쪼개 한 블록 = 한 산출물. 거대한 변경은 비전문 팀원이 검증 불가.
3. **계획 → 승인 → 실행을 강제.** AI가 바로 코드 쓰지 말고 계획부터. 팀원은 "진행해"만.
4. **부탁이 아니라 강제.** 지킬 규칙은 프롬프트로 부탁하지 말고 **권한·훅(§4-D)**으로 강제하라. 잊혀도 작동한다.
5. **자가검증 + 기계 게이트.** 사람이 품질을 못 봐도, AI 체크리스트 위에 **기계적으로 떨어지는** 검사(테스트·placeholder)를 둔다.
6. **환각 차단을 문장화.** "추측이면 TODO로" 같은 한 문장을 미리 줘서 가짜 값을 거른다.
7. **쉬운 말 강제.** 헌장과 온보딩에 "용어는 풀어서, 설명은 쉽게"를 박는다.
8. **래칫.** 같은 실수 2번 = 헌장 함정 노트에 규칙 1줄 영구 추가(PR). 하네스를 자라게 한다.
9. **중복 금지.** 같은 규칙을 여러 문서에 복사하지 마라(갱신 누락 → 규칙 표류). 링크·참조만.
10. **사람 안전장치는 별도로.** 위험한 동작(배포·삭제 등)은 권한 deny + 사람 승인, 금지 표현은 헌장 §1 최상단에 고정.

## 6. 자가검증 + 기계적 게이트 (산출물 납품 전, 너가 스스로)

**A. 기계적으로 돌려서 결과로 보고할 것 (자기 낭독 금지):**

- [ ] **링크 유효성** — 문서 간 상호 링크·READ-FIRST 경로가 실제 존재하는 파일을 가리키는가?
- [ ] **settings.json 유효성** — JSON 파싱이 되는가? 훅의 `{테스트/린트 명령}`이 실제 명령으로 치환됐는가?

**B. 내용 점검:**
- [ ] §1 입력을 다 받았는가? 못 받은 칸을 지어내지 않고 물었는가? (§1-1 분기 처리 포함)
- [ ] `docs/ARCHITECTURE.md`에 컴포넌트·데이터 흐름·폴더 구조·단방향 의존·공유 계약이 있는가?
- [ ] 헌장에 **충돌 우선순위(SSOT)**·**확정 결정**·**함정 노트(래칫) 자리**가 있는가?
- [ ] **한 사람 = 한 폴더**(또는 §1-1 대안)로 경계가 안 겹치는가? 공유 계약·머지 담당 규칙이 있는가?
- [ ] 각 `AI명령프롬프트.md`에 **§0 사용법 / §1 온보딩 / §3 복붙블록(`[작업][제약][검증][산출물]`) / §5 자가검증**이 다 있는가?
- [ ] 복붙 블록이 **한 번에 하나** 단위로 쪼개졌는가? 환각 차단 문장·쉬운 말 지시가 있는가?
- [ ] 팀 도구에 맞게 `CLAUDE.md`/`AGENTS.md`를 만들고(서로 링크로 대체하지 않음), 헌장으로 링크하며 중복하지 않는가?
- [ ] `settings.json`에 위험 명령 deny + 자동검증 훅이 있는가? git 규칙(main push 금지·브랜치·PR·머지 담당)이 명확한가?

- 아니오가 하나라도 있으면 고친 뒤 다시 점검하고, 결과를 정직하게 보고한다.
