# 연금계좌 합성 목데이터

> 실제 고객정보가 아닌 완전 합성 데이터. 서비스 화면·규칙 엔진·벤치마크 기능의 개발 및 시연에만 사용한다.

## 범위

생성 계좌는 아래 세 종류뿐이다.

| 코드 | 의미 | 위험자산 규칙 |
|---|---|---|
| `DC` | 확정기여형 퇴직연금 | 일반 위험자산 합계 70% 이하 |
| `IRP` | 개인형 퇴직연금 | 일반 위험자산 합계 70% 이하 |
| `PENSION_SAVINGS_FUND` | 연금저축펀드 | 동일한 70% 총량 한도 없음 |

DB형, 연금저축보험, 연금저축신탁은 생성하지 않는다. 연금저축펀드에는 원리금보장상품을 생성하지 않는다.

## 파일

- `users.csv`: 합성 사용자 10,000명과 고용형태·총급여 또는 종합소득금액·성향·수령선호·세액공제·수령세제 시나리오
- `accounts.csv`: 사용자가 보유한 DC·IRP·연금저축펀드 계좌와 납입액·가입기간·세액공제 대상액·예상 수령액
- `holdings.csv`: 계좌별 국내주식·글로벌주식·채권·원리금보장·현금성 구성
- `sources.json`: 공식 출처와 모델 가정의 구분
- `validation_summary.json`: 생성 건수, 평균, 표준편차 및 제약 검증 결과

`data_kind`는 전부 `MOCK`이다. `source_ids`는 해당 행을 보정한 통계와 가정의 식별자이며, 실제 개인의 출처를 뜻하지 않는다.

## 목시나리오 3종

| 코드 | 의미 |
|---|---|
| `DC_NEGLECT` | DC 계좌에서 원리금보장·현금성 자산 비중이 큰 방치형 |
| `TAX_BENEFIT_IDLE` | IRP 또는 연금저축펀드에 납입했지만 현금성 자산으로 남은 유형 |
| `OVERLAP_RISK` | 둘 이상의 계좌에서 주식형 자산이 중복되거나 위험 비중이 높은 유형 |

세 유형의 비중과 계좌 조합은 공개 교차통계가 없어 `ASSUMPTION_V1`로 관리한다.

## 앱 시연용 대표 고객 6명

합성 고객 10,000명은 통계·벤치마크용이며 Auth 사용자가 아니다. 앱에서 직접
로그인해 시연하는 대표 고객은 기존 행동형 3명과 생애주기형 3명으로 분리한다.

| 시나리오 코드 | 대표 고객 | 연령대 | 로그인 ID | 대표 상황 |
|---|---|---|---|---|
| `dc_dormant` | 박준호(가상) | 40대 | `j@kda-demo.invalid` | DC 적립금이 원리금보장 상품에 머문 방치형 |
| `tax_contribution_uninvested` | 이서연(가상) | 30대 | `s@kda-demo.invalid` | 세액공제를 위해 납입했지만 자금을 운용하지 않은 유형 |
| `overlap_risk_concentration` | 정민재(가상) | 30대 | `m@kda-demo.invalid` | 여러 연금계좌에 같은 위험자산이 중복된 유형 |
| `young_retirement_distance` | 김하린(가상) | 20~39세 | `r@kda-demo.invalid` | 노후가 멀게 느껴져 연금 운용의 우선순위가 낮은 유형 |
| `family_budget_pressure` | 최지훈(가상) | 40~54세 | `h@kda-demo.invalid` | 자녀·주거비로 납입이 빠듯하지만 노후를 걱정하기 시작한 유형 |
| `pension_payout_transition` | 윤정희(가상) | 55세 이상 | `y@kda-demo.invalid` | 연금 수령을 시작했거나 수령 직전인 유형 |

로그인 ID와 고객 매핑은 `demo_scenario_users.json`에 저장한다. 실제 비밀번호는
Git에 커밋하지 않고 아래 명령으로 `secrets/demo_scenario_auth.json`에 생성한다.

```powershell
uv run python scripts/provision_demo_auth_users.py --prepare-only
```

팀장 승인과 서버 전용 `SUPABASE_SECRET_KEY`·`DATABASE_URL` 설정 후 같은
스크립트를 옵션 없이 실행하면 Supabase Auth에 계정을 만들고 6개 로그인과 금융
컨텍스트 연결을 검증한다. 시나리오 코드는
사용자가 수정할 수 없는 Auth `app_metadata`에 연결하며 비밀번호는 출력하지 않는다.

로그인 후 FastAPI는 Auth UUID로 `demo_user_financial_context`를 조회한다. 계좌
잔액은 연결된 `mock_accounts`에서 합산하고, 총급여·종합소득금액과 당해연도
IRP·연금저축 납입액은 DB 컬럼에 값이 없으면 발표용 승인 기준에 따라 0원으로
정규화한다. 이 컨텍스트는 `GET /me/pension-context`와 인증된 `POST /chat`에서만
사용하며 브라우저가 보낸 `scenario_code`나 세액공제 입력값보다 서버 조회값을
우선한다. 사용자 계좌 컨텍스트는 RAG·임베딩 코퍼스에 넣지 않는다.

## 설문 기반 고객 특성

한국경영자총협회 「2025 직장인 퇴직연금 인식조사」(퇴직연금 가입 직장인 1,003명)의 응답 비율을 10,000명 합성 고객에 맞춰 배분했다.

| `users.csv` 필드 | 코드와 10,000명 배분 | 반영 기준 |
|---|---|---|
| `preferred_management_type` | `PRINCIPAL_GUARANTEED` 2,250명, `STABLE_INVESTMENT` 5,010명, `NEUTRAL_INVESTMENT` 2,120명, `ACTIVE_INVESTMENT` 620명 | 원리금보장형 22.5%, 안정투자형 50.1%, 중립투자형 21.2%, 적극투자형 6.2% |
| `risk_profile` | `STABLE`, `STABLE_SEEKING`, `RISK_NEUTRAL`, `ACTIVE` | 위 4유형을 서비스의 5단계 성향 중 가장 가까운 단계로 매핑. 조사에 별도 공격투자형이 없어 `AGGRESSIVE`는 임의 생성하지 않음 |
| `retirement_fund_attitude` | `STABILITY_FIRST`, `PARTIAL_INVESTMENT`, `ACTIVE` | 연령대별 적립금 인식. 예: 30대 적극투자 10.7%, 50대 안정관리 73.7% |
| `investment_readiness` | `NEEDS_GUIDANCE`, `INFORMED`, `DISENGAGED` | 관심은 있으나 방법을 모름 57.1%, 잘 알고 있음 33.6%, 무관심·미이해 9.3% |
| `payout_preference` | `MIXED`, `ANNUITY`, `LUMP_SUM` | 연령대별 수령계획. 전체 기준 혼합 37.7%, 연금 32.3%, 일시금 30.0% |
| `primary_outside_asset` | `DEPOSIT_SAVINGS`, `SECURITIES`, `INSURANCE_PENSION`, `GOLD_FX`, `REAL_ESTATE`, `CRYPTO`, `NONE` | 개인적으로 추가 운용하는 주된 재테크 수단 |

`50_plus`는 50~64세이지만 조사 교차표는 50대까지만 제공한다. 따라서 60~64세에도 50대 비율을 적용한 부분은 `ASSUMPTION_V2`다. 각 특성은 공개된 주변분포를 맞춘 것이며, 특성끼리의 결합분포는 공개되지 않아 합성 고객별 조합 자체는 실제 상관관계를 뜻하지 않는다.

서비스 `risk_profile`의 단계별 목표 위험비중은 실제 적합성평가 결과가 아니라 `ASSUMPTION_V1`의 합성 기준이다. 계좌 배분에는 연령·계좌 기준선과 이 목표를 함께 반영한 뒤, 방치형·현금대기형은 위험비중을 낮추고 위험중복형은 높인다. 따라서 같은 성향 안에서도 행동 시나리오에 따라 실제 합성 보유비중이 달라진다.

## 공식값과 가정값

공식값으로 직접 보정한 항목:

- 보험연구원 연구보고서 2025-20의 연령 구성, DC 연령별 평균 적립액, 원리금보장·실적배당 연령 패턴
- 고용노동부·금융감독원 2025 퇴직연금 투자 백서의 DC·IRP 과거 1년 수익률
- 통계청 2024 퇴직연금통계의 IRP 가입자·적립금으로 계산한 계좌당 평균 적립액
- 금융위원회·금융감독원 2025 연금저축 투자 백서의 연금저축펀드 계약수·적립금·과거 1년 수익률
- 한국경영자총협회 2025 직장인 퇴직연금 인식조사의 선호 운용유형, 연령별 운용태도·수령계획, 운용 이해도, 추가 재테크 수단

DC·IRP 위험자산 비중의 출발점은 공식 실적배당 비중(DC 33.0%, IRP 44.3%)과 연령 패턴을 참고한다. 다만 방치형·현금대기형·위험중복형 시나리오를 의도적으로 섞었으므로 최종 목데이터 평균은 공식 시장 평균과 같지 않다.

공개자료가 없어 가정한 항목:

- 계좌 조합, 연령별 IRP·연금저축펀드 적립액 곡선
- 개인별 적립액·수익률 표준편차
- 근로자·자영업자·프리랜서 비중, 직업유형별 총급여·종합소득금액 분포와 개인별 납입 편차·주기
- 계좌 가입기간, 예상 수령개시 연령·수령기간과 현재 잔액만으로 계산한 예상 수령액
- IRP 적립금의 이연퇴직소득·개인납입금·운용수익 재원 구성
- 계좌 안의 국내주식·글로벌주식·채권·현금 세부 비중
- 목시나리오 비중과 고객 특성 간 결합관계

투자성향의 주변분포는 경총 조사로 보정했다. 다만 경총의 4유형을 서비스의 5단계 코드로 연결한 매핑과 조사에서 제공하지 않은 특성 간 상관관계는 모델 가정이다.

IRP와 연금저축펀드의 연령별 평균 적립액은 각각 공식 전체 평균을 DC 연령 패턴으로 배분한 파생값이다. 연금저축펀드 계약당 평균은 `61.3조원 ÷ 586.3만 계약`을 기준으로 한다.

수익률은 2025년 공식 과거수익률 평균에 맞춘 합성값이다. 미래 기대수익률이나 수익 보장값으로 사용하면 안 된다. 개인별 표준편차는 공개되지 않아 모델 가정이며 `validation_summary.json`에서 생성 결과를 확인한다.

## 납입액 생성 기준

`monthly_contribution_krw`는 실제 매월 이체액이 아니라 **연간 납입액을 12개월로 나눈 월 환산값**이다.

| 계좌 | 생성 방식 | 생성 결과 전체평균 | 활동 납입자 평균 |
|---|---|---:|---:|
| DC | 근로자 합성 총급여 ÷ 144. 사용자의 연간 사용자부담금은 연간 임금총액의 12분의 1 이상이라는 제도 규칙을 월로 환산 | 505,682원 | 505,682원 |
| IRP | 소득구간별 활동 납입액에 로그정규 편차를 적용 | 205,976원 | 388,735원 |
| 연금저축펀드 | 전체 연금저축의 소득구간별 활동 납입액을 대용값으로 사용 | 134,884원 | 214,166원 |

시장 보정 기준은 2024년 월 환산 DC 사용자부담금 약 51.1만 원, IRP 전체 가입자 개인부담금 약 22.0만 원, 2025년 전체 연금저축 가입자 납입액 약 13.4만 원이다. IRP 활동 납입자 기준은 2021년 약 42.1만 원을 함께 사용했다. 연금저축펀드만의 납입총액은 공개되지 않아 전체 연금저축 통계를 대용한 부분을 `ASSUMPTION_CONTRIBUTION_V1`로 표시한다.

`contribution_status=INACTIVE`이면 월·연간 납입액은 0원이고 주기는 `NONE`이다. 활동 개인계좌의 주기는 월납·분기납·연말 일시납으로 합성하되, 어떤 주기든 금액 필드는 비교 가능한 월 환산액과 연간 합계로 저장한다. DC의 `MONTHLY_EQUIVALENT`는 실제 회사 납부 주기를 의미하지 않는다.

## 세액공제·수령세제 시나리오

2025년 귀속 규칙을 기준으로 근로자는 `gross_salary_krw`(총급여) 5,500만 원, 자영업자·프리랜서는 `comprehensive_income_krw`(종합소득금액) 4,500만 원을 기준으로 지방소득세 효과를 포함한 16.5% 또는 13.2%를 적용한다. 두 금액은 서로 다른 세법상 기준이므로 한 필드에 섞지 않는다.

| 고용형태 | 인원 | 소득 필드 | 세액공제율 경계 | 계좌 제약 |
|---|---:|---|---:|---|
| 근로자 | 7,900명 | `gross_salary_krw` | 총급여 5,500만 원 | DC·IRP·연금저축펀드 가능 |
| 자영업자 | 1,080명 | `comprehensive_income_krw` | 종합소득금액 4,500만 원 | IRP·연금저축펀드만 생성 |
| 프리랜서 | 1,020명 | `comprehensive_income_krw` | 종합소득금액 4,500만 원 | IRP·연금저축펀드만 생성 |

근로자의 종합소득금액과 비근로자의 총급여는 빈 값으로 저장한다. `tax_credit_income_basis`와 `tax_credit_income_amount_krw`는 어떤 소득 기준으로 세액공제율을 선택했는지 명시한다. 고용형태 비중과 합성 소득분포는 공개된 연금가입자 교차통계가 없어 `ASSUMPTION_TAX_SCENARIO_V1`이다.

공제대상 납입액은 연금저축 600만 원, IRP와 합산 900만 원까지만 인정하며 회사가 납입한 DC 사용자부담금은 제외한다.

`estimated_pension_tax_credit_krw`는 공제대상 납입액에 소득구간별 비율을 적용한 **예상 세액공제액**이다. 실제 환급액은 결정세액과 개인별 과세상황에 따라 달라지므로 환급 보장값으로 사용하지 않는다.

예상 수령 시나리오는 현재 계좌잔액을 사용자가 선호한 수령방식의 합성 기간으로 나눈 단순값이다. 연금 방식은 55세 이후·가입 5년 경과 요건을 참고하고, 개인납입·운용수익 재원은 연 1,500만 원 이하면 연령별 저율 분리과세, 초과하면 종합과세 또는 16.5% 분리과세 선택 가능 대상으로 분류한다. 일시금 선호는 `NON_PENSION_WITHDRAWAL_REVIEW`, DC의 이연퇴직소득은 `DEFERRED_RETIREMENT_INCOME_RULE`로 별도 표시한다.

`planned_contribution_years_at_receipt`는 현재 가입기간에 수령개시까지 남은 기간을 더한 값이다. 연금 선호 고객은 이 값으로 5년 요건을 확인해 `pension_receipt_eligibility`를 부여하며, 일시금 선호 고객은 `NOT_APPLICABLE_LUMP_SUM`으로 구분한다.

IRP는 적립금 안의 이연퇴직소득·세액공제 납입금·운용수익 비율이 공개 목데이터에 없으므로 수령세액을 확정 계산하지 않는다. `planned_receipt_tax_treatment`는 적용 가능 규칙을 보여주는 교육용 분류이며 `ASSUMPTION_TAX_SCENARIO_V1`로 관리한다.
