# 연금계좌 운용 가이드 — 프로젝트 기획서

> 키움 디지털 아카데미 1차 프로젝트 · 투자·자산관리 주제
> 문서 버전: v2.2 · 갱신일: 2026-07-14
> 대상 계좌: **DC형 퇴직연금 · 개인형퇴직연금(IRP) · 연금저축계좌**
> 현재 단계: 기획 확정 / MVP 구현 전

## 1. 제품 정의

### 1.1 한 줄 정의

**DC형·IRP·연금저축계좌의 역할과 제약, 전체 자산구성을 쉽게 설명해 이용자가 스스로 운용 결정을 내리도록 돕는 AI 연금계좌 운용 가이드**

### 1.2 해결할 문제

이용자는 연금계좌를 보유해도 계좌별 역할과 운용 규칙을 몰라 자산을 제대로 배치하고 점검하지 못한다.

- 적립금 운용에 **관심은 있지만 방법을 모르는** 응답이 57.1%로 무관심(9.3%)보다 훨씬 높다. (경총 2025 인식조사)
- 원리금보장을 넘어 운용하려는 의향은 77.5%지만, 2023년 말 퇴직연금 적립금의 87.2%는 원리금보장형에 머물렀다.
- 이용자가 꼽은 제도개선 1순위는 정보 비대칭 해소(24.6%)다.
- DC형·IRP·연금저축은 납입 주체, 세제, 인출 조건, 상품 범위와 위험자산 규칙이 달라 한 기준으로 관리할 수 없다.
- 여러 계좌를 따로 보면 전체 주식·채권·현금성 비중과 중복 노출을 파악하기 어렵다.

따라서 이 프로젝트는 정보를 더 나열하는 대신 다음 질문에 답한다.

1. 각 계좌는 어떤 역할을 하는가?
2. 지금 계좌 상태에서 무엇을 확인해야 하는가?
3. 세 계좌를 합치면 전체 자산구성은 어떻게 보이는가?
4. 적용된 규칙과 계산 근거는 무엇인가?
5. 실제 계좌에서 이용자가 다음에 할 일은 무엇인가?

### 1.3 핵심 타깃과 페르소나

1차 타깃은 **DC형·IRP·연금저축계좌 중 하나 이상을 보유했지만 계좌별 차이와 운용 방법을 모르는 직장인**이다. 무관심층보다 “관심은 있으나 방법을 모르는 정보부족형”에 집중한다.

대표 페르소나 `김직장(35세)`:

- 회사 DC형, 퇴직급여·세액공제 목적 IRP, ETF를 보유한 연금저축계좌가 있다.
- 세 계좌의 현금성·주식형 자산 비중을 합산해 본 적이 없다.
- DC형·IRP의 위험자산 제약과 연금저축 규칙을 혼동한다.
- 자동 일임보다 근거를 이해한 뒤 직접 점검하고 결정하기를 원한다.

### 1.4 서비스 범위와 포지셔닝

| 계좌 | 기본 역할 | 서비스가 설명할 핵심 |
|---|---|---|
| DC형 퇴직연금 | 회사 부담금을 근로자가 운용 | 회사 부담금, 디폴트옵션, 위험자산 한도, 정기 점검 |
| IRP | 퇴직급여와 개인 추가 납입금 관리 | 퇴직급여·추가 납입 구분, 위험자산 한도, 인출·이전 제약 |
| 연금저축계좌 | 개인의 장기 노후 준비 | 세제 구조, 상품 유형, 장기 적립, 중도인출 유의점 |

> 세 계좌를 대신 운용하는 서비스가 아니라, 계좌별 규칙과 전체 구성을 근거와 함께 해석해 이용자의 자기결정을 돕는 교육·의사결정 지원 서비스다.

### 1.5 하지 않는 것

- 특정 금융상품의 개인화된 매수·매도 지시
- 실제 금융회사 계좌 연결과 주문·자동 리밸런싱
- 실명 인증, 실제 계좌 비밀번호 수집, 실제 금융계좌 로그인 연동
- 계좌 이전 자동 실행
- 미래 수익률 보장과 시장 방향 예측
- 개인별 확정 절세액·세금 최적화
- 국민연금 예상액과 DB형 퇴직연금 운용 진단
- 은퇴 후 인출 순서 최적화

상세 규제 경계는 [금융권 규제 및 컴플라이언스 고려사항](./금융권%20규제%20및%20컴플라이언스%20고려사항.md)을 따른다.

## 2. MVP 결정

### 2.1 골든패스

```text
로그인·회원가입 화면 진입(데모 세션)
  → 보유 연금 선택(IRP·DC형·연금저축펀드)
  → 홈에서 내 연금자산 요약 확인
  → 계좌 역할·규칙 비교
  → 목데이터 계좌별 진단
  → 세 계좌 통합 자산구성 확인
  → 적용 규칙·수치·출처 설명
  → 교육용 what-if 비교
  → 실제 계좌에서 확인할 체크리스트

홈에서 분기: 설명형 챗봇 Q&A / 연금 정보 커뮤니티
```

MVP의 핵심은 기능 수가 아니라 다음 조합이 한 흐름에서 작동하는지 증명하는 것이다.

> **계좌별 규칙 분리 × 개별·통합 상태 해석 × 출처가 보이는 what-if × 이용자 자기결정**

### 2.2 핵심 기능과 부가기능

핵심 기능은 이용자가 **계좌별 규칙과 자신의 연금자산 상태를 이해하고, 다음 점검 행동을 스스로 결정**하게 하는 P0 범위다. 부가기능은 이해·학습·탐색을 돕되, 핵심 진단 흐름을 대체하지 않는 P1 범위다.

#### 핵심 기능 (P0 — 반드시 완성)

1. **접속·계좌 선택·홈 요약**: 데모 세션으로 진입해 IRP·DC형·연금저축펀드를 선택하고, 홈에서 내 연금자산과 포트폴리오를 요약해 보여준다.
2. **계좌 역할·규칙 비교**: 같은 자산도 DC·IRP·연금저축에서 규칙이 다름을 보여준다.
3. **계좌별 진단**: 현금성·원리금보장형, 자산군 비중, 편중, 위험자산 한도 상태를 계산한다.
4. **통합 해석**: 세 계좌 합산 자산군 비중과 유사 자산 중복을 보여준다.
5. **근거 설명**: 엔진 결과, 적용 규칙, 출처, 기준일, 목데이터 여부를 한 카드에 표시한다.
6. **다음 행동 체크리스트**: 자동 주문 대신 실제 계좌에서 이용자가 확인할 항목을 제시한다.

#### 부가기능 (P1 — 핵심 기능 완성 후 축소 구현)

- 동일 연령대 비교: 목데이터 또는 공개 통계 기준으로 현재 상태를 상대적으로 이해하도록 돕는다. 실제 이용자 개인정보와 직접 비교하지 않는다.
- 투자성향·남은 기간 분석 및 투자 스타일 퀴즈: 상품 추천이 아니라 교육 예시 노출 범위 제한에 사용한다.
- 교육용 자산배분 예시: 진단·성향·기간을 바탕으로 자산군 비중과 역할을 설명한다. 특정 상품을 지시하지 않는다.
- 적립 시뮬레이션: 현재 적립금·월 납입액·기간·가정수익률을 조절하는 단일 what-if
- 하락장 테스트: 자산군 충격 시나리오 1개
- 설명 Q&A: 엔진 결과와 검증 콘텐츠 안에서만 답변
- 연금 정보 커뮤니티: 운영·검증된 연금 교육 콘텐츠를 읽기 전용으로 제공한다.

#### P2 — 이후 검토

- 실제 상품 데이터·수수료·위험등급 고도화
- 실계좌·마이데이터 연동
- 상품별 스코어링과 개인화 제안
- 주문·자동 리밸런싱
- 개인별 세금·인출 최적화

### 2.3 기능 명세

| 구분 | 기능 | 입력 | 핵심 출력 | 완료 기준 |
|---|---|---|---|---|
| 핵심 | 로그인·회원가입 | 데모 진입 선택 | 개인식별정보 없이 시작한 데모 세션 | 실명 인증·실계좌 연동·민감정보 수집 없음 |
| 핵심 | 계좌 선택 | IRP·DC형·연금저축펀드 선택 | 적용할 계좌·목시나리오 | 실제 데이터가 아님을 명확히 표시 |
| 핵심 | 홈 요약 | 선택 계좌·목데이터 | 내 연금자산, 포트폴리오 비중 | 각 수치의 목데이터·기준일·출처를 구분 표시 |
| 핵심 | 역할·규칙 비교 | 계좌 유형 | 목적·납입·제약·인출 비교 | 일반 규칙과 예외를 구분 |
| 핵심 | 계좌별 진단 | 상품·잔액 목데이터 | 자산군 비중·편중·한도 상태 | 계좌별 규칙을 정확히 적용 |
| 핵심 | 통합 보기 | 계좌별 진단 결과 | 합산 평가금액·전체 자산군·중복 | 개별 합계와 통합 합계 일치 |
| 부가 | 동일 연령대 비교 | 선택 계좌·목데이터 또는 공개 통계 | 비교 기준이 표시된 상대적 현황 | 개인정보 직접 비교 없이 비교 집단·기준일·출처 표시 |
| 부가 | 성향·기간 및 투자 스타일 퀴즈 | 설문 응답 | 분류 결과와 이유 | 규칙 기반이며 성향 밖 예시 차단 |
| 부가 | 교육용 예시 | 진단·성향·기간 | 자산군 단위 예시 | 상품 지시 없이 계좌 제약 준수 |
| 부가 | 적립 what-if | 적립금·납입액·기간·가정수익률 | 원금과 가정수익을 구분한 비교 | 모든 가정과 기준일 표시 |
| 부가 | 스트레스 테스트 | 자산군별 충격 가정 | 계좌별·전체 변동 비교 | 미래 예측이 아님을 표시 |
| 부가 | 설명 Q&A | 엔진 결과·검증 콘텐츠 | 수치·규칙·출처가 연결된 답변 | 엔진과 답변 수치 일치 |
| 핵심 | 체크리스트 | 계좌 유형·진단 결과 | 이용자가 직접 확인할 다음 단계 | 주문 버튼 없이 공식 채널 안내 |
| 부가 | 연금 정보 커뮤니티 | 검증된 연금 교육 콘텐츠 | 주제별 정보 목록·상세 콘텐츠 | 개인화 매수·매도 의견, 광고성 후기, 주문 유도 없음 |

### 2.4 계좌 비교 최소 항목

| 항목 | 연금저축펀드 | 개인형 IRP | DC형 퇴직연금 |
|---|---|---|---|
| 핵심 역할 | 자유도 높은 개인 장기투자 | 퇴직급여 통합·보호 | 회사 납입·근로자 운용 |
| 납입 주체 | 가입자 | 퇴직급여 + 가입자 | 회사 + 근로자 추가납입 가능 |
| 일반 위험자산 한도 | 없음 | 70% | 70% |
| 디폴트옵션 | 없음 | 있음 | 있음 |
| 중도 부분인출 | 비교적 자유로움 | 법정 사유만 | 법정 사유만 |
| 수급권 보호 | 퇴직급여법상 보호 없음 | 있음 | 있음 |
| 예금자보호 | 펀드는 비보호 | 보호대상 상품만 | 보호대상 상품만 |
| 금융회사 이전 | 계좌이체 가능 | 조건부 이전 | 회사 계약 범위·조건 확인 |

모든 행에는 기준일과 공식 출처를 붙이고 `일반 규칙/예외`, `법적 보장/사업자별 혜택`을 구분한다.

## 3. 계좌별 설계 원칙

### 3.1 공통 원칙

- 상품명보다 자산군·위험·비용·역할을 먼저 설명한다.
- 수익 가능성과 손실 가능성을 함께 표시한다.
- 입력값·가정·기준일·출처를 결과와 연결한다.
- 실제 공시 데이터와 사용자 목데이터를 섞지 않는다.
- 제도·세제·상품 규칙은 코드에 고정하지 않고 버전 데이터로 관리한다.

### 3.2 계좌별 핵심 규칙

| 계좌 | 반드시 분리할 규칙 |
|---|---|
| DC형 | 회사 부담금과 추가 부담금, 디폴트옵션, 위험자산 한도·예외, 사업자별 상품 범위, 퇴직 시 IRP 이전 |
| IRP | 퇴직급여와 개인 납입금, 위험자산 한도·예외, 디폴트옵션, 중도인출·수령·이전, 기준연도별 세제 |
| 연금저축 | 보험·펀드 유형, ETF·펀드 적격성, DC·IRP와 다른 위험자산 규칙, 부분인출·연금 외 수령의 세제상 불이익 |

연금저축펀드에는 DC형·IRP와 같은 일반 위험자산 70% 한도를 적용하지 않는다. 예금자보호는 계좌 전체가 아니라 편입된 보호대상 상품 단위로 설명한다.

## 4. 사용자 경험

### 4.1 화면 구성

| 단계 | 화면 목적 | 핵심 요소 |
|---|---|---|
| 로그인·회원가입 | 서비스 시작점 제공 | 회원가입·로그인 버튼, 데모 서비스·개인정보 미수집 고지 |
| 계좌 선택 | 보유 연금 선택 | IRP·DC형·연금저축펀드 선택 버튼, 선택 완료 버튼 |
| 홈 화면 | 내 연금 현황을 한눈에 요약 | 내 연금자산, 포트폴리오 원형 차트, 동일 연령대 자산 비교, 투자 스타일 퀴즈 진입 |
| 계좌별 진단 | 개별 상태 해석 | 자산군 비중, 현금성 자산, 한도, 편중 |
| 통합 대시보드 | 전체 구성 이해 | 합산 평가금액, 전체 자산군, 중복 |
| 교육용 비교 | 대안의 효과·위험 이해 | 성향 가드레일, what-if, 스트레스 시나리오 |
| 챗봇 | 결과 이유와 연금 기초 질문 확인 | 대화 시작 문구, 적용 수치·규칙·공식 출처가 연결된 설명형 Q&A |
| 연금 커뮤니티 | 검증된 연금 정보 탐색 | 주제별 연금 정보 목록, 콘텐츠 상세, 연금 포트폴리오 확인하기 진입 |
| 체크리스트 | 실제 행동 연결 | 계좌별 확인 항목, 상품설명서·공식 채널 |

### 4.2 UX 원칙

- 한 화면에서 한 가지 판단만 요구한다.
- 현재 상태 → 문제 → 근거 → 교육용 대안 → 위험 → 다음 행동 순서를 유지한다.
- 혜택과 위험을 같은 수준으로 표시한다.
- 목데이터와 실제 공시 데이터 라벨을 고정 노출한다.
- 확인 버튼과 실제 거래로 오해될 버튼을 구분하며 MVP에는 주문 버튼을 두지 않는다.
- 홈 화면의 요약 카드와 원형 차트는 상세 진단 화면으로 이어지며, 차트만으로 투자 판단을 유도하지 않는다.
- 로그인·회원가입은 MVP에서 데모 진입 화면이다. 실명 인증과 실제 금융계좌 연결은 제공하지 않는다.
- 커뮤니티는 운영·검증된 교육 콘텐츠 열람을 우선한다. 이용자 후기·댓글·개인화 조언을 제공할 경우에는 별도 운영·광고성 표시·준법 기준을 확정한 뒤 진행한다.

## 5. 규칙 엔진·데이터·AI 설계

### 5.1 시스템 구조

```text
[모바일 웹앱(PWA)]
        │ REST
[FastAPI + LLM 설명 계층]
        │ 엔진 도구 호출
[계좌 규칙·진단·시뮬레이션 엔진]
        │
[도메인 모델 + 버전형 규칙 테이블 + 공개 데이터 + 목계좌]
```

### 5.2 엔진 책임

- 계좌 분류와 계좌별 상품·한도·예외 검사
- 상품의 자산군 분류
- 계좌별 현금성 비중·편중·중복·위험자산 상태 계산
- 세 계좌 합산 평가금액·자산군 비중 계산
- 성향 설문 점수화
- 적립 what-if와 스트레스 시나리오 계산
- LLM에 전달할 수치·규칙·출처 구조화

규칙 데이터의 필수 필드는 `계좌 유형`, `규칙 ID`, `적용 조건`, `제한·한도`, `예외`, `공식 출처`, `시행일`, `검증일`, `검토자`, `로직 버전`이다.

### 5.3 데이터 경계

| 데이터 | 구분 | 용도 |
|---|---|---|
| 고용노동부·금융감독원 퇴직연금 정보 | 실제 공개 데이터 | DC·IRP 제도·공시 근거 |
| 금융위원회·통합연금포털 연금저축 정보 | 실제 공개 데이터 | 연금저축 제도·상품 근거 |
| KRX·금융회사 공개 상품정보 | 실제 공개 데이터 | ETF·펀드·수수료 보조 정보 |
| 계좌 시나리오 3종 | 목데이터 | 실제 계좌 연동 대체 |
| 성향·시뮬레이션 입력 | 데모 입력 | 규칙 분류와 what-if 계산 |

목데이터 시나리오:

1. **DC 방치형**: 현금성·원리금보장형 비중이 높음
2. **세액공제 후 미운용형**: IRP·연금저축에 납입만 하고 운용하지 않음
3. **중복·위험 편중형**: 세 계좌에 유사 주식형 자산을 보유하고 DC·IRP 한도에 근접

### 5.4 LLM 책임과 가드레일

LLM은 엔진 결과와 검증된 콘텐츠를 설명한다. 계산·한도 판정·상품 적격성 검사는 하지 않는다.

- 엔진에 없는 숫자·시장 전망·확정 절세액 생성 금지
- 계좌 유형을 확인하지 않은 상품 설명과 규칙 혼합 금지
- 성향 밖 교육용 예시 차단
- 개인화 특정 상품 매수·매도 지시 금지
- 모든 수치에 가정·기준일·출처 연결
- 엔진 결과와 답변 수치가 다르면 폐기 후 재생성
- 개인정보·계좌번호 입력 마스킹

## 6. 이용자 보호와 규제 경계

MVP는 특정 상품 추천과 주문을 제외한다. 핵심 원칙은 다음과 같다.

- 과거 수익률을 미래 수익처럼 표현하지 않는다.
- 장기 예상값과 스트레스 결과는 사용자가 선택한 가정임을 표시한다.
- 퇴직연금 수급권 보호와 예금자보호를 구분한다.
- 실제 개인정보와 금융계좌 정보를 수집하지 않는다.
- 상품설명서와 금융회사 공식 안내로 이동할 수 있는 링크를 제공한다.
- 규칙 준수와 고객 적합성 판단을 같은 의미로 사용하지 않는다.
- 챗봇과 커뮤니티에서 특정 상품의 매수·매도·보유를 유도하거나, 이용자 간 개인화 투자 조언을 중개하지 않는다.

개인화 상품 제안·실계좌·주문으로 확장할 경우 적합성·설명의무, 투자자문·RA, 개인정보·마이데이터, 전자금융 절차를 먼저 검토한다. 출시 게이트와 금지 표현은 [금융권 규제 및 컴플라이언스 고려사항](./금융권%20규제%20및%20컴플라이언스%20고려사항.md)을 단일 기준으로 사용한다.

## 7. 검증 기준

### 7.1 기능·데이터

- [ ] 선택한 계좌 조합으로 골든패스를 끝까지 완료한다.
- [ ] DC형·IRP와 연금저축에 서로 다른 규칙이 적용된다.
- [ ] 계좌별 평가금액 합계와 통합 평가금액이 일치한다.
- [ ] 계좌별 자산군 합계와 전체 자산군 합계가 일치한다.
- [ ] 모든 시뮬레이션에 입력값·가정·기준일·위험이 표시된다.
- [ ] Q&A 수치와 규칙 설명이 엔진 결과와 일치한다.
- [ ] 목데이터와 실제 공개 데이터가 화면에서 구분된다.
- [ ] 개인화 특정 상품 지시, 출처 없는 수치, 계좌 규칙 위반이 0건이다.
- [ ] 로그인·회원가입 화면에서 실명 인증·실계좌 연동이 없고, 데모 세션임을 알 수 있다.
- [ ] 홈 화면의 자산·포트폴리오·또래 비교 수치에 목데이터 여부와 기준일이 표시된다.
- [ ] 챗봇 답변과 커뮤니티 콘텐츠에 개인화 상품 지시와 주문 유도가 없다.

### 7.2 사용자

5~8명의 과업 테스트에서 이용자가 다음을 설명하거나 수행할 수 있어야 한다.

- 세 계좌의 역할과 위험자산 규칙 차이
- 계좌별 비중과 전체 비중을 함께 보는 이유
- 유사 자산 중복이 전체 위험에 미치는 영향
- 시뮬레이션이 확정 수익이 아닌 이유
- 실제 계좌에서 다음에 확인할 행동 한 가지

### 7.3 발표

- 세 계좌를 다루는 이유를 한 문장으로 설명한다.
- 계좌별 규칙이 다르게 적용되는 장면을 보여준다.
- 계좌별 진단과 통합 해석을 하나의 시나리오로 연결한다.
- 계산은 엔진, 설명은 LLM이라는 구조를 시연한다.
- 추천·주문이 아닌 자기결정 지원이라는 범위를 명확히 한다.

## 9. 로드맵과 미확정 사항

### 9.1 단계별 확장

1. **Phase 1 — MVP**: 로그인·계좌선택·홈을 포함한 P0 골든패스와 축소된 what-if·Q&A, 읽기 전용 연금 정보 커뮤니티
2. **Phase 2 — 데이터 고도화**: 상품·수수료·위험등급·설명서, 점검 알림, 사업자별 상품 차이
3. **Phase 3 — 실서비스 검토**: 자사·마이데이터 계좌 연동, 개인화 제안, 계좌 이전·인출 교육

Phase 3는 법무·준법·개인정보·정보보호 검토와 내부 승인 이후에만 진행한다.

### 9.2 미확정 사항

- 서비스명과 최종 프론트엔드 방식
- 데이터베이스 사용 여부
- 성향 분류 기준표
- 교육용 자산배분 예시 비중
- 적립·스트레스 시뮬레이션 가정
- DC형·IRP 위험자산 규칙의 세부 판정과 예외
- 연금저축 상품 적격성 규칙
- 기준연도별 세액공제 데이터 구조
- 실제 공개 API 사용 범위
- 사용자 테스트 모집·평가 방식

미확정 값은 임의로 결정하지 않고 `TODO: 확인 필요`로 관리한다.
