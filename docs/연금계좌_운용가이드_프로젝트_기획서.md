# 연금계좌 운용 가이드 — 프로젝트 기획서

> 키움 디지털 아카데미 1차 프로젝트 · 투자·자산관리 주제
>
> 문서 버전: v2.0 · 작성일: 2026-07-13
>
> 대상 계좌: **DC형 퇴직연금 · 개인형퇴직연금(IRP) · 연금저축계좌**
> 프로젝트 단계: 기획 재정의 / MVP 구현 전

## 1. 프로젝트 개요

### 1.1 한 줄 정의

**DC형 퇴직연금·IRP·연금저축계좌를 보유했지만 계좌별 차이와 운용 방법을 모르는 이용자에게, 각 계좌의 역할과 제약을 구분해 설명하고 스스로 운용 결정을 내리도록 돕는 AI 연금계좌 운용 가이드**

### 1.2 다루는 범위

이 프로젝트에서 다루는 것은 단일 금융상품이 아니라 성격이 다른 세 종류의 **연금계좌**다.

| 계좌 | 기본 성격 | 누가 운용하는가 | 서비스가 설명할 핵심 |
|---|---|---|---|
| DC형 퇴직연금 | 회사가 부담금을 적립하고 근로자가 운용하는 퇴직연금 | 근로자 | 회사 부담금, 위험자산 한도, 디폴트옵션, 정기 점검 |
| IRP | 퇴직급여와 개인 추가 납입금을 관리하는 개인형 퇴직연금 | 가입자 | 퇴직급여 관리, 추가 납입, 위험자산 한도, 인출 제약 |
| 연금저축계좌 | 개인이 노후 준비를 위해 가입하는 개인연금 계좌 | 가입자 | 세제혜택 구조, 상품 선택 범위, 장기 적립, 중도인출 유의점 |

세 계좌는 모두 노후자산을 위한 계좌지만 납입 주체, 세제, 인출 조건, 운용 가능 상품과 한도 규칙이 다르다. 서비스는 이 차이를 없애지 않고 **공통 원칙과 계좌별 규칙을 분리해 설명**한다.

### 1.3 기획 배경

이용자는 회사에서 DC형을 선택하고, 퇴직급여 또는 세액공제를 위해 IRP를 만들고, 별도로 연금저축계좌까지 보유할 수 있다. 그러나 계좌가 늘어날수록 다음 문제가 발생한다.

- 각 계좌의 목적과 차이를 구분하기 어렵다.
- 어느 계좌에 어떤 자산을 둘 수 있는지 모른다.
- 위험자산 한도와 상품 제한을 계좌마다 다르게 적용하기 어렵다.
- 동일하거나 비슷한 상품을 여러 계좌에 중복 보유할 수 있다.
- 계좌별 화면은 볼 수 있어도 전체 연금자산의 구성을 이해하기 어렵다.
- 세제혜택만 보고 가입한 뒤 실제 운용은 현금성·저위험 자산에 방치할 수 있다.
- 시장 하락 시 계좌별로 무엇을 점검해야 하는지 판단하기 어렵다.

### 1.4 프로젝트 목표

1. DC형·IRP·연금저축계좌의 역할과 차이를 쉽게 설명한다.
2. 이용자가 보유한 계좌별 운용 상태를 구분해 진단한다.
3. 세 계좌 전체의 자산군 비중과 중복을 한눈에 보여준다.
4. 계좌별 허용 상품과 규칙을 위반하지 않는 교육용 예시를 제공한다.
5. 납입액·기간·가정수익률을 조절해 장기 결과를 비교하게 한다.
6. AI가 계산과 규정 판단을 임의로 수행하지 않도록 규칙 엔진과 설명 계층을 분리한다.
7. 실제 주문 대신 이용자가 각 계좌에서 확인할 다음 행동을 안내한다.

## 2. 문제 정의

### 2.1 핵심 문제

**이용자는 연금계좌를 보유하고 있어도 계좌별 역할과 운용 규칙을 몰라 자산을 제대로 배치하고 점검하지 못한다.**

이 문제는 감상이 아니라 통계로 확인된다.

- 적립금 운용에 **관심은 있으나 방법을 모르는** 응답이 57.1%로, 무관심(9.3%)의 여섯 배가 넘는다. (경총 2025 인식조사)
- 원리금보장을 넘어 운용하려는 의향은 77.5%인데 실제 적립금은 87.2%가 원리금보장형에 머문다 — 의향과 실행의 큰 격차. (원리금보장 비중은 전체 퇴직연금 '23년 말 기준)
- 이용자가 꼽은 제도개선 1순위도 "정보 비대칭 해소"(24.6%)다.
- 방치 보완용으로 도입된 디폴트옵션조차 85.4%가 안정형에 쏠려, 필요한 것이 자동화가 아니라 설명임을 보여준다.

### 2.2 문제의 원인

- DC형·IRP·연금저축계좌의 명칭과 목적이 비슷해 보인다.
- 가입 과정은 안내받지만 가입 이후의 운용 교육은 부족하다.
- 금융회사 앱은 계좌와 상품 목록 중심으로 구성되어 있다.
- 세제·인출·위험자산 규칙이 달라 하나의 기준을 일괄 적용할 수 없다.
- 일반 주식투자 경험이 있어도 연금계좌의 장기 목적과 제약은 따로 배워야 한다.
- 자동운용 서비스는 편리하지만 이용자에게 판단 기준이 남지 않을 수 있다.
- 장기 결과는 납입액·기간·수익률·수수료 가정에 민감하지만 비교가 어렵다.

### 2.3 해결 가설

다음 순서로 경험을 제공하면 이용자가 세 계좌를 구분하고 스스로 점검할 가능성이 높아진다.

`보유 계좌 확인 → 계좌별 역할 이해 → 계좌별 상태 진단 → 전체 자산구성 비교 → 교육용 운용 예시 → 시뮬레이션 → 다음 행동 체크리스트`

## 3. 핵심 타깃

### 3.1 1차 타깃

**DC형 퇴직연금·IRP·연금저축계좌 중 하나 이상을 보유했지만, 계좌별 차이와 운용 방법을 모르는 직장인**

주요 특성:

- 회사 퇴직연금에서 DC형을 선택했거나 운용 중이다.
- 퇴직급여 수령 또는 세액공제를 위해 IRP를 개설했다.
- 장기 노후 준비를 위해 연금저축계좌를 개설했다.
- 계좌 개설 목적은 알지만 실제 상품과 비중을 정하지 못했다.
- 일반 주식이나 ETF 투자 경험은 있지만 연금계좌 규칙은 잘 모른다.
- 여러 계좌를 따로 관리해 전체 자산배분을 파악하지 못한다.
- 원리금보장을 넘어 운용할 의향은 있으나 방법을 몰라 실행하지 못한다(무관심층이 아니다).
- 자동 일임보다 설명을 이해한 뒤 직접 결정하기를 원한다.

### 3.2 대표 페르소나

**김직장, 35세, 회사원**

- 회사의 DC형 퇴직연금 가입자다.
- 이직 후 받은 퇴직급여와 세액공제 목적의 납입금이 IRP에 있다.
- 증권사 연금저축계좌에서 ETF를 일부 보유하고 있다.
- 세 계좌의 현금성 자산과 주식형 자산 비중을 합산해 본 적이 없다.
- DC형과 IRP에는 위험자산 관련 제약이 있다는 사실만 어렴풋이 안다.
- 연금저축계좌에도 같은 규칙이 적용되는지 혼동한다.
- 계좌별 역할과 전체 구성을 쉽게 설명해 주면 직접 점검할 의향이 있다.

### 3.3 사용자 요구

1. 세 계좌의 차이를 한 번에 이해하고 싶다.
2. 내 계좌가 각각 어떤 역할을 해야 하는지 알고 싶다.
3. 계좌마다 운용 가능한 상품과 제한을 알고 싶다.
4. 전체 연금자산이 특정 자산군에 편중되었는지 확인하고 싶다.
5. 내 성향과 은퇴까지 남은 기간에 따른 교육용 예시를 보고 싶다.
6. 납입액과 가정수익률에 따라 장기 결과가 어떻게 달라지는지 비교하고 싶다.
7. 실제 계좌별로 무엇을 확인해야 하는지 체크리스트를 받고 싶다.

## 4. 서비스 가치와 포지셔닝

### 4.1 핵심 가치

| 가치 | 제공 내용 | 기존 경험과의 차이 |
|---|---|---|
| 계좌 구분 | DC형·IRP·연금저축의 목적과 제약을 비교 | 비슷해 보이는 계좌를 역할 중심으로 정리 |
| 계좌별 진단 | 각 계좌의 현금성 자산·상품군·위험자산 비중 해석 | 상품 목록을 운용 상태로 변환 |
| 통합 관점 | 세 계좌의 자산군 비중과 중복을 합산해 표시 | 금융회사·계좌별로 흩어진 정보를 연결 |
| 설명 가능한 시뮬레이션 | 가정·근거·위험이 표시된 교육용 예시 제공 | 결과만 보여주는 블랙박스 경험 완화 |
| 자기결정 지원 | 실제 계좌에서 확인할 항목을 계좌별 체크리스트로 제공 | 자동 일임이나 즉시 매수 유도와 구분 |

### 4.2 포지셔닝 문장

> 세 계좌를 대신 운용하는 서비스가 아니라, 이용자가 DC형·IRP·연금저축계좌의 차이와 전체 구성을 이해하고 스스로 운용 결정을 내리도록 돕는 교육·의사결정 지원 서비스

### 4.3 하지 않는 것

- 특정 금융상품의 매수·매도를 직접 지시하지 않는다.
- 실제 계좌 주문과 자동 리밸런싱을 실행하지 않는다.
- 이용자 동의 없이 자동으로 운용하지 않는다.
- 미래 수익률을 보장하거나 시장 방향을 예측하지 않는다.
- 국민연금 예상액과 DB형 퇴직연금을 MVP 운용 대상으로 포함하지 않는다.
- 세금 신고나 개인별 절세 결과를 확정적으로 안내하지 않는다.

## 5. 계좌별 설계 원칙

### 5.1 공통 원칙

- 세 계좌 모두 장기 노후자산이라는 목적을 우선한다.
- 이용자의 투자성향과 남은 운용 기간을 함께 고려한다.
- 상품명보다 자산군·위험·비용·역할을 먼저 설명한다.
- 수익 가능성과 손실 가능성을 함께 표시한다.
- 모든 계산 결과에 입력값, 가정, 기준일과 출처를 표시한다.

### 5.2 DC형 퇴직연금

- 회사가 정해진 부담금을 적립하고 근로자가 직접 운용하는 구조를 설명한다.
- 운용지시가 없을 때 적용될 수 있는 디폴트옵션을 설명한다.
- 퇴직연금 위험자산 한도와 예외 상품을 규칙 엔진에서 검사한다.
- 회사가 계약한 퇴직연금사업자와 제공 상품 범위가 다를 수 있음을 표시한다.
- 실제 회사 제도나 사업자 상품 목록을 MVP에서 추정하지 않는다.

### 5.3 IRP

- 퇴직급여를 모아 관리하는 기능과 개인 추가 납입 기능을 구분한다.
- DC형과 마찬가지로 퇴직연금 운용 규칙과 위험자산 한도를 적용한다.
- 중도인출과 연금수령 조건은 공식 최신 기준을 확인하도록 안내한다.
- 세액공제 한도·세율은 기준연도별 설정값으로 관리하고 코드에 고정하지 않는다.
- 실제 이용자의 소득·공제 가능액을 추정해 확정적인 절세액을 제시하지 않는다.

### 5.4 연금저축계좌

- 개인이 노후 준비를 위해 납입하고 운용하는 개인연금 계좌임을 설명한다.
- 연금저축보험과 연금저축펀드 등 상품 유형 차이를 구분한다.
- 증권사 연금저축펀드 계좌의 ETF·펀드 운용 범위와 제한 상품을 설명한다.
- DC형·IRP의 위험자산 한도 규칙을 그대로 적용하지 않고 별도의 상품 적격성 규칙을 사용한다.
- 중도인출과 연금 외 수령에 따른 세제상 불이익 가능성을 안내한다.
- 세액공제 한도·세율은 공식 최신 자료를 기준으로 설정값으로 관리한다.

## 6. MVP 범위

### 6.1 기능 1 — 보유 계좌 선택

- DC형·IRP·연금저축계좌 중 보유 계좌를 선택한다.
- 실제 계좌 연결 대신 시나리오 목데이터를 사용한다.
- 각 계좌가 실제 데이터가 아닌 데모 데이터임을 표시한다.

### 6.2 기능 2 — 계좌 역할 비교

- 납입 주체
- 계좌 목적
- 운용 책임
- 주요 상품군
- 위험자산·상품 제한
- 인출 시 유의점
- 세제 정보 확인 필요 항목

위 기준으로 세 계좌를 비교한다.

### 6.3 기능 3 — 계좌별 현황 진단

- 현금성·원리금보장형 비중
- 주식형·채권형·혼합형 등 자산군 비중
- 위험자산 한도 사용 상태(DC형·IRP)
- 상품군 편중
- 동일 자산군 또는 유사 상품 중복
- 계좌별 수수료·위험등급 확인 필요 항목

### 6.4 기능 4 — 전체 연금계좌 통합 보기

- 세 계좌의 평가금액을 합산한다.
- 전체 자산군 비중을 표시한다.
- 계좌별 비중과 전체 비중을 동시에 보여준다.
- 같은 자산군이 여러 계좌에 중복되어 있는지 표시한다.
- 실제 계좌 이전이나 자산 이동을 자동 제안하지 않는다.

### 6.5 기능 5 — 투자성향·기간 분석

- 위험수용도
- 은퇴까지 남은 기간
- 단기 손실 감내 수준
- 정기 납입 가능성
- 운용 경험

규칙 기반 점수로 성향을 분류하고 결과 이유를 표시한다.

### 6.6 기능 6 — 교육용 계좌별 운용 예시

- 전체 목표 자산군 비중을 먼저 보여준다.
- DC형·IRP·연금저축계좌별로 가능한 운용 예시를 구분한다.
- 계좌별 규칙을 위반하는 상품군 배치를 차단한다.
- 상품명보다 자산군과 역할 중심으로 설명한다.
- 예시는 실제 추천이 아닌 학습용 시나리오임을 표시한다.

### 6.7 기능 7 — 적립 시뮬레이션

입력값:

- 계좌별 현재 적립금
- 계좌별 정기 납입액
- 남은 운용 기간
- 계좌·자산군별 가정수익률
- 수수료·물가 가정

출력값:

- 계좌별 예상 적립금
- 세 계좌 합산 예상 적립금
- 납입원금과 가정수익 구분
- 입력 가정 변화에 따른 결과 비교

### 6.8 기능 8 — 하락장 스트레스 테스트

- 자산군별 하락 가정을 적용한다.
- 계좌별·전체 예상 변동을 비교한다.
- 위험자산 한도와 실제 손실 가능성을 함께 설명한다.
- 결과를 미래 예측이 아닌 가정 기반 시뮬레이션으로 표시한다.

### 6.9 기능 9 — 설명 Q&A

예상 질문:

- DC형과 IRP의 운용 규칙은 어떻게 다른가?
- IRP와 연금저축계좌의 역할은 어떻게 구분해야 하는가?
- 왜 계좌별 비중과 전체 비중을 함께 봐야 하는가?
- 위험자산 한도는 어느 계좌에 적용되는가?
- 세 계좌에 같은 ETF가 있으면 무조건 문제인가?
- 중도인출 전에 무엇을 확인해야 하는가?
- 세액공제 한도는 어디에서 최신 정보를 확인해야 하는가?

LLM은 규칙 엔진 결과와 검증된 콘텐츠를 설명하며 직접 계산하지 않는다.

## 8. 규칙 엔진과 데이터 설계

### 8.1 규칙 엔진 모듈

1. **계좌 분류기**: DC형·IRP·연금저축계좌 구분
2. **계좌 규칙 검사기**: 계좌별 허용 상품·한도·예외 검사
3. **자산군 분류기**: 보유 상품을 현금성·원리금보장·주식·채권·혼합 등으로 분류
4. **계좌 진단기**: 편중·중복·현금성 비중·위험자산 한도 상태 계산
5. **통합 집계기**: 세 계좌 전체의 자산군 비중 계산
6. **성향 분석기**: 설문을 규칙 기반 점수로 분류
7. **적립 시뮬레이터**: 납입액·기간·가정수익률에 따른 결과 계산
8. **스트레스 테스트**: 자산군별 충격 시나리오 적용
9. **설명 데이터 생성기**: 수치·규칙·출처를 구조화해 LLM에 전달

### 8.2 계좌 규칙 데이터

계좌 규칙은 코드에 흩어 넣지 않고 버전이 있는 데이터 테이블로 관리한다.

필수 필드:

- 계좌 유형
- 규칙 이름
- 적용 조건
- 허용 또는 제한 내용
- 한도 값
- 예외 조건
- 근거 기관
- 공식 출처 URL
- 기준일
- 검토자

### 8.3 데이터 구분

| 데이터 | 구분 | 용도 |
|---|---|---|
| 고용노동부·금융감독원 퇴직연금 정보 | 실제 데이터 | DC형·IRP 제도와 공시 근거 |
| 금융위원회·통합연금포털 연금저축 정보 | 실제 데이터 | 연금저축 제도·상품·수익률 근거 |
| KRX·금융회사 공개 상품정보 | 실제 데이터 | ETF·펀드·수수료 보조 정보 |
| 계좌 시나리오 3종 | 목데이터 | 실제 계좌 연동 대체 |
| 성향 설문 응답 | 데모 입력 | 규칙 기반 성향 분류 |
| 시뮬레이션 입력값 | 데모 입력 | 적립 결과·스트레스 테스트 계산 |

### 8.4 목데이터 시나리오

#### 시나리오 A — DC형 방치형

- DC형의 현금성·원리금보장형 비중이 높다.
- IRP와 연금저축계좌는 아직 없다.
- 학습 목표: DC형 운용책임, 디폴트옵션, 자산배분 기초

#### 시나리오 B — 세액공제 가입 후 미운용형

- DC형·IRP·연금저축계좌를 모두 보유한다.
- IRP와 연금저축계좌는 납입만 하고 운용하지 않았다.
- 학습 목표: 계좌 역할 구분, 현금성 자산 점검, 전체 비중 이해

#### 시나리오 C — 계좌별 중복·위험 편중형

- 세 계좌에 유사한 주식형 자산을 중복 보유한다.
- DC형·IRP의 위험자산 한도에 근접해 있다.
- 학습 목표: 계좌별 한도, 전체 자산군 중복, 하락장 위험 이해

### 8.5 데이터 경계

- 사용자 계좌는 목데이터라는 사실을 명확히 표시한다.
- 실제 공시와 시나리오 입력값을 섞어 표현하지 않는다.
- 모든 실제 수치에는 출처와 기준일을 표시한다.
- 세액공제 한도·세율·인출 규정은 기준연도별 설정값으로 관리한다.
- 공식 근거가 없거나 해석이 필요한 값은 `TODO: 확인 필요`로 표시한다.

## 9. AI 및 시스템 설계

### 9.1 시스템 구조

```text
[모바일 웹앱(PWA)]
        │ REST
[FastAPI + LLM 설명 계층]
        │ 엔진 도구 호출
[계좌별 규칙 엔진]
        │
[연금계좌 도메인 모델 + 규칙 테이블 + 실제 공개 데이터 + 목계좌]
```

### 9.2 계산과 설명의 분리

- 계산·한도 판정·상품 적격성 검사는 규칙 엔진이 수행한다.
- LLM은 엔진 결과를 자연어로 설명하고 후속 질문에 답한다.
- LLM이 적립금·수익률·세액공제·한도 값을 직접 계산하지 않는다.
- 답변 속 수치는 엔진 결과와 자동 대조한다.
- 불일치하면 답변을 폐기하고 재생성한다.

### 9.3 AI 가드레일

- 계좌 유형을 확인하지 않은 상품 설명 금지
- 계좌별 규칙을 혼합 적용하는 답변 금지
- 근거 없는 수치와 시장 예측 금지
- 개인별 확정 절세액 표현 금지
- 성향 밖 교육용 예시 차단
- 수익 보장과 실제 주문 유도 표현 금지
- 데이터 출처·기준일·시뮬레이션 가정 표시

## 10. 규제 및 이용자 보호

### 10.1 서비스 표현 원칙

- 특정 상품의 매수를 지시하기보다 계좌 역할·상품군·비교 기준을 설명한다.
- 포트폴리오는 교육용 예시로 표시한다.
- 실제 적합성 판단과 주문은 이용자가 수행한다.
- 세제 관련 값은 기준연도와 공식 출처를 표시한다.
- 계좌별 중도인출·연금수령 조건은 최신 공식 안내 확인을 유도한다.

### 10.2 이용자 보호 원칙

- 수익 가능성과 손실 가능성을 같은 화면에 표시한다.
- 과거 수익률을 미래 수익처럼 표현하지 않는다.
- 장기 예상값은 가정 결과임을 표시한다.
- 목데이터와 실제 데이터를 구분한다.
- MVP에서는 실제 개인정보와 금융계좌 정보를 수집하지 않는다.
- 상품설명서와 금융회사 공식 안내를 확인할 수 있는 링크를 제공한다.

## 11. 성공 기준

### 11.1 기능 검증

1. 계좌 조합이 달라도 전체 사용자 흐름이 중단 없이 완료된다.
2. DC형·IRP에 한도 규칙이 적용되고 연금저축에는 별도 규칙이 적용된다.
3. 계좌별 평가금액 합계와 통합 평가금액이 일치한다.
4. 계좌별 자산군 합계와 전체 자산군 합계가 일치한다.
5. 모든 시뮬레이션에 입력값·가정·기준일·위험 고지가 표시된다.
6. Q&A의 수치와 규칙 설명이 엔진 결과와 일치한다.
7. 목데이터와 실제 공시 데이터가 화면에서 구분된다.

### 11.2 사용자 검증

체험 후 이용자가 다음 질문에 답할 수 있어야 한다.

- DC형·IRP·연금저축계좌는 각각 어떤 역할을 하는가?
- 어느 계좌에 위험자산 한도가 적용되는가?
- 왜 계좌별 비중과 전체 비중을 함께 봐야 하는가?
- 유사한 자산을 여러 계좌에 보유하면 무엇을 확인해야 하는가?
- 시뮬레이션 결과가 확정 수익이 아닌 이유는 무엇인가?
- 실제 계좌별로 다음에 확인할 항목은 무엇인가?

### 11.3 발표 검증

- 세 계좌를 다루는 이유를 한 문장으로 설명한다.
- 세 계좌의 차이와 공통점을 한 화면에서 보여준다.
- 계좌별 규칙이 다르게 적용되는 장면을 시연한다.
- 계좌별 진단과 통합 진단을 연결해 보여준다.
- AI가 계산하지 않는 구조를 설명한다.
- 진단부터 체크리스트까지 하나의 시나리오로 시연한다.

| 계좌 규칙 혼동 | 잘못된 설명 | 버전형 규칙 테이블과 계좌별 자동 테스트 |
| 세제 정보 변경 | 오래된 정보 제공 | 기준연도 설정값·공식 출처·기준일 표시 |
| LLM 수치 환각 | 잘못된 안내 | 계산은 엔진만 수행하고 답변 수치 자동 대조 |
| 실제·목데이터 혼동 | 이용자 오해 | 데이터 구분 라벨과 출처 칩 표시 |
| 추천 서비스로 오해 | 규제 위험 | 교육용 예시·비교·시뮬레이션 표현 사용 |
| 어려운 금융 UX | 사용자 이탈 | 한 화면 한 질문, 계좌별 색상·용어 일관성 유지 |

## 15. 로드맵

### Phase 1 — 3개 연금계좌 운용 가이드 MVP

- 계좌 역할 비교
- 계좌별 목데이터 진단
- 전체 연금계좌 통합 보기
- 투자성향 분석
- 교육용 계좌별 운용 예시
- 적립·하락장 시뮬레이션
- 설명 Q&A
- 계좌별 체크리스트

### Phase 2 — 실제 데이터와 점검 기능 고도화

- DC형·IRP·연금저축 상품 데이터 연결
- 수수료·위험등급·상품설명서 비교
- 계좌 점검 알림
- 학습 진행도와 이해도 확인
- 금융회사별 제공 상품 차이 반영

### Phase 3 — 실계좌·은퇴 단계 확장 검토

- 마이데이터 또는 금융회사 계좌 연동 검토
- 계좌 이전과 납입 우선순위 교육
- 국민연금·DB형을 포함한 노후자산 조회 검토
- 인출 단계와 세금 관련 교육 콘텐츠 검토
