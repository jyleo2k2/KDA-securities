# 연금계좌 운용 가이드 SWOT 분석

> 분석 대상: DC형 퇴직연금·IRP·연금저축계좌 운용 가이드
> 문서 버전: v2.0 · 기준일: 2026-07-14 (구 `swot-analysis.md`의 TOWS 전략·발표 요약·경쟁군 비교를 병합, SWOT 단일 문서로 통합. 원본은 `archive/`)
> 제품 기준: [프로젝트 기획서](../10_기획/기획서.md) v2.2
> 규제 내용은 전략 검토용이며 상용화 전 준법감시·법무 확인이 필요하다.

## 1. 전략 결론

프로젝트는 계속 추진할 가치가 있다. 연금시장이 성장하고 직접 운용 범위가 넓어지는 가운데, **관심은 있지만 방법을 모르는 이용자**의 정보·행동 격차가 공식 자료로 확인되기 때문이다.

다만 통합조회, 계산기, 포트폴리오 예시, AI 챗봇은 각각 이미 존재하거나 쉽게 복제된다. 방어 가능한 차별점은 단일 기능이 아니라 다음 조합이다.

> **세 계좌의 규칙 분리 × 계좌별·통합 상태 해석 × 근거가 보이는 what-if × 이용자 자기결정**

가장 큰 약점은 이 조합의 사용자 가치가 아직 설문·과업 테스트로 검증되지 않았고, 실계좌 대신 목데이터를 사용한다는 점이다. 따라서 10개 기능을 균등 구현하지 않고, 위 조합이 드러나는 P0 골든패스에 집중해야 한다.

### 한 문장 판단

> 연금정보를 더 보여주는 서비스가 아니라, 서로 다른 세 연금계좌의 규칙과 전체 자산구성을 근거와 함께 해석해 이용자가 스스로 다음 행동을 결정하도록 돕는 서비스로 추진한다.

## 2. 판단 근거 스냅샷

| 외부 근거 | 확인 내용 | 전략적 의미 |
|---|---|---|
| 2025년 퇴직연금 투자 백서 | 적립금 501.4조원, 전년 대비 16.8% 증가. DC·IRP 54.3%, ETF 투자금액 48.7조원 | 시장 성장과 자기운용 수요 확대 |
| 2025년 연금저축 투자 백서 | 적립금 198.2조원, 가입자 840.3만명. 연금저축펀드 적립금은 전년 대비 50.7% 증가 | 세 계좌 통합 관점의 대상 확대 |
| 경총 2025 인식조사 | 57.1%가 “관심은 있지만 방법을 모름”, 24.6%가 정보 비대칭 해소를 최우선 과제로 선택 | 설명·의사결정 지원 수요 |
| 통합연금포털 개편 | 비교·검색·초보자 콘텐츠를 강화한 개편 포털을 2026년 12월 공개 예정 | 공공 데이터 기회이자 일반 정보 기능의 대체 위험 |
| 퇴직연금 RA 일임 | 금융위가 17개 투자일임업자의 서비스를 혁신금융서비스로 지정하고 2025년부터 순차 출시 | 자동운용과 직접 경쟁하면 불리함 |
| 금융권 생성형 AI 확산 | 2026년 4월 기준 혁신금융서비스 169건 지정, 45개 서비스 출시 | 설명형 UI 수용성은 높지만 AI 자체는 차별점이 아님 |

위 수치는 각 공식 자료의 발표 기준이며 서비스 화면에 사용할 때는 출처와 기준일을 다시 확인한다.

## 3. SWOT 평가

중요도는 `영향도 × 시급성 × 근거 강도`를 종합한 5점 정성평가다.

### 3.1 Strengths — 내부 강점

| ID | 강점 | 중요도 | 전략적 의미 |
|---|---|---:|---|
| S1 | DC·IRP·연금저축 규칙 분리 | 5 | 일반 통합조회와 구분되는 도메인 전문성의 기반 |
| S2 | 규칙 엔진 계산·LLM 설명 분리 | 5 | 수치 환각을 줄이고 테스트·재현·감사 추적 가능 |
| S3 | 계좌별 진단과 전체 연금자산 연결 | 4 | 어느 계좌의 자산이 전체 위험을 만드는지 설명 가능 |
| S4 | 가정·기준일·출처가 보이는 what-if | 5 | 장기 예상값을 예측이 아닌 비교 도구로 제한 |
| S5 | 자동 일임이 아닌 자기결정 지원 | 4 | RA와 다른 사용 목적을 만들고 이용자 이해를 강화 |
| S6 | 세 가지 목데이터 시나리오 | 3 | 골든패스와 자동 테스트를 빠르게 연결 가능 |
| S7 | 심리적 불안을 숫자로 전환 | 4 | 막연한 단기손실 공포를 예상 적립금·하락 시나리오로 "관리 가능한 숫자"로 변환 — 유저가 *왜 쓰는가*의 감정적 훅 |
| S8 | 하네스 방법론 자산 | 3 | 비전문 팀원도 AI로 산출물 생성, 설명가능 구조와 궁합. 재사용 템플릿 보유([참고파일/](../../참고파일/)) |

### 3.2 Weaknesses — 내부 약점

| ID | 약점 | 중요도 | 대응 방향 |
|---|---|---:|---|
| W1 | 실계좌 미연동 | 5 | 데모의 한계를 고정 표시하고 과업 테스트로 이해·행동 가치를 검증 |
| W2 | 기능 범위가 일정 대비 큼 | 5 | P0 골든패스 우선, what-if·스트레스·Q&A는 축소 |
| W3 | 규칙표·성향·가정 미확정 | 5 | 공식 근거가 있는 규칙 3~5개부터 엔진과 테스트로 고정 |
| W4 | 단일 기능의 모방 방지력 부족 | 4 | 기능 수가 아니라 규칙→진단→근거→행동의 연결 경험에 집중 |
| W5 | 연금 점검의 낮은 사용 빈도 | 3 | 가입·이직·납입·분기 점검·급락 등 이벤트 기반 재진입 설계 |
| W6 | 타깃 범위가 넓음 | 3 | 설문을 계좌 보유 조합별로 분석해 핵심 페르소나 한 명을 고정 |
| W7 | LLM 외부 클라우드 규제 미검증 | 3 | 금융권 망분리·클라우드 이슈. 현직자·컴플라이언스 검증 대기 |

### 3.3 Opportunities — 외부 기회

| ID | 기회 | 중요도 | 활용 방향 |
|---|---|---:|---|
| O1 | 퇴직연금·연금저축 시장 성장 | 5 | 직접 운용·이해 지원이 필요한 사용자 기반 확대 |
| O2 | 정보와 행동 사이의 공백 | 5 | 일반 교육을 실제 계좌 점검 기준과 행동으로 번역 |
| O3 | 공식 공시·포털 데이터 | 4 | 규칙·상품 데이터와 출처 칩으로 신뢰 확보 |
| O4 | 금융권 AI 도입 환경 개선 | 3 | 설명형 인터페이스 도입 가능성 확대 |
| O5 | 키움의 IRP·키우GO·투자 플랫폼 | 4 | 새 운용 엔진보다 기존 기능을 이해·승인하게 돕는 레이어로 결합 |
| O6 | 자체 설문·프로토타입 검증 | 4 | 계좌 비교·통합 해석·what-if 수요를 기능별로 실증 |

### 3.4 Threats — 외부 위협

| ID | 위협 | 중요도 | 방어 방향 |
|---|---|---:|---|
| T1 | 통합연금포털 기능 확장 | 5 | 일반 조회·정보 경쟁을 피하고 규칙 적용·행동 설명에 집중 |
| T2 | 증권사·은행의 RA 상품제시·일임 | 5 | 편리함 대신 이해·근거·자기결정이라는 목적을 선명하게 유지 |
| T3 | 생성형 AI의 빠른 범용화 | 4 | AI 명칭이 아니라 엔진·출처·검증 구조를 차별점으로 제시 |
| T4 | 개인화 시 규제 부담 증가 | 5 | MVP 출력을 자산군 교육 예시와 what-if로 제한 |
| T5 | 세제·한도·상품 규칙 변경 | 4 | 기준일·버전·검토자·자동 테스트를 운영 체계로 구축 |
| T6 | 목데이터·수익 예측 오인 | 4 | 데이터 종류·가정·미래성과 비보장을 UI에 고정 표시 |
| T7 | 사용자 신뢰 확보 난이도 | 4 | 연금은 장기 돈 — 근거·한계·리스크 고지가 약하면 신뢰 상실. 하락장엔 "설명대로 했는데 손실" 역풍 가능 → 스트레스 테스트 결과를 선제 제시 |

## 4. 핵심 전략

SWOT 조합에서 실행 우선순위가 높은 전략만 남긴다.

| 전략 | 근거 조합 | 실행안 |
|---|---|---|
| 1. 설명형 골든패스 | S1·S2·S4 × O2·O3 | 공식 규칙으로 계산한 상태를 `문제 → 근거 → 확인할 행동`으로 번역 |
| 2. 키움 설명 레이어 | S3·S5 × O5 | 키우GO와 경쟁하는 자동운용이 아니라 기존 연금 기능을 이해·승인하게 지원 |
| 3. 범위 축소 | W2·W3 × O3 | 공식 데이터가 연결되는 규칙 3~5개와 통합 진단을 먼저 완성 |
| 4. 일반 정보 경쟁 회피 | S1·S4 × T1·T3 | 포털·챗봇형 화면을 줄이고 계좌별 규칙 적용과 출처를 핵심 시연으로 사용 |
| 5. 규제 안전 경계 | S2·S5 × T2·T4 | 자산군 교육 예시·what-if까지만 제공하고 특정 상품·주문은 제외 |
| 6. 재현 가능한 신뢰 | S6 × T5·T6 | 시나리오마다 규칙 판정·합산·출처·기준일·목데이터 라벨을 자동 테스트 |

### 전략상 포기할 경쟁

- 통합연금포털보다 많은 일반 정보 제공
- RA보다 편리한 자동운용
- 범용 챗봇보다 많은 자유 질의응답
- 근거 없는 초개인화·수익률 예측

## 5. MVP에 미치는 영향

상세 기능 정의는 [프로젝트 기획서 §2](../10_기획/기획서.md#2-mvp-결정)에서만 관리한다. SWOT의 우선순위 판단은 다음과 같다.

| 우선순위 | 범위 | 이유 |
|---|---|---|
| P0 | 계좌 규칙 비교, 계좌별 진단, 통합 해석, 근거 설명, 체크리스트 | 차별화 조합을 직접 증명 |
| P1 | 단일 적립 what-if, 충격 시나리오 1개, 성향 가드레일, 제한형 Q&A | P0 이해를 보조하되 일정 위험을 통제 |
| P2 | 실계좌, 상품 스코어링, 개인화 제안, 주문·리밸런싱, 세금 최적화 | 데이터·인허가·보안·운영 요건이 추가됨 |

MVP 성공 여부는 구현 기능 수가 아니라 다음 장면이 설득력 있게 연결되는지로 판단한다.

1. 같은 자산이라도 계좌에 따라 적용 규칙이 다르다.
2. 개별 계좌에서는 보이지 않던 중복·편중이 통합 화면에서 드러난다.
3. 결과에 사용된 수치·규칙·출처를 확인할 수 있다.
4. 이용자가 자동 주문 없이 다음 행동을 선택할 수 있다.

## 6. 검증 계획

### 6.1 설문

확정한 10문항은 다음 가설을 검증하는 데 사용한다.

| 검증 가설 | 문항 조합 | 확인할 결과 |
|---|---|---|
| 계좌 비교가 필요한가 | Q1 × Q2 | 복수 계좌 보유자의 낮은 차이 이해도 |
| 개별 진단이 필요한가 | Q3 × Q5 | 낮은 점검 빈도와 자산구성 파악의 어려움 |
| 통합 보기가 필요한가 | Q1 × Q6 | 복수 계좌 보유자의 전체 자산군 인지 부족 |
| 제안 기능이 문제와 맞는가 | Q4 × Q7 | 실제 어려움과 선택한 도움 기능의 일치 |
| what-if 수요가 있는가 | Q7 × Q8 | 적립·하락장 비교 선택률 |
| 자기결정 포지셔닝이 유효한가 | Q9 × Q10 | 근거 설명 후 직접 결정 선호와 출처 요구 |

표본 수와 통과 기준은 조사 대상·모집 방식을 확정한 후 정한다. 응답 수집 전까지 자체 설문은 근거가 아니라 검증 계획이다.

### 6.2 프로토타입 과업 테스트

5~8명을 대상으로 다음을 확인한다.

1. 세 계좌의 역할 차이를 설명할 수 있는가?
2. 위험자산 규칙이 적용되는 계좌를 구분하는가?
3. 계좌별 비중과 전체 비중의 차이를 해석하는가?
4. 중복 자산이 전체 위험에 미치는 영향을 설명하는가?
5. 시뮬레이션이 확정 수익이 아님을 이해하는가?
6. 실제 계좌에서 다음에 확인할 행동을 하나 선택하는가?

### 6.3 계속·수정 판단

- **계속**: P0 흐름을 이해하고 근거 확인 후 스스로 다음 행동을 선택한다.
- **수정**: 계좌 규칙과 통합 화면은 이해하지만 행동으로 연결되지 않는다.
- **범위 축소**: 세 계좌 동시 경험보다 특정 계좌·페르소나에서만 문제가 강하게 나타난다.
- **포지셔닝 재검토**: 일반 정보·자동운용 선호가 설명형 자기결정보다 일관되게 높다.

## 부록 A — TOWS 교차 전략 (구 swot-analysis.md 병합)

> SWOT를 교차시켜 실행 전략으로. 나열이 아니라 다음 행동.

### SO (강점으로 기회 잡기 — 공격)

- **실물이전 컨시어지를 히어로 후보로.** 설명 엔진 + 통합연금포털 공시 데이터로 "당신 상품 하위 30% → 이전 시 절감액 → 이전 추적"을 만든다. 키움 실물이전 유치 목표에 직결.
- **발표 히어로 메시지 확정.** *"하고 싶은 사람 77%, 실제 실행 13%, 자동화(디폴트옵션)는 85% 안정형으로 실패 — 우리는 이해시켜 스스로 옮기게 한다."* 검증된 타깃(정보부족형 57.1%)과 니즈 1순위(정보 비대칭 해소 24.6%)가 정확히 겹침.

### WO (기회로 약점 보완)

- **목데이터 한계를 실데이터로 상쇄.** 실계좌 없이도 "실 시장데이터(통합연금포털) + 목계좌 3종"으로 데모 신뢰도 확보. 실/목 경계를 화면에 명시해 약점을 정직성으로 전환.
- **수익모델 프록시 = 이전 전환.** "중립 설명"의 수익화 대신 키움 실물이전 유치를 KPI로 삼아 "이전 전환 수"를 가치 지표로.

### ST (강점으로 위협 방어)

- **모방 방어 = 조합의 두께.** 단일 기능이 아니라 [3계좌 규칙분리 × 개별·통합 진단 × 설명 × 실데이터]를 한꺼번에. 키움이 설명 UX만 얹어도 이 조합까지 재현해야 따라옴.
- **신뢰를 설계로 확보.** 모든 제안에 근거·출처칩·한계·리스크 고지를 기본 탑재하고, 하락장엔 "장기 관점 + 스트레스 테스트 결과"를 먼저 보여줘 "설명대로 했는데 손실" 역풍을 선제 차단. (T7 대응)

### WT (약점 최소화 · 위협 회피)

- **경쟁이 아니라 보완재.** 독자 사업화 대신 "키움 설명 레이어 프로토타입"으로 스코프 고정 → 모방 대상이 아니라 채택 대상이 됨.
- **MVP를 좁힌다.** 3계좌 전부보다 핵심 플로우(의향-실행 격차 진단 → 설명 → 다음 행동)부터. 무관심층·안정 선호 50대는 명시적 비타깃으로 선언.

## 부록 B — 발표용 요약·경쟁군 비교 (구 swot-analysis.md 병합)

### 발표용 한 장

- **왜 이긴다**: 유저가 1순위로 원하는 것(정보 비대칭 해소)을, 아무도 안 채운 자리(설명 레이어)에서, 규제상 가장 안전한 구조로 한다.
- **가장 큰 위험**: 키움의 모방 → 대응은 조합의 두께 + 보완재 포지션.
- **다음 검증**: 키움 현직자(모방 가능성·LLM 클라우드 규제)·MVP 스코프 확정.

### 경쟁군 한눈에 — "우리가 뚫을 지점"

| 경쟁군 | 강점 | 약점 | 우리가 뚫을 지점 |
|---|---|---|---|
| 증권사 MTS 연금 메뉴 | 실제 매매·상품 라인업·계좌개설 | 상품 중심, 초보자 설명 부족 | "왜 이 상품인지" 설명하는 교육형 PB |
| 은행·보험 퇴직연금 앱 | 안정감·기존 고객 기반 | 원리금·보수적 이미지, 투자 UX 약함 | 투자형 연금 이해·시뮬레이션 |
