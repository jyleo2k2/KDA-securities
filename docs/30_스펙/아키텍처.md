# 기술 아키텍처 — 연금 코파일럿

> 코드·데이터·외부 연동의 기술 SSOT. 역할을 겹치지 않게 자르고 결과를 재현하기 위한 계약이다.
> 근거: [기획서.md](../10_기획/기획서.md) v2.4 §4·§7 · 단계: 원격 실데이터 E2E 완료 / 챗봇 pydantic-ai·검토 과정 / BGE-M3 하이브리드 검색 / 홈 탭 목데이터 연결(2026-07-15)

## 1. 확정 스택과 단방향 의존

```text
[① 프레젠테이션]
React + TypeScript + Vite 모바일 PWA
        │ REST/JSON
        ▼
[② API·오케스트레이션]
FastAPI
  ├─ FSS/NAVER 외부 API 수집·조회
  ├─ 규칙 엔진 도구 호출
  ├─ PostgreSQL 구조화 조회
  ├─ RAG 검색(PostgreSQL 전문검색 + pgvector)
  └─ Claude API 설명·Q&A 하네스
        │
        ├───────────────┐
        ▼               ▼
[③ 비즈니스 로직]   [④ 데이터]
Python 규칙 엔진     Supabase PostgreSQL
6개 모듈             구조화 테이블 + pgvector
```

의존 방향은 `frontend → FastAPI → engine/data`다. 역방향 import를 금지한다.

- 프론트엔드는 엔진·DB를 직접 계산 계층으로 사용하지 않고 REST 계약에 의존한다.
- FastAPI는 인증 컨텍스트, 외부 API, DB, 규칙 엔진, RAG와 LLM을 오케스트레이션한다.
- 규칙 엔진은 가능한 한 순수 함수로 유지하며 FastAPI·Supabase·LLM에 의존하지 않는다.
- PostgreSQL은 원본·상태·실행 이력을 저장하지만 제품 판단 로직을 대신하지 않는다.
- Claude API는 엔진 수치와 검색 근거를 설명할 뿐 직접 계산·판정하지 않는다.

## 2. 규칙 엔진 6모듈 — 계산·판단의 단일 소스

| # | 모듈 | 입력 → 출력 |
|---|---|---|
| 1 | 성향 분석 | 설문 → 5단계 성향(규칙 스코어링) |
| 2 | 계좌 규칙 검사 | 계좌 유형·보유 상품 → DC형/IRP 한도 또는 연금저축 적격성 판정 |
| 3 | 계좌별 진단 | 보유 상품·현금성 자산·자산군 비중 → 계좌별 운용 점검 항목 |
| 4 | 통합 집계 | DC형·IRP·연금저축 자산 → 전체 자산군 비중·중복 |
| 5 | 적립 시뮬레이션 | 계좌별 납입액·기간·승인 가정수익률 → 개별·합산 시나리오 적립금 |
| 6 | 포트폴리오 예시 | 성향·기간·계좌 규칙 → 자산군 단위 전략·교육용 예시·근거 |

> 설명 가능성은 별도 예측 모델이 아니라 엔진 입력·출력·규칙 버전·출처를 연결해 확보한다. 화면의 계좌 상태 카드, 단계별 운용 원리, what-if는 같은 엔진을 다른 입력으로 실행한 표현이다.

## 3. FastAPI·LLM·RAG 계약

- **Engine tools**: 위 6개 엔진 모듈을 명시적 입력·출력 스키마를 가진 도구로 등록한다.
- **Retrieval tools**: 공식 지식 RAG, 구조화 공시 조회, 최신 뉴스 조회를 서로 다른 도구로 둔다.
- **Guardrails**: 수치는 엔진 또는 SQL/API 결과만 인용한다. 성향 밖 상품과 계좌 규칙 위반 결과를 차단한다.
- **RAG**: 제도·용어·규칙의 근거를 찾는다. 최신 공시 숫자, 뉴스 목록, 사용자 계좌 계산을 RAG에 맡기지 않는다.
- **LLM**: 엔진 결과와 검색 근거를 요약·비교·설명한다. 새 숫자·목표가·매매의견을 만들지 않는다.
- **Verification loop**: 답변 수치와 엔진·SQL 결과를 대조하고 불일치하면 재생성 또는 답변 거절한다.
- **Evidence**: 답변과 엔진 실행, 적용 규칙, 데이터 출처, RAG 청크, 뉴스 링크를 연결한다.
- **Logging**: 입력 스냅샷·출력·엔진 버전·규칙 버전·모델/프롬프트 버전·근거를 감사 가능하게 남긴다.
- **Audited API**: `/engine/risk-cap/audited`는 Supabase Bearer token으로 uid를 검증하고, DB 규칙 버전·파라미터와 계산 결과를 대조한 뒤 `run_id`를 반환한다. 인증 없는 `/engine/risk-cap`은 데모 계산만 하며 DB에 쓰지 않는다.
- **Chatbot MVP**: `/chat/demo`는 자연어 질문을 계좌 규칙·목시나리오·공시·뉴스·범위 밖 요청으로 분류하고 Pydantic 응답 계약으로 근거 연결을 검증한다. `/chat/demo/capabilities`와 `/chat/demo/scenarios`는 프론트엔드 연결용 기능·시나리오 계약을 제공한다. `/engine/mock-scenario/{code}`는 같은 목시나리오를 홈 화면 시연용으로 엔진에 태워 반환한다.
- **Local RAG fallback**: 서버 `DATABASE_URL`이 없을 때는 허용된 프로젝트 검증 문서를 제목 단위로 분할한 로컬 전문검색을 사용한다. 공시 fixture는 챗봇 수치 답변에 사용하지 않는다.
- **Claude narration(pydantic-ai)**: API 키가 있으면 pydantic-ai Agent(NativeOutput 구조화 출력 + adaptive thinking)가 검증된 답변만 자연어로 재서술하고, 검토 과정(`narration_reasoning` — thinking 요약 우선, 없으면 검토 노트)을 함께 반환한다. 원문에 없던 숫자를 본문에서 감지하면 결정론적 답변으로 복귀하고, 검토 과정에서 감지하면 그 필드만 생략한다. API 키가 없거나 호출이 실패해도 골든패스는 동작한다.

## 4. 데이터 계층 — SQL/RAG 및 실/목 경계

모든 수치의 종류·모집단·변환·허용 용도와 목데이터 병합 게이트는 [데이터 품질·설명 가능성 계약](./데이터_품질_계약.md)을 따른다.

| 데이터 | 실/목 | 저장·조회 | 용도 |
|---|---|---|---|
| 통합연금포털(FSS) OpenAPI 공시 | **실** | PostgreSQL 공시 스냅샷 + 원본 JSON + 수집 이력 | 회사별·제도별 적립금·과거 수익률·수수료 |
| KRX·금융회사 공개정보 | **실** | 구조화 테이블 또는 검증 캐시 | FSS 공시 보조 |
| NAVER 검색 API 뉴스 | **실 메타데이터** | 제목·요약·원문 링크·발행일·검색어·원문 URL 고유 제약 | 최신 뉴스 목록과 선택 뉴스 맥락 |
| 정부·공공기관 공식 문서 | **검증 지식** | 문서·청크·전문검색 값·pgvector embedding | 제도·용어·규칙 RAG |
| 사용자 DC형·IRP·연금저축계좌 | **목** | 시나리오·계좌·보유자산 구조화 테이블 | 실제 계좌 연동 대체 |
| 공개 포트폴리오 | **목** | 익명 프로필·포트폴리오·보유자산 | 벤치마킹 시연 |

고정 원칙:

- FSS fixture는 파서·회귀 테스트 입력이다. 공시 테이블의 실 적재는 서버가 OpenAPI를 직접 호출한 결과로 생성한다.
- 공시 수집은 호출 종류·요청 기간·시각·상태·수신/적재 건수·오류를 `ingestion_runs`에 남긴다.
- 금액은 원 단위 `numeric`, 수익률·수수료율은 고정소수점 `numeric`을 사용하고 원본 값·단위·payload를 보존한다. FSS 응답 본문에는 적립금 단위가 없어 현재 백만원/억원 변환은 프로젝트 가정과 `reserve_unit_not_in_api_response` 품질 플래그를 함께 저장하며, 운영 전 공식 단위 근거를 추가 확인한다.
- NAVER 뉴스는 MVP에서 기사 전문을 저장하거나 embedding하지 않는다. 최신성은 `published_at` 정렬로 보장한다.
- RAG에는 검증된 공통 지식만 넣는다. 사용자 목계좌·성향·진단·대화의 개인정보성 필드는 embedding하지 않는다.
- 모든 화면 수치에는 출처·기준일·수집 시각·실/목 구분을 표시한다.
- 관측값·파생값·합성값·미래 가정·엔진 결과를 동일한 수익률 필드에 섞지 않는다.

## 5. PostgreSQL 스키마 그룹

실제 마이그레이션의 테이블명과 제약이 최종 기준이다.

| 그룹 | 테이블 | 책임 |
|---|---|---|
| 출처·수집 | `data_sources`, `ingestion_runs` | 출처, API 호출, 원본 위치, 수집 상태·건수 |
| 기관·공시 | `financial_institutions`, `institution_aliases`, `pension_savings_provider_stats`, `retirement_provider_stats` | 회사명 표준화, 연금저축·퇴직연금 공시 스냅샷 |
| 자산·목계좌 | `asset_classes`, `mock_scenarios`, `mock_accounts`, `mock_holdings` | 자산 분류와 계좌 시나리오 3종 |
| 목 벤치마크 | `mock_public_profiles`, `mock_public_portfolios`, `mock_public_portfolio_holdings` | 익명 공개 포트폴리오 시연 |
| 규칙·실행 | `rule_sets`, `pension_rules`, `engine_runs`, `engine_run_evidence` | 버전형 규칙, 엔진 입력·출력, 규칙·출처 근거 |
| RAG·콘텐츠 | `knowledge_documents`, `knowledge_chunks`, `news_items`, `curated_contents` | 공식 문서·청크·embedding, 뉴스 메타데이터, 검수 콘텐츠 |
| 챗봇 | `chat_sessions`, `chat_messages`, `chat_message_evidence` | 대화와 엔진·문서·청크·뉴스 근거 연결 |

`knowledge_chunks.embedding`은 **BGE-M3(1024차원)**로 확정됐다(2026-07-15). 적재는 `scripts/embed_knowledge_chunks.py`(선택 그룹 `uv sync --group embeddings`), 검색은 전문검색+벡터 RRF 하이브리드이며 임베딩 미설치·실패 시 전문검색으로 폴백한다. 차원 고정·HNSW 인덱스 마이그레이션(`*_fix_embedding_dimension_bge_m3.sql`)은 원격 적용 대기 중(`scripts/apply_embedding_migration.py`, 이재용 직접 실행).

## 6. 외부 API 수집 계약

### 6.1 통합연금포털(FSS)

1. FastAPI 서버 프로세스가 환경변수의 API 키로 직접 호출한다.
2. 호출 시작 시 `ingestion_runs`를 만들고 성공·부분 성공·실패를 기록한다.
3. 원본 응답을 보존하고 회사명을 표준 기관·별칭에 연결한다.
4. 퇴직연금과 연금저축은 필드·단위가 다르므로 별도 공시 테이블에 정규화한다.
5. DB·DC·IRP 공시는 보존하되 사용자 진단 대상은 DC·IRP·연금저축으로 제한한다.
6. fixture와 실호출 결과를 혼동하지 않으며 출처·기준분기·수집시각을 검증한다.

### 6.2 NAVER 검색 API

1. API 자격증명은 FastAPI 서버 환경변수에만 둔다.
2. 제목·요약·NAVER 링크·원문 링크·발행일·검색어·수집시각을 저장하고, 같은 출처의 원문 URL 고유 제약으로 중복을 제거한다.
3. 최신 뉴스 목록은 SQL 날짜 정렬 또는 API 결과 순서를 사용하고 벡터 유사도를 최신성 기준으로 사용하지 않는다.
4. 사용자가 선택한 뉴스의 의미를 묻는 경우 뉴스 메타데이터, 공식 문서 RAG, 계좌 규칙 엔진 결과를 분리해 LLM에 전달한다.

## 7. Supabase 보안 계약

- 브라우저에는 publishable key만 허용하며 `service_role` 또는 secret을 노출하지 않는다.
- 노출 스키마의 모든 테이블은 RLS를 활성화한다. Data API 접근 권한(`GRANT`)과 행 접근 정책(RLS)은 별도로 검증한다.
- 사용자 소유 실행·대화 데이터는 `TO authenticated`와 `(select auth.uid()) = owner_id` 조건을 함께 적용한다.
- UPDATE 정책은 `USING`과 `WITH CHECK`를 모두 두고 필요한 SELECT 정책을 함께 둔다.
- 내부 수집·규칙·공시 원본·RAG 데이터는 기본적으로 FastAPI 서버 경유로 접근한다.
- 뷰를 노출할 때는 `security_invoker = true`를 사용하거나 노출 권한을 명시적으로 차단한다.
- 원격 `KDA-securities`에서 마이그레이션·RLS·인덱스·Data API 권한과 익명/인증/service_role 역할을 검증했다(2026-07-15). 내부 테이블의 `anon` 권한은 회수하고 인증 사용자에게는 소유 대화·엔진 결과 최소 권한만 부여한다.

## 8. 폴더·담당 경계

```text
frontend/             ① React + TypeScript + Vite PWA (4탭 골격·연금가이드 챗 화면)
backend/app/api/      ② FastAPI 라우터(엔진 도구·공시·뉴스·RAG·챗봇)
backend/app/chat/     ② 챗봇 오케스트레이션(서비스·Claude 내레이터·로컬 지식)
backend/app/ingestion/·retrieval/  ② 외부 API 수집·조회 저장소
backend/app/engine/   ③ 순수 Python 규칙 엔진(6모듈+전략)
supabase/migrations/  ④ PostgreSQL/pgvector 스키마·RLS·권한·seed 마이그레이션
data/                 FSS fixture·목시나리오 JSON(실/목 라벨 필수)
tests/                엔진·수집·API·스키마 계약 테스트
docs/                 제품·기술·규제·팀 문서
```

공유 계약(REST 스키마, 엔진 I/O 타입, 데이터베이스 마이그레이션) 변경 시 PR에 `계약 변경`을 명시한다.
