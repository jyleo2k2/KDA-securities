# 챗봇 추천 카드·답변 시각화 계약

> 상태: **구현 완료 — main 반영(PR #78 머지, `계약 변경` 포함)** · 최종 갱신: 2026-07-20
> 구현 대상: `backend/app/chat/**` · `backend/app/api/chat.py` · `frontend/src/pages/GuidePage.tsx` 외
> 이 작업은 프론트-챗봇 세션 간 계약 변경을 포함한다. PR에는 `계약 변경`과 SSE `response` 이벤트 스키마 변경을 명시한다.

## 1. 초기 카드 카탈로그

`GET /chat/cards`는 비인증 정적 카탈로그를 반환한다. DB 조회는 하지 않는다.

```json
{
  "cards": [
    {
      "card_id": "news_market",
      "title": "오늘 증시 뉴스",
      "message": "오늘 증시 뉴스 알려줘.",
      "intent": "news",
      "conditions": [],
      "priority": 10,
      "preview": null
    }
  ]
}
```

| card_id | intent | message | conditions | priority |
|---|---|---|---|---:|
| `news_market` | NEWS | 오늘 증시 뉴스 알려줘. | — | 10 |
| `tax_credit` | PENSION_TAX | 올해 받을 수 있는 연금세액공제가 궁금해. | — | 20 |
| `withdrawal_tax` | ACCOUNT_RULE | 연금계좌를 중도에 해지하면 어떻게 돼? | — | 30 |
| `account_diff` | ACCOUNT_RULE | DC형, IRP, 연금저축은 뭐가 달라? | — | 40 |
| `edu_portfolio` | EDUCATIONAL_PORTFOLIO | 내 상황에 맞는 연금저축전략을 알려줘. | — | 50 |

초기 추천 카드 다섯 장은 로그인·시나리오·설문 여부와 관계없이 항상 표시한다. `맞춤형 포트폴리오`는 설문이 없으면 기존 설문 완료 안내를 반환하고 임의의 나이·성향을 만들지 않는다. 조건 태그 계약은 `requires_scenario`, `requires_survey`, `requires_auth`로 유지하며, 프론트는 알 수 없는 태그를 숨긴다. `preview`는 확장 슬롯이며 이번 구현에서는 항상 `null`이다.

`SUGGESTED_CHAT_PROMPTS`는 부팅 프리워밍 전용이다. 문구는 카탈로그의 `message`와 문자열이 정확히 일치해야 하며, 이번 변경에서는 세액공제 질문 한 건만 유지한다.

카탈로그에서 제거된 질문의 의도 분류·처리기와 대화 중 후속 질문은 삭제하지 않는다. 사용자가 같은 내용을 자연어로 직접 입력하면 기존 기능을 계속 제공한다. `DC형, IRP, 연금저축은 뭐가 달라?`는 결정론적 계좌 개요로 라우팅하며, IRP·DC형의 일반 위험자산 70% 원칙과 연금저축의 별도 상품 적격성 규칙을 출처와 함께 표시한다.

## 2. 대화 중 후속 카드

`ChatResponse.suggested_follow_ups: list[SuggestedFollowUp] = []`를 추가한다.

```text
SuggestedFollowUp:
  follow_up_id: str
  label: str
  message: str
```

서버가 응답 인텐트와 대화 맥락으로 최대 3개를 생성한다. 클라이언트 전용 상태에 의존하는 질문은 넣지 않는다.

| 응답 인텐트 | 후속 카드 |
|---|---|
| NEWS | 첫 번째 뉴스 자세히 · 반대 지역 증시 뉴스 · 다른 뉴스 더 보기 |
| MOCK_PORTFOLIO | IRP 위험자산 한도 기준 · 연금 세액공제 계산 |
| PENSION_TAX | 세액공제 응답일 때만 중도해지 세금 |
| EDUCATIONAL_PORTFOLIO | 연금계좌의 위험자산 한도 적용 |
| 그 외 | 빈 배열 |

NEWS 지역 전환은 응답 `market_region`이 `kr`/`us`일 때만 반대편을 만든다. `all`에는 지역 전환 카드를 넣지 않는다.

## 3. 답변 시각화

`ChatVisualization.series: list[VisualizationSeries] = []`를 추가한다. 기존 `items` 스키마와 `verify_evidence_links`의 숫자 대조는 유지한다.

```text
VisualizationSeries:
  label: str
  unit: str
  points: list[VisualizationPoint]

VisualizationPoint:
  position: int
  label: str
  value: Decimal
```

`VisualizationKind`에는 `sleeve_allocation`, `stress_scenarios`, `disclosure_comparison`, `accumulation_projection`를 추가한다. 시각화 수치는 응답에 이미 있는 엔진·공시 근거에서 복사하며 새 계산을 하지 않는다. 내레이터에 시각화 값은 주입하지 않는다.

| kind | 부착 대상 | 데이터 |
|---|---|---|
| `sleeve_allocation` | 교육용 포트폴리오 | 5슬리브 목표비중 |
| `stress_scenarios` | 교육용 포트폴리오 | 스트레스 3종 손실 추정치 |
| `disclosure_comparison` | 공시 응답 | 회사별 과거 수익률과 **공시값이 있는 경우의** 1년 수수료율 |
| `accumulation_projection` | 적립 시뮬레이션을 응답에 싣는 경로 | 저/기준/고 시계열 |

현재 챗 서비스에는 적립 시뮬레이션 평가를 응답에 싣는 결정론 경로가 없으므로 `accumulation_projection`은 이번 구현에서 생성하지 않는다. 새 엔진 호출 경로도 만들지 않는다.

`_attach_visualizations`는 리스트 축적 방식으로 바꾼다. 기존 `asset_allocation`, `risk_cap`, `tax_summary`의 생성 조건·데이터·순서는 유지한다.

## 4. 프론트 최소 구현

카드 목록은 노란색 아이콘 없이 CSS `scroll-snap` 캐러셀로 표시하며 온전한 두 장과 다음 카드 일부가 보이게 한다. 차트·캐러셀·상태관리·라우팅 라이브러리를 추가하지 않는다.

- 카탈로그 1회 호출 후 로컬 조건으로 필터·정렬한다.
- 마지막 assistant 응답 아래에 `suggested_follow_ups`를 일반 질문과 같은 전송 경로로 렌더한다.
- `sleeve_allocation`은 기존 도넛을 재사용한다.
- `stress_scenarios`와 `disclosure_comparison`은 기존 수치 그리드를 재사용한다.
- `series`는 CSS 기반 단순 시계열 목록으로 렌더한다.

## 5. 검증

- 카탈로그는 지정한 다섯 장만 지정 순서로 반환하며 모든 문구의 라우팅은 차단·오라우팅 없이 고정한다.
- 프리워밍 문구는 카탈로그와 문자열 일치한다.
- `/chat/cards`는 조건 enum만 반환한다.
- 계좌 비교 카드 응답에는 IRP 일반 위험자산 70% 원칙과 검증 출처가 포함된다.
- 추천 카드에는 노란색 아이콘이 없고 클릭·터치 시 카드의 `message`를 그대로 전송한다.
- 후속 카드는 3개 이하고 NEWS 지역 전환은 반대 지역이다.
- 기존 단독 시각화는 동일 결과이며 복수 시각화가 가능하다.
- 신규 필드는 빈 배열로 직렬화되고 SSE `response`의 기존 필드는 유지된다.
- 프론트의 알 수 없는 조건 태그는 숨긴다.
