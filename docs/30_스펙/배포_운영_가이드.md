> 최종 확인: 2026-07-24 KST
> 적용 범위: Vercel 프론트엔드 → Render FastAPI → Supabase
> 상태: **환경변수 복구·재배포·원격 골든패스 E2E 대기**

이 문서는 원격 배포 주소, 환경변수 계약, 배포 순서와 검증 절차의 정본이다. API 키와 DB 연결 문자열 등 비밀값은 이 문서에 기록하지 않는다.

Vercel의 별도 프로젝트 `kda-securities`는 저장소 루트 `.`을 Root Directory로 사용해 `vite: command not found`로 실패한 중복 설정이다. 운영 프론트는 `kda-securities-lzix` 하나로 통일하고, 중복 프로젝트는 Git 연결을 해제하거나 삭제한다.

## 2. Vercel 설정

### 프로젝트 빌드

| 항목 | 값 |
|---|---|
| Project | `kda-securities-lzix` |
| Root Directory | `frontend` |
| Framework Preset | `Vite` |
| Install Command | `npm install` |
| Build Command | `npm run build` |
| Output Directory | `dist` |

### Production·Preview 환경변수

```text
VITE_API_BASE_URL=https://pension-copilot-api.onrender.com
VITE_SUPABASE_URL=<Supabase project URL>
VITE_SUPABASE_PUBLISHABLE_KEY=<Supabase publishable key>
```

- `VITE_API_BASE_URL`은 비어 있으면 안 되며 후행 `/`는 생략한다.
- Vite의 `VITE_` 변수는 build 시 번들에 들어가므로 값 변경 뒤 Vercel을 반드시 다시 배포한다.
- `SUPABASE_SECRET_KEY`, `DATABASE_URL` 등 서버 비밀값은 Vercel에 넣지 않는다.
- Production을 외부에 공유하려면 Vercel Deployment Protection이 로그인 없이 접근 가능한 정책인지 확인한다.

## 3. Render 설정

`render.yaml`의 서비스명은 `pension-copilot-api`, health check는 `/health`다. Render 대시보드에는 서버 비밀값과 함께 다음 CORS 값을 설정한다.

```text
CORS_ORIGINS=["https://kda-securities-lzix-kda4.vercel.app","https://kda-securities-lzix-zeta.vercel.app"]
```

- 사용자가 실제 접속하는 모든 안정 alias를 JSON 배열에 정확히 넣는다.
- 임시 Preview URL은 매번 바뀌므로 원격 골든패스는 위 Production alias에서 검증한다.
- CORS 변경 뒤 Render를 재배포해야 한다.
- 무료 인스턴스는 유휴 뒤 첫 요청이 느릴 수 있다. 2026-07-24 실측에서는 첫 health/API 확인에 약 54초가 걸렸다.

## 4. 2026-07-24 장애 실측

아래는 문서 작성 시점의 실제 상태이며 복구 완료 표시가 아니다.

1. Render `/health`와 `/accounts/link-options`는 각각 HTTP 200을 반환했다.
2. Vercel `kda-securities-lzix` Production의 `VITE_API_BASE_URL`은 키만 있고 값이 비어 있었다.
3. 빈 문자열은 프론트 API 클라이언트의 nullish fallback을 사용하지 않으므로 `/accounts/link-options`를 Vercel 자기 origin으로 요청하게 된다.
4. Render에서 두 Production alias의 CORS preflight를 실행한 결과 HTTP 400이었고 `access-control-allow-origin` 헤더가 없었다.
5. Vercel `kda-securities`는 Root Directory 오류로 `vite: command not found`가 발생했다.
6. `kda-securities-lzix`의 최초 Production build는 성공했지만 이후 Git 배포가 `blocked` 상태로 관측됐다. 차단 원인을 해소하고 최신 `main` 재배포 성공을 별도로 확인해야 한다.

따라서 현재 원격 배포 상태는 **백엔드 정상 / 프론트 환경변수·CORS·최신 배포 복구 대기**다.

## 5. 복구·배포 순서

1. Vercel 운영 프로젝트를 `kda-securities-lzix`로 통일한다.
2. Vercel Production·Preview의 `VITE_API_BASE_URL`을 Render 고정 주소로 설정한다.
3. Render `CORS_ORIGINS`에 두 Production alias를 설정한다.
4. Render를 먼저 재배포하고 `/health`와 CORS preflight를 확인한다.
5. Vercel을 최신 `main`으로 재배포한다.
6. 브라우저에서 로그인 → 계좌 정보 확인 → 투자성향 → 홈 → 챗봇 → 계산기 → 전략 → User Pick 순으로 원격 골든패스를 검증한다.

## 6. 검증 명령

### Render 상태

```powershell
curl.exe -sS https://pension-copilot-api.onrender.com/health
curl.exe -sS https://pension-copilot-api.onrender.com/accounts/link-options
```

둘 다 HTTP 200이어야 한다.

### CORS preflight

```powershell
curl.exe -sS -o NUL -D - -X OPTIONS `
  https://pension-copilot-api.onrender.com/accounts/link-options `
  -H "Origin: https://kda-securities-lzix-zeta.vercel.app" `
  -H "Access-Control-Request-Method: GET" `
  -H "Access-Control-Request-Headers: content-type"
```

응답에 아래 헤더가 있어야 한다.

```text
access-control-allow-origin: https://kda-securities-lzix-zeta.vercel.app
```

### 프론트 확인

- 공유 주소가 Vercel 로그인 화면으로 이동하지 않는다.
- 계좌 정보 화면에 재시도 오류가 나타나지 않는다.
- 브라우저 Network에서 `/accounts/link-options` 요청 host가 `pension-copilot-api.onrender.com`이다.
- API·SSE 요청에 CORS 오류가 없다.
