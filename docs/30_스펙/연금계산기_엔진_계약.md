## 1. 목적과 범위

모바일 화면에서 **납입 나이·금액을 게이지 바로 드래그**하면 즉시 재계산되는 연금 계산기의 백엔드 계약이다.
벤치마크는 시그널 연금계산기 "예상 연금" 탭(`참고파일/시그널 연금계산기.png`)이며, 다음 세 가지를 산출한다.

1. 납입 종료 시점의 **총액 · 총 납입원금 · 총 수익금액**
2. **연차별 누적 원금/수익 시계열** (스택 막대그래프용)
3. **은퇴 후 월 수령액** (세전·세후)

여기에 벤치마크에 없는 요소를 하나 더한다.

4. **투자성향 기반 전략 목록** — 기대수익률 내림차순, 성향 내/밖 구분

### 1.1 범위 밖 (명시적 제외)

| 항목 | 제외 사유 |
|---|---|
| 이연퇴직소득(퇴직급여) 재원 과세 | 수령연차별 70/60/50% 비율은 문서에 있으나, 기준이 되는 **퇴직소득세 본 계산(근속연수공제·환산급여공제 누진표)의 근거가 저장소에 없다.** 임의 구현은 환각 금지 위반. 별도 PR로 분리한다. 응답에 `deferred_severance_excluded: true`를 실어 명시한다. |
| 종합과세 vs 분리과세 유불리 비교 | 사용자의 다른 종합소득을 알아야 판단 가능하므로 계산기 입력으로 부적합. 연 1,500만원 초과 시 **16.5% 분리과세 선택**을 고정 가정하고 경고를 붙인다. |
| 국민연금 합산 | 별도 단계. |
| 실질가치(물가 디플레이터) | 기존 `simulate_accumulation`에는 있으나 벤치마크·이번 요구에 없다. 향후 확장 지점으로만 기록. |
| 개별 ETF 종목 선택 | 계산기는 **자산 버킷 배분 수준**까지만 다룬다. 종목 단위는 `educational_portfolio.py` 담당. |

## 2. 기존 코드와의 관계

**`simulation.py`는 수정하지 않는다.** `simulate_accumulation()`의 응답 수치가 바뀌면 챗봇 툴(`chat/tools.py:50`)과 기존 테스트 계약이 함께 흔들리기 때문이다. 신규 모듈이 아래를 **재사용만** 한다.

| 재사용 대상 | 용도 |
|---|---|
| `assumptions.ALLOCATION_MATRIX` / `PENSION_SAVINGS_EXTENSION` | 연령대·성향별 자산배분 |
| `assumptions.net_annual_return_percent()` | 비용 차감 후 명목 가정수익률(전정밀도) |
| `assumptions.age_band()` | 연령 구간 판정 |
| `assumptions.ASSUMPTION_VERSION` / `ASSUMPTION_SOURCE` | 가정 버전·출처 칩 |
| `models.RiskProfile` / `AccountType` / `AssumptionScenario` / `AllocationWeights` | 공용 타입 |
| `educational_portfolio.PROFILE_POLICY[*]["strategy"]` | 전략 라벨 문자열 |

**CMA 경로(`planning_return.py` / `calculate_portfolio_planning_return()`)는 사용하지 않는다.** 개별 ETF 유니버스 조회가 필요해 드래그 응답성(목표 p95 < 50ms)에 맞지 않고, 계산기가 필요한 정밀도는 버킷 배분 수준으로 충분하다.

## 3. 가정 변경 — `AT_OR_ABOVE_55` 배분 신설

### 3.1 배경

현재 `ALLOCATION_MATRIX`는 `AGE_20S`~`AGE_50_54`만 정의하고 `AT_OR_ABOVE_55`가 **의도적으로 비어 있다**(`assumptions.py:59-60`). 기존 엔진이 55세 고정 종료였기 때문이다.
벤치마크는 "지금부터 **65세**까지 납입"이므로 55~70세 구간의 배분 가정이 필요하다.

### 3.2 결정 (2026-07-20, 이재용 승인)

**`AGE_50_54` 배분을 `AT_OR_ABOVE_55`에 그대로 연장한다.**

| 성향 | 성장/안전/현금 |
|---|---|
| 안정형 STABLE | 0 / 50 / 50 |
| 안정추구형 STABLE_SEEKING | 0 / 75 / 25 |
| 위험중립형 RISK_NEUTRAL | 20 / 70 / 10 |
| 적극투자형 ACTIVE | 35 / 60 / 5 |
| 공격투자형 AGGRESSIVE | 50 / 50 / 0 |

연장을 택한 이유: 50대 초반 배분이 이미 "수익률보다 직전 손실 방어"를 반영한 가장 보수적인 구간이므로, 은퇴 임박 구간에 그대로 적용해도 글라이드패스 방향(위험 축소)과 모순되지 않는다. 55세 이상 전용 배분을 새로 정의하는 안은 순수 신규 가정이라 근거 문서 개정 부담이 커서 보류했다.

### 3.3 구현 시 지켜야 할 것

- `ASSUMPTION_VERSION`을 `2026-07-15.1` → **`2026-07-20.1`**로 올리고 `ASSUMPTION_SOURCE.as_of`를 `2026-07-20`으로 갱신한다.
- `assumptions.py:59-60`의 "intentionally absent" 주석을 결정 근거 주석으로 교체한다.
- `PENSION_SAVINGS_EXTENSION`에는 `AT_OR_ABOVE_55` 행을 **추가하지 않는다** (20·30대 공격형 전용 확장이며 은퇴 임박 구간에 확대할 근거가 없다).
- 이 변경은 `engine/CLAUDE.md`가 정의한 **계획가정 변경**에 해당한다 → 김태형 오너 합의 후 머지. 변경 전후 교육용 포트폴리오 120개 결과가 **0건 차이**임을 테스트로 증명한다.
- `simulate_accumulation()`은 55세 이상에서 조기 반환하므로 이 행을 참조하지 않는다. 응답 무변경을 회귀 테스트로 고정한다.

### 3.4 함께 갱신해야 하는 기존 테스트

`tests/test_assumptions.py::test_matrix_covers_modeled_bands_and_all_profiles`가
`ALLOCATION_MATRIX`의 키 집합을 **정확히 4개 구간**으로 고정하고 있다. 55세 행을 추가하면
이 단언은 반드시 실패한다 — 의도된 실패이며, 새 가정을 검증하는 형태로 바꿔야 한다.

```python
assert set(ALLOCATION_MATRIX) == {AGE_20S, AGE_30S, AGE_40S, AGE_50_54}
```

**갱신 방향** (단순히 통과시키지 말 것):

1. 기대 집합에 `AgeBand.AT_OR_ABOVE_55`를 추가한다.
2. `AT_OR_ABOVE_55` 배분이 `AGE_50_54`와 **원소 단위로 동일**함을 단언하는 테스트를 새로
   추가한다. §3.2의 "연장" 결정이 코드에서 지켜지는지를 고정하기 위함이다.
3. `PENSION_SAVINGS_EXTENSION`에 `AT_OR_ABOVE_55` 키가 **없음**을 단언하는 테스트를 추가한다.
4. `ASSUMPTION_VERSION == "2026-07-20.1"`을 단언하는 테스트가 있으면 함께 갱신한다.

다른 기존 테스트가 가정 변경으로 깨지면 **동일하게 처리한다 — 단언을 삭제하거나 느슨하게
만들어 통과시키지 말고, 새 가정을 검증하는 형태로 바꾸고 그 사유를 PR 본문에 적는다.**

### 3.5 기본 물가가정 출처 정책 추가 (2026-07-20)

김태형 엔진 오너 승인으로 `ASSUMPTION_VERSION`을 `2026-07-20.2`로 올린다. 수익률·배분
숫자는 변경하지 않고, 실질가치 환산의 기본 물가가정 `2.0%`에 한국은행 물가안정목표 공식
출처 칩을 연결한다. 사용자가 기본값이 아닌 물가가정을 입력하면 해당 공식 목표 출처 칩은
붙이지 않는다. 최신 CPI 관측값은 기본 물가가정을 자동 대체하지 않는다.

## 4. API 계약

### 4.1 엔드포인트

```
POST /engine/pension-calculator
```

인증 없음(기존 `/engine/*` 관행과 동일). 순수 산술이므로 DB·네트워크·LLM 호출 없음.

### 4.1.1 현재 보유 ETF CMA 경로 (계약 변경, 2026-07-22)

```
POST /engine/pension-calculator/portfolio-cma
```

`calculator: PensionCalculatorInput`과 `current_holdings: [{ isu_code, amount_krw }]`를 받는다. API 경계에서 계좌별 ETF 유니버스를 읽고, 보유 평가금액 비중으로 ETF별 CMA 매핑·불확실성 할인·검증된 실부담비용을 가중 합산한 뒤 계산기에 주입한다. 규칙 엔진 자체는 DB를 읽지 않는다.

계산기 응답의 가정 버전은 `2026-07-22.1`이며, 기존 버킷 가정 계산기와 결과를 섞지 않는다.

- 기준 시나리오(`base`)만 허용한다. 별도의 낙관 수익률 가산은 정의하지 않는다.
- 비용 데이터가 없는 ETF는 0% 비용으로 대체하지 않고 422로 거절한다.
- 결과의 `planning_return.components`에는 ETF별 CMA 코드·비용·할인·출처가 남는다.
- 현재 보유 ETF의 비중이 적립·수령 기간 동안 고정된다는 교육용 가정이며, 미래 수익률 예측이 아니다.

## 5. 계산 규칙

### 5.1 적립 단계

기존 `simulation.py`의 규약을 그대로 따른다 — 임의 변경 금지.

- **월말 납입**, 월수익률 `i = (1 + r/100)^(1/12) - 1`
- `Decimal` + `localcontext(prec=50)` 결정론 계산
- 연령 구간(`AgeBand`)이 바뀌는 시점에 배분·수익률을 **재계산**한다. 예: 25세 위험중립형의 5.2%를 30년 고정 적용하지 않고 30대·40대·50대 배분으로 순차 하향한다.
- 배분 선택: `ALLOCATION_MATRIX[age_band][strategy_profile]`. 단 `account_type == pension_savings`이고 `PENSION_SAVINGS_EXTENSION`에 해당 셀이 있으면 그것을 우선한다.
- **DC·IRP 70% 한도**: 선택된 배분의 `growth_percent`가 70을 초과하면 계산을 진행하지 않고 오류로 처리한다(현재 매트릭스에는 위반 셀이 없으나 방어적으로 강제).

**연차별 스냅샷** — 벤치마크 그래프용 신규 산출물.

- `year_index`는 1부터 시작하고 납입 연차를 뜻한다(벤치마크 x축 "1년 … 39년").
- 각 `year_index` 말(12개월 경과 시점)의 잔액을 기록한다.
- `cumulative_principal_krw = current_balance_krw + monthly_contribution_krw × year_index × 12`
- `cumulative_gain_krw = balance_krw - cumulative_principal_krw`
- **항등식**: 모든 연차에서 `cumulative_principal + cumulative_gain == balance` (테스트로 고정)
- 마지막 원소의 `balance_krw`가 `headline.total_krw`와 일치해야 한다.

### 5.2 전략 목록

전략은 새로 정의하지 않고 **기존 5개 성향 정책을 그대로 잇는다**.

| `strategy_id` | 성향 | 위험 순위 |
|---|---|---|
| `capital_preservation_core` | 안정형 | 1 |
| `defensive_diversified_core` | 안정추구형 | 2 |
| `balanced_core_satellite` | 위험중립형 | 3 |
| `growth_core_satellite` | 적극투자형 | 4 |
| `barbell_growth_tactical` | 공격투자형 | 5 |

- 각 전략의 기대수익률 = `net_annual_return_percent(ALLOCATION_MATRIX[age_band(current_age)][profile], scenario)`
- 정렬: `net_annual_return_percent` **내림차순**. 동률이면 위험 순위 오름차순.
- `within_profile = 전략 위험순위 <= 사용자 성향 위험순위`
  사용자 성향보다 **보수적인** 전략은 성향 밖이 아니다. 더 **공격적인** 전략만 성향 밖으로 본다.
- `default_visible = within_profile인 것 중 수익률 상위 최대 3개`

> **⚠️ UI 함의(프론트 협의 필요)**: 이 규칙에서 안정형 사용자는 `default_visible`이 **1개**뿐이고, 안정추구형은 2개다. "기본 버튼 3개"를 항상 채우려면 성향 밖 전략을 기본 노출해야 하는데 이는 CLAUDE.md의 *"성향 밖 상품 제안 금지"* 위반이다. 따라서 **기본 노출 개수는 최대 3개이되 성향에 따라 줄어든다**로 확정한다. 나머지는 "더보기"에서 `within_profile: false` 배지·위험 경고와 함께 노출한다.

### 5.3 수령 단계 — 월 수령액

- 수령 개시 나이 = `contribution_end_age` (요청 검증에서 55 이상 보장)
- 수령 기간 중에도 잔액은 `AT_OR_ABOVE_55` 배분의 수익률로 운용된다고 가정한다.
- 월수령액(세전) = 연금현가 공식

  ```text
  n = payout_years × 12
  i = 수령기 월수익률
  월수령액 = balance × i / (1 - (1 + i)^(-n))
  ```

  `i == 0`인 경우(이론상 발생하지 않으나 방어) `balance / n`으로 처리한다.
- `annual_payout_krw = 월수령액 × 12`

### 5.4 수령 단계 — 과세

근거: `연금계좌세액공제 및 과세방법.md` §5.

**연령별 원천징수세율(지방소득세 포함)**

| 수령 당시 나이 | 세율 |
|---|---:|
| 70세 미만 | 5.5% |
| 70세 이상 80세 미만 | 4.4% |
| 80세 이상 | 3.3% |

- 수령 **연차마다 나이를 다시 계산**해 해당 세율을 적용한다. 수령 기간이 길면 세율이 단계적으로 낮아진다.
- `withholding_rate_percent_by_year`에 연차별 적용 세율을 담는다.
- `effective_rate_percent = 총 세액 / 총 수령액 × 100`
- `headline.monthly_payout_after_tax_krw`는 **첫 수령 연차 기준** 세후 금액이다(벤치마크가 단일 숫자를 보여주므로). 연차별 변동은 `withholding_rate_percent_by_year`로 확인 가능하다.

**연 1,500만원 기준**

- `annual_payout_krw > 15,000,000`이면 `exceeds_annual_15m_threshold = true`
- 이 경우 **전액에 16.5% 분리과세 선택**을 가정해 세후액을 계산한다.
- 경고 추가: 종합과세가 유리할 수 있으며 실제 판단에는 다른 종합소득이 필요하다는 안내.

**연금수령한도**

```text
연금수령한도 = 과세기간 개시일 현재 평가액 ÷ (11 - 연금수령연차) × 120%
```

- 연차 1~10에 대해 계산한다. 11년차 이상은 한도를 적용하지 않는다.
- 어떤 연차의 `annual_payout_krw`가 한도를 초과하면 초과 연차를 `warnings`에 기록한다(초과분은 연금외수령으로 보아 기타소득 16.5% 과세 대상).
- `payout_years < 10`이면 초기 연차에서 한도 초과가 발생하기 쉬우므로 특히 검증한다.

**항상 붙는 가정 경고**

- 가입일 입력이 없으므로 **가입 5년 경과 요건 충족**을 가정한다.
- 이연퇴직소득 재원은 계산에서 제외됐다.
- 세율·한도는 2026년 기준이며 실제 과세는 개인 상황에 따라 달라진다.
