# 챗봇 테스트 가이드

> 연금가이드 챗봇(`/chat/demo`)을 자동 테스트·API·화면 3단계로 검증하는 절차.
> 대상 코드: `backend/app/chat/`(서비스·내레이터) · `backend/app/api/chat.py`(라우터) · `frontend/src/pages/GuidePage.tsx`(화면)
> 최종 검증: 2026-07-15 (원격 Supabase 실데이터 연동 상태에서 전 항목 통과)

## 0. 사전 준비

```bash
# 저장소 루트에서 (의존성은 uv가 자동 해결)
uv run pytest            # 백엔드 전체 테스트
cd frontend && npm install   # 화면 테스트 시 1회
```

`.env` 상태에 따라 챗봇 기능이 달라진다. **DB 없이도 핵심 기능은 동작한다.**

| .env 키 | 없을 때 | 있을 때 |
|---|---|---|
| (없음/기본) | 계좌 규칙 Q&A(로컬 문서 검색) + 목시나리오 진단(로컬 JSON) + 차단 응답 | — |
| `DATABASE_URL` | 공시·뉴스 질문이 "미지원/조건부" 안내 | FSS 공시 비교·최신 뉴스 답변 활성화 |
| `ANTHROPIC_API_KEY` | 검증 원문 그대로 답변(`narration_mode: deterministic`) | Claude(pydantic-ai)가 쉬운 말로 재서술(`claude_verified`) + 검토 과정(`narration_reasoning`) 반환, **새 숫자 만들면 자동으로 원문 롤백** |

## 1. 자동 테스트 (가장 빠른 확인)

```bash
uv run pytest tests/test_chat_mvp.py -v   # 챗봇만 16건
uv run pytest                              # 전체 (엔진·API 포함)
```

16건이 검증하는 것: 계좌 규칙 답변의 출처·수치 근거, 연금저축에 DC/IRP 한도 미적용, 목시나리오 엔진 실행·mock 경계 유지, 개별 상품 비교 차단, **미래 수익·주문 요청 차단**, 공시 답변이 저장소 숫자만 인용, fixture 폴백 금지, 뉴스 메타데이터·원문 링크, 출처 없는 숫자 거부, **내레이터의 새 숫자 감지·롤백**, 검토 과정(thinking 요약 우선·검토 노트 폴백·새 숫자 시 생략), FastAPI 골든패스. 내레이터 테스트는 pydantic-ai `FunctionModel` 오버라이드로 실 API 없이 돈다.

## 2. API 데모 테스트

### 2-1. 서버 실행

```bash
uv run uvicorn backend.app.main:app --reload
```

브라우저에서 http://127.0.0.1:8000 접속 → `/docs`(Swagger)로 자동 이동.
**Swagger UI에서 직접 호출하는 것이 가장 간편하다** (한글 인코딩 문제 없음).

### 2-2. 엔드포인트 3개

| 메서드·경로 | 역할 |
|---|---|
| `GET /chat/demo/capabilities` | 지원/조건부/미지원 질문 유형과 시나리오 코드 |
| `GET /chat/demo/scenarios` | 목계좌 시나리오 3종 목록 |
| `POST /chat/demo` | 질문 → 검증 답변 (`{"message": "...", "scenario_code": "..."(선택)}`) |

### 2-3. 질문 유형별 기대 결과

| 질문 예시 | intent | 확인 포인트 |
|---|---|---|
| "IRP와 연금저축의 위험자산 한도 차이를 알려줘" | `account_rule` | 70% 한도·연금저축 미적용, `sources`에 검증 지식 출처 |
| "DC형 방치 시나리오를 진단해줘" + `scenario_code: dc_dormant` | `mock_portfolio` | `data_mode: mock_scenario`, 엔진 실행 결과 포함 |
| "IRP 수익률 공시 좋은 회사 알려줘" | `provider_disclosure` | DB 필요. FSS 실공시 수익률 인용, 출처=금감원 |
| "연금 뉴스 알려줘" | `news` | DB 필요. NAVER 메타데이터·원문 링크 |
| "내년 예상수익률을 알려줘" | `out_of_scope` | **차단**: `data_mode: blocked`, 미래 예측 거부 문구 |

시나리오 코드 3종: `dc_dormant`(DC형 방치) · `tax_contribution_uninvested`(세액공제 후 미운용) · `overlap_risk_concentration`(중복·위험 편중).

### 2-4. curl로 테스트할 때 — Windows 한글 주의 ⚠️

PowerShell·Git Bash에서 한글을 `-d '...'`로 넘기면 cp949로 깨져서
`{"detail":"There was an error parsing the body"}`가 나온다(서버 버그 아님).
**UTF-8 파일로 저장 후 `--data-binary`를 쓸 것:**

```bash
# 질문을 UTF-8 파일로 저장 (편집기에서 UTF-8로 저장해도 됨)
printf '{"message":"IRP와 연금저축의 위험자산 한도 차이를 알려줘"}' > q.json

curl -s -X POST http://127.0.0.1:8000/chat/demo \
  -H "Content-Type: application/json" --data-binary @q.json
```

## 3. 화면(UI) 테스트

```bash
# 터미널 1 — 백엔드
uv run uvicorn backend.app.main:app --reload
# 터미널 2 — 프론트
cd frontend && npm run dev    # http://localhost:5173
```

**연금가이드 탭**에서 확인할 것:

1. 사이드바 하단 연결 상태가 "데모 API 연결됨"인지 (좌상단 햄버거 메뉴로 열기)
2. 추천 프롬프트 4개 클릭 → 각각 위 표의 intent대로 응답하는지
3. 사이드바에서 시나리오 선택 → "진단해줘" 질문 시 해당 목계좌로 진단되는지
4. 답변 카드의 **출처 N개** 토글 → 출처 칩(검증 지식/공식 공시/목데이터/뉴스 메타데이터 경계 라벨) 표시
5. 수치 근거 카드·"확인할 점"(한계 고지) 표시
6. "내년 예상수익률" 질문 → 차단 응답 확인

## 4. Claude 내레이터 검증 (선택)

`.env`에 `ANTHROPIC_API_KEY`를 넣고 서버 재시작 후 같은 질문을 보내면:

- 응답의 `narration_mode`가 `claude_verified`로 바뀌고 문장이 쉬운 말로 재서술됨
- `narration_reasoning`에 검토 과정이 담김(모델이 실제 생각한 경우 thinking 요약,
  아니면 검토 노트) — 화면에서는 답변 아래 **"AI가 검토한 과정"** 접이식 박스로 표시
- **숫자·단위는 검증 원문과 동일해야 함** — Claude가 새 숫자를 만들면 서비스가
  자동으로 원문으로 되돌리고 `limitations`에 "새로운 숫자를 감지해 …되돌렸습니다"가 추가됨.
  검토 과정에서만 새 숫자가 나오면 본문은 유지하고 검토 과정만 생략됨
- API 호출 실패 시에도 검증 원문으로 폴백 (답변이 끊기지 않음)
- 내부 구현은 pydantic-ai Agent(구조화 출력) — 향후 챗봇 도구 확장도 같은 Agent에 등록

## 5. 문제 해결

| 증상 | 원인·해결 |
|---|---|
| `There was an error parsing the body` | 한글 인코딩 깨짐 → §2-4의 UTF-8 파일 방식 사용 |
| 공시·뉴스 질문이 "조건부/미지원" 답변 | `DATABASE_URL` 미설정 또는 공시 미적재 → `uv run python -m backend.app.ingestion.fss`로 적재 |
| 프론트 연결 배지 "API 연결 필요" | 백엔드 미실행 또는 `frontend/.env`의 `VITE_API_BASE_URL` 불일치 (기본 `http://127.0.0.1:8000`) |
| CORS 오류 | `.env`의 `CORS_ORIGINS`에 프론트 주소 포함 여부 확인 |
