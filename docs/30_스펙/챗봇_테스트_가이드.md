# 챗봇 테스트 가이드

> 연금가이드 챗봇(인증 SSE `/chat/stream`)을 자동 테스트·API·화면 3단계로 검증하는 절차.
> 대상 코드: `backend/app/chat/`(오케스트레이터·인텐트 핸들러·내레이터) · `backend/app/api/chat.py`(SSE 라우터) · `frontend/src/hooks/useChatStream.ts`·`frontend/src/pages/GuidePage.tsx`(화면 조립)
> 최종 검증: 2026-07-21 (PR #106 화면 분리·PR #108 SSE 오류 하드닝·PR #120 뉴스 UX·PR #122 뉴스 구간 backfill 반영)

## 0. 사전 준비

```bash
# 저장소 루트에서 (의존성은 uv가 자동 해결)
uv run pytest            # 백엔드 전체 테스트
cd frontend && npm install   # 화면 테스트 시 1회
```

`.env` 상태에 따라 챗봇 기능이 달라진다. **DB 없이도 핵심 기능은 동작한다.**

| .env 키               | 없을 때                                                                | 있을 때                                                                                                                                            |
| --------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| (없음/기본)           | 계좌 규칙 Q&A(로컬 문서 검색) + 목시나리오 진단(로컬 JSON) + 차단 응답 | —                                                                                                                                                 |
| `DATABASE_URL`      | 공시·뉴스 질문이 "미지원/조건부" 안내                                 | FSS 공시 비교·최신 뉴스 답변 활성화                                                                                                               |
| `ANTHROPIC_API_KEY` | 새 뉴스 요약 생성 불가, 일반 답변은 결정론 모드                         | 수집 워커의 뉴스 원문 3줄 요약 + 검증 답변의 선택적 Claude 재서술 활성화. 뉴스 답변 자체는 저장 요약을 결정론적으로 조립                                 |
| `ANTHROPIC_MODEL` | 기본값 `claude-haiku-4-5` 사용(현재 기본, 재검토될 수 있음) | 내레이터 모델 지정. Haiku 계열은 thinking 미지원이라 `narration_reasoning`이 거의 항상 비어 있고, 비Haiku 모델(예: Sonnet)로 바꾸면 adaptive thinking이 켜져 검토 과정이 채워진다 |
| `NEWS_SUMMARY_MODEL`, `NEWS_SUMMARY_PROMPT_VERSION` | 기본값 사용 | 뉴스 요약 재현성을 위한 모델·프롬프트 버전 지정 |

## 2. API 테스트

### 2-1. 서버 실행

```bash
uv run uvicorn backend.app.main:app --reload
```

### 2-3. SSE 응답 계약

성공 스트림은 `phase`를 하나 이상 보낸 뒤 결정론 답변 전체를 `answer_delta`로 보낸다. Claude 내레이션이 검증을 통과한 경우에만 `narration_update`가 한 번 더 오며, 마지막 `response`에는 완전한 `ChatResponse`와 인증 경로의 저장 ID·멱등성 재생 여부가 담긴다. 저장소·손상된 저장 응답 등 스트림 진행 중 오류는 `error` 이벤트로 수신하며, 이때 `response`는 오지 않는다.

### 2-5. 연금세액 Tool 테스트 질문 3개

아래 질문은 **연금세액 선택 입력 패널을 작성하지 않고 질문 그대로 전송**한다. 서버의 제한된 슬롯 추출기가 계좌별 금액·당해연도 납입액·소득 기준·인출 사유만 구조화하고, 실제 계산은 규칙 엔진 Tool이 수행해야 한다. 입력 패널은 자연어에 필요한 값이 없을 때만 보완 수단으로 사용한다.

#### 1. 세액공제 한도 검증

- 올해 연금저축에 700만 원, IRP에 400만 원을 납입했고 총급여는 5,000만 원이야. 세액공제 대상 금액과 예상 세액공제액을 알려줘.
- 자동 인식: 연금저축 당해연도 납입액 700만 원, IRP 당해연도 납입액 400만 원, 소득 기준 `근로소득 총급여`·5,000만 원. 세액공제 계산에는 계좌 잔액을 요구하지 않아야 한다.
- 기대 결과: 연금저축 600만 원과 IRP 300만 원, 합계 900만 원이 세액공제 대상이며 16.5% 표시율 기준 예상 세액공제액은 148만 5,000원

#### 2. 8,000만 원 최대 과세 예시 검증

> 연금저축 잔액이 3,000만 원이고 IRP 잔액이 5,000만 원이야. 올해 납입액은 없고 IRP 퇴직금 이전분은 몰라. 두 계좌를 일반 중도해지하면 최대로 얼마가 과세될 수 있어?

- 자동 인식: 연금저축 잔액 3,000만 원·당해연도 납입액 0원, IRP 잔액 5,000만 원·당해연도 납입액 0원, 인출 사유 `일반 중도해지`, IRP 퇴직금 이전분 `모름`
- 기대 결과: 8,000만 원 전부를 16.5% 적용 대상으로 가정한 최대 기타소득 원천징수 간이 추정액 1,320만 원과 이연퇴직소득 미확인 한계 표시

#### 3. 예외 사유 계산 차단 검증

> 의료비 때문에 연금저축과 IRP를 중도인출하려고 해. 부득이한 인출로 보고 16.5% 세금을 계산해줘.

- 자동 인식: 의료비·부득이한 인출 사유. 계산 차단에는 계좌 잔액과 납입액을 요구하지 않아야 한다.
- 기대 결과: 16.5% 예상세액을 계산하지 않고 부득이한 사유의 요건과 과세방식 확인이 필요하다고 안내하며 결과 상태는 `requires_review`

세 질문의 답변은 모두 다음 문장을 **맨 마지막 줄**에 표시해야 한다.

> 자세한 내용은 금융기관을 통한 확인 및 세무전문가의 상담이 필요합니다.

### 2-6. curl로 테스트할 때 — Windows 한글 주의 ⚠️

PowerShell·Git Bash에서 한글을 `-d '...'`로 넘기면 cp949로 깨져서
`{"detail":"There was an error parsing the body"}`가 나온다(서버 버그 아님).
**UTF-8 파일로 저장 후 `--data-binary`를 쓸 것:**

```bash
# 질문을 UTF-8 파일로 저장 (편집기에서 UTF-8로 저장해도 됨)
printf '{"message":"IRP와 연금저축의 위험자산 한도 차이를 알려줘"}' > q.json

curl -Ns -X POST http://127.0.0.1:8000/chat/stream \
  -H "Authorization: Bearer <access-token>" \
  -H "Idempotency-Key: 11111111-1111-4111-8111-111111111111" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" --data-binary @q.json
```

## 3. 화면(UI) 테스트

### 3-1. 서비스 실행 — `dev.bat` 더블클릭

루트 `.env`에 비어 있지 않은 `DATABASE_URL`을 설정한 뒤 저장소 루트의
**`dev.bat`을 더블클릭**하면 백엔드·프론트가 함께 뜬다. API와 화면 준비가 끝나면
브라우저가 연금가이드 화면(`http://127.0.0.1:5173/#guide`)으로 열린다. 로그는
`[api]`·`[web]` 접두어로 한 창에 합쳐지고, **창을 닫거나 Ctrl+C**하면 둘 다
정리된다. `frontend/node_modules`가 없으면 `npm install`도 한 번 실행한다.

> `dev.bat`은 비인증 상태 확인 경로인 `/health`와 Vite가 응답할 때까지 최대 120초
> 기다린다. Supabase 설정이 있고 로그인 세션이 없으면 연금가이드 대신 로그인
> 화면이 먼저 보일 수 있다. BGE-M3 선택 의존성을 설치한 환경은 임베더 준비 때문에
> 시작이 더 오래 걸릴 수 있다.

터미널에서 직접 띄우거나 두 서버를 따로 재시작하려면 기존 방식도 그대로 쓸 수 있다.

```powershell
# 터미널 1 — 프로젝트 루트에서 백엔드
uv run uvicorn backend.app.main:app --reload

# 터미널 2 — 프론트엔드
Set-Location frontend
npm run dev
```

두 주소는 `127.0.0.1`로 통일한다. `localhost`와 혼용하면 Supabase 로그인 저장
공간이 달라져 같은 브라우저에서도 로그인 상태가 다르게 보일 수 있다.

### 3-2. 확인 항목

**연금가이드 탭**에서 확인할 것:

1. 사이드바 하단 연결 상태가 "데모 API 연결됨"인지 (좌상단 햄버거 메뉴로 열기)
2. 추천 프롬프트 5개 클릭 → 각각 위 표의 intent대로 응답하는지
3. 사이드바에서 시나리오 선택 → "진단해줘" 질문 시 해당 목계좌로 진단되는지
4. 답변 카드의 **출처 N개** 토글 → 출처 칩(검증 지식/공식 공시/목데이터/뉴스 메타데이터 경계 라벨) 표시
5. 수치 근거 카드·"확인할 점"(한계 고지) 표시
6. §2-5의 세 질문을 입력 패널 없이 그대로 보내 자연어 값이 Tool 입력으로 구조화되는지 확인하고, 값이 부족한 별도 질문에서만 선택 입력 패널 안내가 나오는지
7. "내년 예상수익률" 질문 → 차단 응답 확인

## 4. Claude 내레이터 검증 (선택)

`.env`에 `ANTHROPIC_API_KEY`를 넣고 서버 재시작 후 같은 질문을 보내면:

- 응답의 `narration_mode`가 `claude_verified`로 바뀌고 문장이 쉬운 말로 재서술됨
- `narration_reasoning`에 검토 과정이 담길 수 있음(모델이 thinking을 낸 경우만) —
  화면에서는 답변 아래 **"AI가 검토한 과정"** 접이식 박스로 표시. **기본 모델
  `claude-haiku-4-5`는 thinking을 지원하지 않아 이 필드가 거의 항상 `None`이다**
  (`narrator.py`). 검토 과정을 실제로 확인하려면 `ANTHROPIC_MODEL`을 Sonnet 등
  비Haiku 모델로 바꿔야 한다 — 빈 값은 버그가 아니라 현재 기본 모델의 정상 동작
- **숫자·단위는 검증 원문과 동일해야 함** — Claude가 새 숫자를 만들면 서비스가
  자동으로 원문으로 되돌리고 `limitations`에 "새로운 숫자를 감지해 …되돌렸습니다"가 추가됨.
  검토 과정에서만 새 숫자가 나오면 본문은 유지하고 검토 과정만 생략됨
- 같은 질문(정확히 같은 프롬프트)을 다시 보내면 검증 통과 내레이션은 서버 내
  LRU 캐시(최대 256건)에서 즉시 반환된다 — 재현 지연이 갑자기 짧아져도 API가
  스킵된 게 아니라 캐시 히트다. 폴백(가드 거부·오류) 응답은 캐시되지 않는다
- API 호출 실패 시에도 검증 원문으로 폴백 (답변이 끊기지 않음)
- 내부 구현은 pydantic-ai Agent(구조화 출력) — 향후 챗봇 도구 확장도 같은 Agent에 등록

## 5. 문제 해결

| 증상                                    | 원인·해결                                                                                          |
| --------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `There was an error parsing the body` | 한글 인코딩 깨짐 → §2-6의 UTF-8 파일 방식 사용                                                    |
| 서버 부팅에 ~10초 이상 걸림 | 정상 — 부팅 시 내레이터·임베딩 프리워밍(`warm_chat_dependencies`)이 콜드스타트 지연을 미리 흡수한다(실측 ~11.5초, 2026-07-18). 워밍업 실패는 경고만 남기고 첫 요청은 결정론 폴백으로 동작 |
| 공시·뉴스 질문이 "조건부/미지원" 답변  | `DATABASE_URL` 미설정 또는 공시 미적재 → `uv run python -m backend.app.ingestion.fss`로 적재   |
| 프론트 연결 배지 "API 연결 필요"        | 백엔드 미실행 또는 루트 `.env`의 `VITE_API_BASE_URL` 불일치 (기본 `http://127.0.0.1:8000`) |
| CORS 오류                               | `.env`의 `CORS_ORIGINS`에 프론트 주소 포함 여부 확인                                            |
