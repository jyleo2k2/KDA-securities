# ETF 테마 챗봇 계약

## 목적과 범위

챗봇이 ETF 테마 1~23을 설명하고, 사용자의 완료된 투자성향 설문과 보유 계좌 범위 안에서 교육용 ETF 비교 후보를 제시하며, 요청 시 한국투자증권 API 구성종목 비중을 근거로 답한다. 상품 선택·주문·미래 수익률 예측은 하지 않는다.

## 데이터 경계

| 데이터 | 단일 원본 | 답변 경계 |
|---|---|---|
| 테마 쉬운 설명·포함 분야·관찰 요인·비유·정의·장점·위험 | `data/reference/etf_theme_catalog.json` | 사용자 조사자료 기반 서비스 설명·공식 검증 대기 |
| 테마별 대표기업 3곳·쉬운 설명·선정 이유 | `data/reference/etf_theme_catalog.json` | 기업 공식 홈페이지 URL·기준일을 함께 보존한 교육용 예시 |
| 테마 질문 유형별 공식 검증 상태 | `etf_theme_content_reviews`, `etf_theme_content_evidence` | 카탈로그 버전·응답 payload SHA-256과 승인 지식 근거 연결 |
| 계좌별 ETF 적격성·비용·품질지표 | `data/cache/returns/{account}_etf_cost_return_*.json` | 규칙 엔진 산출물 |
| 구성종목·비중 | `data/cache/kis/etf_snapshot_YYYY-MM-DD.json` | 한국투자증권 API 기준일 스냅샷 |
| 테마 질문 의도와 응답 | `backend/app/chat/` | 결정론적 라우팅·근거 연결 |

테마 설명과 숫자 근거를 섞어 출처를 가장하지 않는다. 특히 구성종목 배열의 `etf_cnfg_issu_rlim`은 한국투자증권이 반환한 값을 그대로 Decimal로 정규화하고, 챗봇이 비중을 새로 추정하지 않는다.

### 조사자료 정규화 원칙

- 공유 대화의 `쉽게 말하면`, 포함 기업·분야, 가격 동인과 한 줄 비유는 테마별 `plain_summary`, `exposure_segments`, `performance_drivers`, `one_line_analogy`로 보존한다. 주의점은 `risks`, 서비스 분류 설명은 `definition`으로 관리한다.
- 대표기업은 테마마다 정확히 3곳을 `representative_companies`에 보존한다. 각 항목은 기업명, 테마에서의 역할, 초보자용 설명, 대표 사례로 고른 이유, 기업 공식 홈페이지 URL, 기준일을 포함한다.
- `performance_drivers`는 미래 수익률 예측이 아니라 사용자가 확인할 관찰 요인으로만 표시한다.
- 런타임은 `data/reference/etf_theme_catalog.json`만 읽는다. 공유 대화 원문이나 동일한 내용을 23개 Markdown 파일로 복제하지 않는다.
- 공통 체크리스트와 테마 간 중복 비교는 이 계약과 리서치 문서에서 관리하고, ETF 구성종목·비중은 정적 설명에 섞지 않는다.
- 공식 문서로 교차 검증되기 전에는 승인 RAG에 넣지 않는다. 검증된 문장만 별도 근거 문서와 `data/knowledge/approved_documents.json`을 통해 승격한다.

### 공식 검증 장부

- 답변 문구의 단일 원본은 계속 JSON 카탈로그다. DB에 같은 문구를 복제하지 않는다.
- 검토 단위는 23개 테마 × `overview`, `representative_companies`, `investment_considerations` 3종의 69개다.
- 각 검토 행은 실제 렌더링 필드의 정규화된 SHA-256을 저장한다. 카탈로그 문구가 바뀌어 해시가 달라지면 기존 승인을 재사용하지 않는다.
- `verified` 상태, 유효한 검토기한, `permitted` 승인 지식 문서, 활성 청크, 해당 문서의 `official_source_urls`에 등록된 URL을 모두 확인한 경우에만 공식 검증 완료로 취급한다.
- 검증 완료된 질문 유형에서는 공식 근거를 `verified_knowledge` 출처로 연결하고 `공식 문서 검증 전 초안` 한계만 제외한다. 미래 성과 비예측·대표기업 비추천 한계는 유지한다.

## 처리 흐름

1. 질문의 테마명·동의어 또는 `N번 테마`를 카탈로그에 매칭한다.
2. `OO 테마가 뭐야`, `OO 테마 알려줘` 같은 개요 요청이면 쉬운 정의, 무엇을 담는지, 한 줄 비유를 제공한다.
3. `OO 테마 대표 기업` 요청이면 카탈로그의 대표기업 3곳과 각 기업의 쉬운 설명·선정 이유를 제공한다.
4. `OO 테마에 투자할 때 고려할 점` 요청이면 기대할 수 있는 점 3개와 주의할 위험 3개를 제공한다.
5. 선택된 질문 유형의 카탈로그 payload 해시로 DB 검증 장부를 조회한다. 검증이 완료됐으면 공식 근거를 연결하고, 그렇지 않으면 초안 한계를 유지한다.
6. `ETF 대표 종목`, `구성종목`, `편입 비중` 요청은 대표기업 설명보다 우선해 KIS 구성종목 흐름으로 보낸다. 대표기업 예시와 실제 ETF 편입종목을 혼동하지 않는다.
7. ETF 후보 요청이면 완료된 설문과 계좌 유형을 요구한다.
8. 계좌별 적격 유니버스에서 테마를 다대다 분류하고, 성향별 목표 슬리브가 0보다 큰 상품만 남긴다.
9. 기존 품질점수로 후보를 정렬한다. 품질점수에는 보수·유동성·순자산·NAV 괴리·추적 품질·관측 깊이를 쓰며 과거 수익률은 넣지 않는다.
10. 구성종목 요청이면 최신 KIS 스냅샷의 상위 비중을 출처·기준일·숫자 근거와 함께 반환한다.

## 가드레일

- 안정형·안정추구형처럼 전술 슬리브 목표가 없는 성향에는 테마 ETF 후보를 제안하지 않는다.
- 질문 계좌가 설문 프로필의 계좌에 없으면 그 계좌 상품을 제안하지 않는다.
- DC형·IRP·연금저축의 적격 유니버스를 섞지 않는다.
- KIS 공개 시세 데이터만으로 연금계좌 적격성을 판단하지 않는다.
- 구성종목 배열이 비어 있으면 비중을 생성하거나 추정하지 않고 한계를 표시한다.
- 대표기업 3곳은 테마를 이해하기 위한 사례이며, 특정 ETF의 실제 편입종목이나 매수 추천으로 표현하지 않는다.
- 동일 ETF가 여러 테마에 속할 수 있다. 테마 일치 자체는 매수 추천이나 미래 성과 근거가 아니다.
- 답변에 표시한 모든 `%`와 `원` 값은 해당 섹션의 `NumericEvidence`와 `SourceEvidence`에 연결한다.

## 실패 시 동작

- 테마 카탈로그 없음: 테마 기능을 `unavailable`로 응답한다.
- 설문 없음: 테마 설명만 제공하고 후보는 제시하지 않는다.
- 계좌별 적격 유니버스 없음: 해당 계좌 후보를 생략하고 한계를 표시한다.
- KIS 스냅샷 없음: 후보 설명은 가능하지만 구성종목 비중은 표시하지 않는다.
- 검증 DB 미적용·연결 실패·검토기한 경과·해시 불일치·공식 URL 불일치: 테마 답변은 계속 제공하되 `공식 문서 검증 전 초안` 한계를 유지한다.
