# RAG 지식 코퍼스 관리체계 및 5종 확충 설계

## 목표

기존 승인 문서 5건이 주로 연금계좌 규칙에 집중된 문제를 보완한다. 한국거래소·고용노동부·국세청·금융위원회 공식 원문만 근거로 사용자 질문에 답할 검증 문서 5건을 추가하고, Git 매니페스트를 코퍼스 운영의 단일 승인 장부로 강화한다.

## 관리 방식

문서 원본은 도메인별 허용 루트인 `docs/20_리서치`, `docs/40_규제`에 둔다. RAG 전용 복사본은 만들지 않는다. `data/knowledge/approved_documents.json`에 등록된 문서만 적재하며, Git 이력이 문서 버전과 승인 변경 이력을 보존한다.

매니페스트 스키마를 v2로 올리고 각 문서에 다음 운영 메타데이터를 둔다.

- `document_id`: 경로가 바뀌어도 유지하는 영문 kebab-case 식별자
- `official_source_urls`: 승인 근거로 사용한 정부·공공기관 HTTPS 원문
- `topics`, `question_families`: 검색·평가 범위를 설명하는 비어 있지 않은 문자열 목록
- `verified_at`: 사람이 공식 원문을 마지막으로 확인한 날짜
- `review_due_date`: 다음 필수 검토일
- `review_owner`: 검토 책임 역할(`project_owner`)
- `chunking_version`: `markdown-heading-800-v1`

규제·세제 문서는 검토 후 90일, 일반 리서치는 180일 이내로 다음 검토일을 잡는다. 자동화는 날짜를 대신 갱신하지 않는다. `review_due_date`가 지난 문서는 CI와 로더가 적재를 차단하며, 사람이 공식 원문을 확인한 뒤 날짜를 갱신한다. 내용이 바뀌면 본문·SHA-256·검색 품질 사례를 함께 수정한다.

공식 URL은 승인된 공공기관 도메인만 허용한다. 문서와 청크 메타데이터에는 안정 식별자, 공식 출처, 주제, 검증일, 검토기한, 청킹 버전을 전파한다. SHA-256, 개인정보 검사에 더해 숨은 제어문자와 명백한 RAG 지시문 오염을 결정론적으로 거부한다.

## 등록과 검색 품질

각 문서를 `data/knowledge/approved_documents.json` v2에 등록한다. `source_url`은 `project://<path>`, 해시는 UTF-8 `strip()` 본문의 SHA-256, 데이터 경계는 `verified_knowledge`로 고정한다.

`data/search_quality/knowledge_v1.json`에는 문서별 대표 질문 1건 이상을 추가하여 ETF 비교, 과거 운용현황, 연금수령 과세, 실물이전, 예금자보호가 각각 해당 문서를 찾는지 검증한다. 모든 승인 문서는 최소 한 개의 검색 품질 사례를 가져야 한다.

`data/knowledge/README.md`에 후보 선정, 사람 검토, 매니페스트 등록, PR, 원격 적재, 임베딩, 만료 재검토, 폐기 절차를 기록한다. CI는 매니페스트 로딩과 검색 품질 테스트 전에 별도 `--validate-only` 감사를 실행한다.

## 검증

1. 매니페스트가 10건과 신규 경로 5건을 반환한다는 테스트를 먼저 추가하고 실패를 확인한다.
2. 문서와 매니페스트를 추가한 뒤 대상 테스트를 통과시킨다.
3. `load_approved_documents()`로 SHA-256·허용 경로·개인정보·청크 생성을 검증한다.
4. 전체 `uv run pytest`를 실행한다.
5. 원격 Supabase에 승인 문서를 적재하고 BGE-M3 임베딩을 생성한다.
6. 원격 검색 품질을 측정하고 적재·임베딩 건수를 보고한다.
