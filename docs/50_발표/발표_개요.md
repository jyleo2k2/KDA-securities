## 1. Executive Summary (프로젝트 요약)

### 1줄 정의
> **DC형 퇴직연금·IRP·연금저축계좌의 역할·제약과 자산구성을 규칙 엔진으로 계산하고, LLM이 그 수치를 쉽게 설명하는 "설명 가능한(Explainable) AI 연금 운용 가이드".** 자문·정보 제공형이며 실제 주문은 이용자가 공식 채널에서 직접 실행한다(일임 아님).

### 두괄식 핵심 가치 (1슬라이드)
- **문제**: 퇴직연금 적립금의 75.2%(약 373.6조원)가 원리금보장형에 방치. 실적배당형 16.80% vs 원리금보장형 3.09%로 **수익률 5배 격차**, 상·하위 10% 가입자 간 **19%p 격차**. 원인은 무관심이 아니라 "관심은 있지만 방법을 모름" **57.1%**.
- **해결**: 조회(마이데이터로 이미 무료)와 일임(RA 레드오션) 사이의 **빈칸 = [통합진단 → 근거 설명 → 이용자 실행]을 잇는 설명 레이어**를 규칙 엔진 + 검증된 LLM 서술로 채운다.
- **차별화 한 줄**: 모든 계산은 결정론 규칙 엔진(`Decimal`)이 하고 LLM은 **엔진이 낸 수치만** 재서술한다. 근거 없는 숫자는 응답 생성 자체가 실패하도록 코드에 강제(`ChatResponse.verify_evidence_links`).
- **결과물 규모**: 백엔드 158파일·39.3K줄, 프론트 26파일·5.4K줄, 테스트 105파일(백엔드 981 pass / 프론트 53 pass), Supabase 마이그레이션 27개, ETF 유니버스 원격 적재(상품 2,507행·총수익 이력 217,833행).

### 팀 소개 / 프로젝트 아이덴티티
- 프로젝트명(가칭): **연금 코파일럿 (Pension Copilot)**
- 팀: 6인 (총괄 1 · 백엔드/챗봇 1 · 알고리즘/규칙엔진 1 · 프론트 2 · 사이드기능 1) — 상세는 §7.
- 아이덴티티: "떠먹여주는 자동화(일임)"가 아니라 **"납득시켜 스스로 움직이게 하는 설명"**. 헌장 원칙 = Explainable by Design.

## 2. 기획 배경 및 문제 정의

### 2.1 시장 현황 및 문제점 (Pain Point)
- **노후 소득 공백**: 국민연금 부부 평균 월 120만원 = 부부 적정 노후 생활비(월 298~336만원)의 40% 수준. 실질 소득대체율 20~25%.
- **방치의 실증(통계)**: 퇴직연금 원리금보장 75.2%, 가입자 **90%가 운용상품을 한 번도 변경 안 함**, 대기성 자금 이자 연 0.1%. 디폴트옵션(자동화)조차 **85%가 안정형 쏠림** → 자동화는 방치를 못 풀었다.
- **핵심 발견**: 방치의 주범은 무관심(9.3%)이 아니라 **"방법을 모름"(57.1%)**. "넘고 싶다 77% vs 실제로 넘긴 돈 13%" — 의향과 실행의 ~64%p 격차.
- **시의성(변곡점)**: 퇴직연금 시장 501.4조원(+16.1% yoy, 2035년 1,200조 전망), 실물이전 제도(2024.10 시행) 후 은행→증권 머니무브, 연말정산 세액공제 최대 148.5만원 환급 유인.

### 2.2 프로젝트 목표 및 해결책 (Value Proposition)
- **Why**: 조회·자동화는 이미 있는데 방치가 안 풀린다. 빠진 것은 "왜 이 선택인지" 이해시키는 설명 레이어.
- **Who (페르소나)**: "정보부족형 방치자" — 관심 있음 + 방법 모름(57.1%) + 회사 IRP라 내 돈 인식 약함 + 한 번도 운용지시 안 함(90%). 1차 타깃은 세제·적립금 실효성이 큰 3040 직장인.
- **What**: 세 연금계좌의 (1) 통합 자산 홈 (2) 설명 가능한 챗봇 (3) MY투자·전략 비교 (4) 타 고객 포트폴리오 참고 (5) 세금계산 — 5대 핵심 기능. 규칙 엔진이 계산, LLM이 서술, 모든 수치에 출처 칩.
- **보호 경계**: 미래 수익 예측·확정 표현 금지, 성향 밖 상품 제안 금지, 실/목 데이터 경계 유지, 개인 계좌는 RAG에 미포함.

## 3. 데이터 수집 및 분석

### 3.1 데이터 수집 및 전처리
- **출처(실데이터)**: FSS 통합연금포털(연금저축 88건·퇴직연금 42개사 126행), KRX(ETF 일별매매 + 대표 지수 8종), KIS(구성종목·수정주가 897,330개 관측), KIND(현금분배 8,048건), DART·법령(70% 한도 근거), NAVER 검색 API(시장 뉴스 메타데이터).
- **수집 계약**: 소스마다 `*_client.py`(HTTP+응답 검증, API 키는 에러에 미포함) + 수집 CLI(원본 raw 저장·**SHA-256**·기존 파일 skip·재시도 백오프·manifest 기록). 모든 수집은 `ingestion_runs`에 호출·건수·상태를 남긴다.
- **전처리·품질**: 금액은 `numeric`, 수정주가 우선 사용, 분배락 정확일 연결은 ≤7일 창(8,048건 중 8,029건 연결). 결측·저신뢰 분류 ETF만 DART로 타겟 보강. 미래수익률로 외삽하지 않음.
- **실/목 경계**: 시장·제도·상품 = 공식 실데이터, 사용자 계좌·소득·납입 = 목데이터 3종(대표 고객 6명), 뉴스 = 메타데이터+요약, RAG = 검증된 공식 문서만.

### 3.2 탐색적 데이터 분석 (EDA)
- **ETF 유니버스**: 현재 상장·관측충분 945개 중 연금계좌 적격 861개 분류(DC 823·IRP 823·연금저축 861).
- **인사이트**: 계좌 유형별 적격 상품군이 다르고(DC·IRP는 레버리지/인버스 불가), 위험자산 총량 한도(DC·IRP 70%)가 배분의 상한을 결정. 발표의 "방치→격차" 스토리를 뒷받침하는 수익률 격차 통계는 §2.1 참조.

### 3.3 도메인 지식 기반 파생 변수 (Feature Engineering)
- **ETF 다차원 분류**(`asset_classification.py`): 이름·벤치마크·KIS/FSC 신호로 asset_class/region/currency_hedge/management_style/replication_method/leverage_type/strategy + confidence 산출.
- **위험지표**(`market_evidence.py`): 과거 변동성·최대낙폭(MDD)·유동성·추적오차 + 유니버스 대비 백분위.
- **총수익 재구성**: 수정주가 + KIND 현금분배 재투자 반영 총수익 지수(기간수익률 1개월~5년).
- **계좌 적격성**(`pension_eligibility.py`): 한투 퇴직연금 리스트 기반 계좌별 적격성 플래그.

## 4. AI 모델링 및 검증

> 이 프로젝트의 "모델"은 예측 확률 모델(AUC/F1)이 아니라 **결정론 규칙 엔진 + 검증 게이트 위의 LLM 서술**이다. 발표에서는 이 설계 자체가 선택 근거임을 강조(금소법 부당권유·환각 위험을 원천 차단).

### 4.1 모델 파이프라인 및 설계
- **규칙 엔진 6+ 모듈**(`backend/app/engine/`, DB·네트워크·LLM 의존성 0, 전 계산 `Decimal`+`ROUND_HALF_UP`): 성향 분석 → 계좌 규칙 검사(70% 한도) → 계좌별 진단 → 통합 집계 → 적립 시뮬레이션 → 교육용 포트폴리오.
- **교육용 포트폴리오 파이프라인**(`educational_portfolio.py`): 목표배분 → 후보 스코어링(비용20·유동성25·규모20·NAV15·추적오차15·이력5, **과거수익률은 랭킹 미사용**) → 위험(변동성·다운사이드·MDD·VaR95)·스트레스 3종 → 계획수익률(CMA 앵커) → 리밸런싱 가이드.
- **LLM 서술**(`narrator.py`, pydantic-ai + Claude): 엔진이 검증한 답변만 재서술. 숫자·위험주장 가드(`narration_guard.py`)를 통과한 것만 반영, 실패 시 결정론 원문 폴백.
- **검증 게이트**: `ChatResponse.verify_evidence_links`가 답변 속 모든 숫자를 `NumericEvidence`와 대조 — 근거 없는 숫자는 응답 실패.
- **RAG**(`retrieval/`): BGE-M3(1024차원) 하이브리드 — 전문검색+벡터를 RRF(k=60) 융합 후 재랭킹. 임베더 없으면 전문검색 폴백.

### 4.2 모델 실험 및 비교 (선택)
- **내레이터 모델 A/B**: 기본 모델 `claude-haiku-4-5`. 10문항 A/B(질문당 20회)에서 검증 통과율 Haiku 60%(thinking 미사용) vs Sonnet 20%(adaptive thinking). 성능·비용으로 Haiku 채택, 부팅 프리워밍 14→4초·공시 풀 1200→396ms 개선.
- **계획수익률 실험 계보**: CMA 단독 vs 과거·거시 보정 결합을 롤링 빈티지(2023·2024 학습/2025 홀드아웃)로 검증. 12개월 홀드아웃에서 개선 실패 → **현행 반영 기각**, CMA-비용 중앙값 유지(과적합 방어를 정직하게 문서화).

### 4.3 Performance & Backtesting (선택)
- **검증 방식**: 예측 정확도 대신 **불변식 검증**. 교육용 포트폴리오 120개(연령4×은퇴2×성향5×계좌3)에서 DC·IRP 70% 한도 위반 0건·후보 슬리브 누락 0건을 CI에서 강제(위반 시 exit 1).
- **RAG 품질**: 18케이스 로컬 Hit@5=1·Hit@1=1·MRR@5=1, 문서 10건·활성 청크 41건 임베딩 0건 누락.
- **재현성**: 전 계산 `Decimal` 결정론, DB·로컬 입력 동등성 0건 차이, FastAPI 원격 DB E2E 통과. 백엔드 981 pass·프론트 53 pass.

## 5. 서비스 구현

### 5.1 시스템 아키텍처 / Tech Stack
- **스택**: React + TypeScript + Vite PWA → FastAPI → Supabase PostgreSQL/pgvector. 규칙 엔진 Python, LLM은 pydantic-ai(Claude), RAG 임베딩 BGE-M3.
- **단방향 의존**: `frontend → FastAPI → engine/data`. 역방향 import 금지. 엔진은 순수 함수로 고립.
- 상세 그림: [다이어그램.md](./다이어그램.md) §시스템 아키텍처·§데이터 흐름.

### 5.2 핵심 기능 및 시연 (Demo)
- **골든패스**: 로그인 → 계좌 연동 동의(표시 전용) → 투자정보 입력·성향 결과 → 메인 홈 → 챗봇/MY투자/타 고객 포트폴리오/세금계산.
- **시연 포인트**: (1) 챗봇에 "IRP와 연금저축 위험자산 한도 차이" 질문 → 엔진 수치 + 출처 칩 + Claude 서술. (2) 세금계산 → 소득구간별 16.5%/13.2%·600/900만원 한도. (3) 타 고객 포트폴리오 → 로그인 고객 제외 5명 동적 목록.
- **시연 가이드**: [챗봇_테스트_가이드.md](../30_스펙/챗봇_테스트_가이드.md). 동영상/GIF는 골든패스 1회 흐름을 녹화 권장.

## 6. 비즈니스 가치 및 확장 계획

### 6.1 기대 효과
- **정량**: 방치 자금의 실적배당 전환은 상·하위 10% 격차(19%p)를 좁힐 여지. 실물이전 유치 관점에서 "타사 수수료 vs 이전 시 절감액"을 수치로 설명하는 진단 도구는 후발주자(예: 키움 2026.6 진출)의 유치 무기.
- **정성**: 금소법 설명의무를 이행하는 모습으로 신뢰 확보. 조회·일임 사이 빈칸을 선점하는 포지셔닝.
- **KPI 연결**: 연금 적립금 순유입, 실물이전 전환율, 방치 계좌의 운용지시 발생률.
- **규제 안전성**: 후보 풀이 법으로 한정(연금계좌=국내상장 ETF/펀드, 70% 한도)되어 적합성 검증을 규칙 엔진으로 100% 자동화 가능 → 상용화 리스크가 "사업모델 내장"이 아니라 "절차 요건"에 그침.

### 6.2 프로젝트 한계점 및 개선 방향
- **데이터 한계**: 사용자 계좌는 목데이터(실계좌 연동 미구현), CMA 장기 계획가정의 승인 주체·갱신주기 미확정.
- **모델 한계**: 계획수익률의 과거·거시 보정은 홀드아웃 개선 실패로 미채택(CMA-비용 중앙값 사용). 포트폴리오 단위 변동성·하락위험·스트레스 산출 정책 상한 미확정.
- **기술 한계**: 내레이터 안전 가드는 적대적 코퍼스로 계속 보강 중. Supabase Auth 유출 비밀번호 보호 활성화 대기.
- **로드맵**: (P1) 상세 진단·시뮬레이션·알림·미션 → (P2) 실계좌 연동·개인화 자문·주문 연결. 실서비스화 시 투자자문·적합성·개인정보·콘텐츠 권리 재검토.
