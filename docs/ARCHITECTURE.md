# 아키텍처 설계 초안 — 연금 코파일럿

> 코드/구조의 기술 SSOT. 역할을 겹치지 않게 자르기 위한 지도.
> 근거: [pension-copilot-proposal.md](../pension-copilot-proposal.md) §7 · 단계: 구현 전 초안(값 다수 `TODO`)

## 1. 컴포넌트 (의존은 단방향: 위 → 아래, 역방향 import 금지)

```
[① 프레젠테이션]  모바일 웹앱(PWA)              ← 화면·원탭 승인
        │ REST
[② 오케스트레이션] FastAPI + LLM 하네스(Claude API)  ← 도구 호출·서술·검증 루프
        │ (엔진을 '도구'로 호출, 계산은 안 함)
[③ 비즈니스 로직]  규칙 엔진 모듈 (아래 5종)         ← 모든 계산·판단
        │
[④ 도메인/데이터]  연금 도메인 모델 + 데이터 소스     ← 타입·상품 테이블·목데이터
```

## 2. 규칙 엔진 모듈 (③ — 계산·판단의 단일 소스)

| # | 모듈 | 입력 → 출력 |
|---|---|---|
| 1 | 성향 분석 | 설문 → 5단계 성향 (규칙 스코어링) |
| 2 | 부족분 시뮬레이션 | 목표 노후소득 − 예상수령액 (가정 수익률·물가 명시) |
| 3 | drift 감지 | 목표비중 대비 ±5%p 이탈 탐지 → 리밸런싱 트리거 |
| 4 | 상품 스코어링 | 상품-지수-자산군 관계 테이블(경량 지식그래프형) + 수수료율·수익률 → 교체 후보 |
| 5 | 한도 검사 | IRP 위험자산 70% 등 규칙 검사, 위반 제안 차단 |

> **설명(XAI)은 별도 모델이 아니라 이 엔진 출력의 표현 변환 3종**: 수치 근거 카드 / 상품 선택 경로 스텝 / what-if(같은 엔진에 입력만 바꿔 재실행) + 출처 칩.

## 3. LLM 하네스 (② — 계약)
- **Tools**: 엔진 5모듈을 도구로 등록. LLM은 호출만, 계산 금지.
- **Guardrails**: 수치는 도구 결과만 인용. 성향 밖 상품 언급 차단.
- **Loop**: 답변 수치 ↔ 엔진 결과 대조 검증, 불일치 시 재생성.
- **Logging**: 제안·근거·승인 이력(설명의무 감사 추적).

## 4. 데이터 계층 (④ — 실/목 경계가 계약)
| 소스 | 실/목 | 용도 |
|---|---|---|
| 금감원 통합연금포털 Open API (키 발급됨) | **실** | 상품 스코어링·부족분 가정수익률·이전 절감액·출처 칩 |
| KRX / 증권사 OpenAPI (ETF 시세·보수) | **실** | 스코어링 보조(분기 공시 보완) |
| 사용자 3층연금 계좌 | **목** (시나리오 3종: 공격쏠림/중립/방치) | 마이데이터 대체 |

## 5. 폴더 구조 (제안 — 폴더 = 담당 경계, 팀 확정 후 배정)
```
frontend/   ① PWA 화면·원탭 실행
backend/    ② FastAPI + LLM 하네스
engine/     ③ 규칙 엔진 5모듈 (순수 함수 지향, 테스트 최우선)
data/       ④ 통합연금포털 클라이언트·상품 테이블·시나리오 목데이터
docs/       설계·팀 문서
```
> 공유 계약(REST 스키마, 엔진 I/O 타입, 상품 테이블 스키마) 변경 시 PR에 "계약 변경" 명시 + 머지 담당 1인.
