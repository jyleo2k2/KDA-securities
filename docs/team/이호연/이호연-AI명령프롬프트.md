# 이호연 — AI 명령 프롬프트 가이드 (조장·챗봇 백엔드)
> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다. 아래 블록을 순서대로 보내면 AI가 대신 한다.

## 0. 사용법 (사람이 읽는 부분)
1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 "이렇게 만들 계획이야" 하면, 이상 없으면 "진행해" 라고 한다.
4. 만들면 §5 자가검증을 보내 스스로 점검하게 한다.
5. 헷갈리면 §4 문장을 그대로 보낸다. 모르면 "쉽게 설명해줘"라고 해도 된다.
> 팁: 한 번에 다 시키지 말고 한 종류씩.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)
```
너는 연금 코파일럿의 챗봇·백엔드(FastAPI) 작업을 돕는다. 나는 이호연, 조장·챗봇 백엔드 담당이며 뉴스·ETF 테마·연금계좌·세액공제 질문 도구와 서비스 통합을 맡는다. 설명은 쉽고 명확하게.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 내가 할 일 ② 내가 하면 안 되는 것(특히 engine 폴더)
③ 꼭 지킬 핵심 규칙을 정리해줘. 아직 만들지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/team/이호연/이호연-담당업무.md 4.docs/30_스펙/아키텍처.md
환경: uv run python(단독 python 금지), 테스트는 uv run pytest. 작업 폴더: backend/app(engine 제외).
```

## 2. 고정 규칙 (AI가 작업 때 지킬 것)
```
[고정 규칙]
1. LLM(Claude API)은 엔진 결과·검색 근거의 자연어 서술 + Q&A만. 직접 수치 계산 금지(헌장 §1).
2. backend/app/engine은 건드리지 않는다 — 필요하면 engine이 노출한 함수/도구만 호출.
3. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시(가짜 값 금지).
4. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
5. 답변 수치는 반드시 엔진 또는 SQL/API 결과에 연결하고 출처 칩을 단다(아키텍처.md §3 Guardrails).
```

## 3. 작업별 명령 프롬프트 (복붙용, 한 종류씩)
### 3-1. 챗봇 내레이터 검토 과정 표시 마무리
```
[작업] backend/app/chat/narrator.py의 pydantic-ai 내레이터가 반환하는 narration_reasoning을
API 응답(backend/app/api/chat.py)까지 연결해줘. 화면 표시용 필드명은 기존 계약을 유지.
[제약] 원문에 없던 숫자를 감지하면 결정론적 답변으로 복귀(기존 가드 로직 유지). API 키 없을 때도 골든패스 동작 유지.
[검증] uv run pytest tests/test_chat_mvp.py 실행 결과로 확인. 실패하면 원인 설명 후 재시도.
[산출물] 계획 먼저 → "진행해" 하면 생성.
```

### 3-2. RAG 지식 코퍼스 확충
```
[작업] docs/의 검증된 공식 문서를 knowledge_documents/knowledge_chunks에 추가할 수 있게 적재 스크립트 입력을 준비해줘.
[제약] 개인 계좌·사용자 데이터는 절대 넣지 않는다(헌장 §1 실/목 데이터 경계). 출처가 불명확한 문서는 TODO로 보류.
[검증] scripts/embed_knowledge_chunks.py 드라이런 또는 로컬 전문검색 폴백으로 조회 결과 확인.
[산출물] 계획(추가할 문서 목록) 먼저 → "진행해" 하면 적재.
```

### 3-3. 벤치마크 탭 REST 계약 정의
```
[작업] mock_public_profiles/mock_public_portfolios 기반으로 벤치마크 탭이 쓸 REST 응답 스키마를 초안해줘.
[제약] 프론트엔드(최호택·진재현) 담당 폴더는 건드리지 않는다 — 계약(스키마)만 문서화.
[검증] 기존 다른 엔드포인트 응답 스키마 스타일과 일치하는지 비교.
[산출물] 계획(스키마 초안) 먼저 → "진행해" 하면 라우터 구현. PR에 "계약 변경" 명시.
```

## 4. AI와 일하는 법 (막히면 그대로 보내기)
- 한 번에 하나: `지금은 [이것]만 만들자. 다른 건 건드리지 마.`
- 쉽게 설명: `방금 한 걸 누구나 알아듣게 쉽게 설명해줘.`
- 가짜 값 방지: `이 값 추측이야 출처 있어? 추측이면 TODO로 바꿔줘.`
- 검증: `방금 만든 걸 실제로 실행해서 결과를 보여줘. 빠진 것도 확인해줘.`

## 5. 자가검증 프롬프트 (PR 전)
```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/테스트해서):
1. backend/app/engine을 건드리지 않았나?  2. 답변 수치마다 출처가 연결됐나?  3. 헌장 금지사항 안 어겼나?
4. 한국어 안 깨졌나? 빠진 값 의도된 건가?
아니오가 있으면 고친 뒤 다시 보고해.
```
