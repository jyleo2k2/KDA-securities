# 이재용 — AI 명령 프롬프트 가이드 (프로젝트 총괄·AI 서비스 아키텍처)
> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다. 아래 블록을 순서대로 보내면 AI가 대신 한다.

## 0. 사용법 (사람이 읽는 부분)
1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 "이렇게 만들 계획이야" 하면, 이상 없으면 "진행해" 라고 한다.
4. 만들면 §5 자가검증을 보내 스스로 점검하게 한다.
5. 헷갈리면 §4 문장을 그대로 보낸다.
> 팁: 한 번에 다 시키지 말고 한 종류씩.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)
```
너는 연금 코파일럿 프로젝트의 총괄(이재용)을 돕는다. 나는 전체 아키텍처, 규칙 엔진·LLM 분리, 챗봇·RAG, 서비스 통합·검증, 코드 정합성·머지 승인을 담당한다.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 지금 팀 전체 진행 상태 ② 아직 승인 안 된 잠정 파라미터
③ 꼭 지킬 핵심 규칙을 정리해줘. 아직 아무것도 고치지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/30_스펙/아키텍처.md 4.docs/team/{팀원명}/{팀원명}-담당업무.md(감사 대상)
환경: uv run python(단독 python 금지), 테스트는 uv run pytest. 작업 폴더: 전역(전 영역 권한, 단 진입점 파일은 로컬 .claude/.owner-verified 마커 있는 환경에서만 편집).
```

## 2. 고정 규칙 (AI가 작업 때 지킬 것)
```
[고정 규칙]
1. 자문·정보 제공형 유지 — 미래 수익 예측·일임 표현 금지, 계산은 규칙 엔진만.
2. 팀원 담당 폴더는 합의 없이 대신 고치지 않는다(폴더 = 담당 경계, 헌장 §2).
3. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시(가짜 값 금지).
4. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
5. 테스트가 갑자기 통째로 깨지면 다른 AI 도구(Codex 등)의 미커밋 작업이 원인인지 git status로 먼저 확인(헌장 §4 함정 노트).
```

## 3. 작업별 명령 프롬프트 (복붙용, 한 종류씩)
### 3-1. PR 리뷰 + 머지 판단
```
[작업] 현재 열려 있는 PR(또는 지정 브랜치)의 diff를 읽고 헌장 위반·계약 변경 누락·테스트 실패 여부를 점검해줘.
[제약] 담당 폴더 밖 변경이 있으면 이유를 반드시 짚어줘. 계약 변경(REST 스키마·엔진 I/O·DB 마이그레이션) 시 PR에 "계약 변경" 명시 여부 확인.
[검증] uv run pytest·uv run ruff check . 실행 결과와 함께 표로 보고.
[산출물] 계획 먼저 → "진행해" 하면 머지 커맨드 준비(실제 머지는 내가 실행).
```

### 3-2. 헌장 래칫(함정 노트) 갱신
```
[작업] 최근 세션에서 반복된 실수·오작동 패턴을 찾아 docs/team/_공통_AI규칙.md §4 함정 노트에 규칙 1줄로 추가해줘.
[제약] 같은 실수가 실제로 2회 이상 확인된 것만. 추측성 규칙 추가 금지.
[검증] 추가한 줄이 헌장 §2 작업환경 규칙과 모순되지 않는지 확인.
[산출물] 계획(추가할 문장) 먼저 → "진행해" 하면 반영.
```

### 3-3. 아키텍처 문서 최신화
```
[작업] docs/30_스펙/아키텍처.md §9(구현·검증 상태)·§10(남은 결정)을 실제 코드·테스트 결과 기준으로 갱신해줘.
[제약] 실행 결과 없는 "완료" 표기 금지 — uv run pytest 실행 결과를 근거로.
[검증] 갱신 후 CLAUDE.md/AGENTS.md의 요약 링크가 여전히 유효한지(섹션 앵커 일치) 확인.
[산출물] 계획 먼저 → "진행해" 하면 반영.
```

## 4. AI와 일하는 법 (막히면 그대로 보내기)
- 한 번에 하나: `지금은 [이것]만 만들자. 다른 건 건드리지 마.`
- 쉽게 설명: `방금 한 걸 누구나 알아듣게 쉽게 설명해줘.`
- 가짜 값 방지: `이 값 추측이야 출처 있어? 추측이면 TODO로 바꿔줘.`
- 검증: `방금 만든 걸 실제로 실행해서 결과를 보여줘. 빠진 것도 확인해줘.`

## 5. 자가검증 프롬프트 (PR 전)
```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/테스트해서):
1. 팀원 담당 경계를 침범하지 않았나?  2. 계약 변경 시 PR에 명시했나?  3. 헌장 금지사항 안 어겼나?
4. 한국어 안 깨졌나? 빠진 값 의도된 건가?
아니오가 있으면 고친 뒤 다시 보고해.
```
