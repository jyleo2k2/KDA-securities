# 김태형 — 담당업무 (연금 엔진·ETF 데이터 통합)

## 1. 담당 역할

### 연금 운용 규칙 엔진·ETF 데이터 검증·서비스 통합

연금계좌별 제약과 교육용 포트폴리오 계산을 규칙 기반으로 설계하고, ETF의 수익률·보수·거래량·배당·거시 데이터를 검증 가능한 근거로 연결했다. 장기 계획가정, 포트폴리오 위험·스트레스, 챗봇 근거 카드, 계산기·보유종목 화면, PWA 상태 정책까지 연결해 설명 가능한 연금 운용 가이드가 서비스 흐름에서 일관되게 작동하도록 담당했다.

## 2. 발표자료 카드 문구

**김태형　연금 엔진·ETF 데이터 통합**
계좌 규칙 · CMA 계획가정 · 위험·스트레스 · 공식 ETF 데이터 · 서비스 연결

공간이 부족한 경우:

**김태형　연금 엔진·데이터 검증**
ETF 데이터 · 계획가정 · 위험정책 · 챗봇·화면 통합

## 3. 주요 담당 업무

### 연금계좌·포트폴리오 규칙 엔진

- DC형·IRP·연금저축의 계좌별 운용 규칙과 위험자산 한도 차이를 문서와 엔진 기준으로 정리
- DC형·IRP 위험자산 70% 원칙과 연금저축 별도 적격성 규칙의 분리 유지
- 현재 보유 ETF 기반 장기 계획가정과 전략별 연금 계획·추천 카드 연결
- 장기 계획가정을 미래수익률 예측이 아닌 CMA에서 검증 연간비용을 차감하는 원칙으로 설계
- 연금계좌 데이터와 계좌 API를 서비스 계산·화면에 연결

### ETF 공식 데이터 검증·정합성 관리

- KRX 전체 상장 ETF 일별 거래량 스냅샷 연결
- ETF 총수익률 이력을 2011년까지 보강하고 관측 범위가 부족한 상품 관리
- KOFIA 공시 총보수율과 ETF 식별자를 감사 가능한 방식으로 매핑
- KIND 현금분배 데이터와 ETF 수익률 연결 및 공식 배당 데이터 검증
- 과거 데이터를 위험·성과 설명 근거로만 사용하고 미래 성과 보장·예측으로 사용하지 않도록 경계 유지

### 포트폴리오 위험·스트레스 정책

- 포트폴리오 단위 변동성·최대낙폭·정책 스트레스 시나리오 계산 구조 보강
- 사용자 손실감내도와 최악 정책 스트레스 손실을 비교해 기준 이내·재점검 필요·미비교 상태 제공
- 손실감내도 초과 시 목표 비중과 납입 계획 재검토를 안내하되 자동매도·자동주문 지시 금지
- 과거 위험 측정값과 정책 스트레스의 성격을 설명하는 안내·출처 표기 화면 반영
- 엔진과 프론트 컴포넌트 테스트로 상태값·경고·표시 문구 검증

### 거시·챗봇 근거와 화면 연결

- 과거 유사국면 조회 거시 레짐 API와 공식 거시 근거 파이프라인 추가
- 거시 근거를 API·챗봇 카드에 노출해 설명 근거 확인 지원
- 실시간 뉴스 이벤트 전략 안내와 ETF 레짐 결과 근거 카드 연결
- 현재 보유 ETF, 장기 계획가정, 연금 전략 카드, 위험·스트레스 근거를 실제 엔진 응답과 화면에 통합
- 인증·개인화 API와 챗 SSE를 최신 응답으로 유지하는 PWA 캐시·상태 정책 보강

### 운영 정책·재현성 관리

- 장기 계획가정 운영 정책 문서화
- CMA 원천·기준일·비용 출처·입력 스냅샷·엔진 버전·정책 버전 보존
- 계산식·자산군 매핑·비용 처리 변경 시 엔진 오너 승인과 별도 정책 버전을 요구하는 통제 절차 정의
- 최소 연 1회 검토와 예외 검토, 승인·배포·롤백 흐름 정리

## 4. 발표 멘트

저는 연금 운용 규칙 엔진과 ETF 데이터 검증, 그리고 서비스 통합을 담당했습니다. 먼저 DC형·IRP·연금저축의 계좌별 제약이 혼동되지 않도록 규칙 기반 계산 구조를 정리하고, ETF의 총수익률·거래량·총보수·배당 데이터를 공식 출처 중심으로 연결했습니다.

장기 계획가정은 미래수익률을 예측하는 방식이 아니라 CMA에서 검증된 연간비용을 차감하는 기준으로 설계했고, 과거 수익률은 포트폴리오 위험과 최대낙폭을 설명하는 참고 데이터로만 사용했습니다. 또한 사용자의 손실감내도와 정책 스트레스 손실을 비교해 재점검이 필요한 경우를 안내하도록 구현했습니다. 이 결과가 챗봇 근거 카드, 연금 계획·보유종목 화면, PWA 환경까지 자연스럽게 연결되도록 통합했습니다.

## 5. 한 문장 요약

연금계좌 규칙과 ETF 공식 데이터를 기반으로 장기 계획가정·위험 분석·챗봇·화면을 연결해 근거를 확인할 수 있는 연금 운용 엔진과 통합 흐름을 담당했다.

## 개발 작업 경계

- 규칙 엔진의 주 작업 경로는 `backend/app/engine`이며 순수 함수와 단방향 의존을 유지한다.
- FastAPI·Supabase·LLM 연동은 공개된 엔진 인터페이스와 계약을 통해 연결한다.
