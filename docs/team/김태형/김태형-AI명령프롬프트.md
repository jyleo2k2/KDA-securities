# 김태형 — AI 명령 프롬프트 가이드 (연금 엔진·ETF 데이터 통합)
> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다. 아래 블록을 순서대로 보내면 AI가 대신 한다.

## 0. 사용법 (사람이 읽는 부분)
1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 "이렇게 만들 계획이야" 하면, 이상 없으면 "진행해" 라고 한다.
4. 만들면 §5 자가검증을 보내 스스로 점검하게 한다.
5. 헷갈리면 §4 문장을 그대로 보낸다. 모르면 "쉽게 설명해줘"라고 해도 된다.
> 팁: 한 번에 다 시키지 말고 한 종류씩.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)
```
너는 연금 코파일럿의 규칙 엔진과 ETF 데이터 검증 작업을 돕는다. 나는 김태형, 연금 엔진·ETF 데이터 통합 담당이며 계좌 규칙·계획가정·위험·스트레스·서비스 근거 연결을 맡는다. 설명은 쉽고 명확하게.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 내가 할 일 ② 내가 하면 안 되는 것
③ 꼭 지킬 핵심 규칙을 정리해줘. 아직 만들지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/team/김태형/김태형-담당업무.md 4.docs/30_스펙/아키텍처.md
환경: uv run python(단독 python 금지), 테스트는 uv run pytest. 작업 폴더: backend/app/engine.
```

## 2. 고정 규칙 (AI가 작업 때 지킬 것)
```
[고정 규칙]
1. 엔진은 순수 함수로 유지 — FastAPI·Supabase·LLM에 의존하지 않는다.
2. DC형·IRP 위험자산 70% 한도 규칙과 연금저축 적격성 규칙을 섞지 않는다(계좌별 규칙 분리).
3. 계산·판단은 전부 엔진이 한다 — 결과의 자연어 서술은 LLM 몫이지 여기서 만들지 않는다.
4. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시(가짜 값 금지) — 특히 잠정 파라미터.
5. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
```

## 3. 작업별 명령 프롬프트 (복붙용, 한 종류씩)
### 3-1. 잠정 파라미터 검토 자료 작성
```
[작업] 성향 설문 배점·진단 임계값(현금성 80%·편중 50%)·물가 가정 2.0%의 현재 근거와 대안값을 정리해줘(이재용 승인용).
[제약] 확정값으로 바로 바꾸지 말고 TODO: 확인 필요 상태를 유지. 근거 없는 숫자는 만들지 않는다.
[검증] 기존 골든 테스트(수익률_가정_모델.md 28케이스·20셀)가 대안값에서도 논리적으로 재현 가능한지 시뮬레이션.
[산출물] 계획(비교표) 먼저 → "진행해" 하면 문서화.
```

### 3-2. 엔진 회귀 테스트 보강
```
[작업] {대상 모듈}(예: aggregation.py)의 엣지 케이스(계좌 0개, 위험자산 한도 초과 등)에 대한 pytest 케이스를 추가해줘.
[제약] backend/app/engine 밖 코드는 건드리지 않는다.
[검증] uv run pytest -k {모듈명} 실행 결과로 통과 확인.
[산출물] 계획 먼저 → "진행해" 하면 생성.
```

## 4. AI와 일하는 법 (막히면 그대로 보내기)
- 한 번에 하나: `지금은 [이것]만 만들자. 다른 건 건드리지 마.`
- 쉽게 설명: `방금 한 걸 누구나 알아듣게 쉽게 설명해줘.`
- 가짜 값 방지: `이 값 추측이야 출처 있어? 추측이면 TODO로 바꿔줘.`
- 검증: `방금 만든 걸 실제로 실행해서 결과를 보여줘. 빠진 것도 확인해줘.`

## 5. 자가검증 프롬프트 (PR 전)
```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/테스트해서):
1. 엔진이 여전히 순수 함수인가(외부 의존 안 생겼나)?  2. 계좌별 규칙이 섞이지 않았나?  3. uv run pytest 전부 통과했나?
4. 한국어 안 깨졌나? 빠진 값 의도된 건가?
아니오가 있으면 고친 뒤 다시 보고해.
```
