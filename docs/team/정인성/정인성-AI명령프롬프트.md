# 정인성 — AI 명령 프롬프트 가이드 (데이터·서비스 통합 및 고객 UX)
> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다. 아래 블록을 순서대로 보내면 AI가 대신 한다.

## 0. 사용법

1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 읽은 규칙과 수정 범위를 요약하면 §3에서 한 종류의 작업만 보낸다.
3. 최신 원격 `main`에서 전용 워크트리·브랜치·claim을 만든 뒤 작업한다.
4. 작업 후 §5 자가검증으로 데이터·화면·챗봇의 일관성을 확인한다.

## 1. 온보딩 프롬프트

```
너는 연금 코파일럿의 데이터·서비스 통합과 고객 UX 작업을 돕는다. 나는 정인성이고, 고객 목데이터·대표 6인 시나리오·Supabase/Auth·ETF 포트폴리오·벤치마크 기획·챗봇 및 데모 UX·QA를 담당한다. 설명은 쉽고 명확하게.

먼저 최신 원격 main의 아래 파일을 읽고 ① 현재 역할 ② 이번 작업의 파일 경계 ③ 지켜야 할 데이터·엔진·LLM 규칙을 정리해줘. 아직 수정하지 마.
읽을 파일: 1.AGENTS.md 2.docs/team/_공통_AI규칙.md 3.docs/team/정인성/정인성-담당업무.md 4.docs/10_기획/기획서.md 5.작업 대상 폴더의 AGENTS.md 또는 CLAUDE.md
환경: Python은 uv run python, 테스트는 uv run pytest. 프론트는 frontend에서 npm run build와 npm test. 작업 전 git-session-manager로 전용 워크트리와 claim을 만든다.
```

## 2. 고정 규칙

```
[고정 규칙]
1. 최신 origin/main에서 새 codex/정인성/<작업명> 브랜치와 전용 워크트리를 만든다.
2. 역할이 여러 영역에 걸쳐 있어도 실제 파일 수정은 폴더별 AGENTS.md·CLAUDE.md와 claim 범위 안에서만 한다.
3. 계산·한도 판정·성향 분류는 규칙 엔진 결과를 사용하고 LLM이나 화면 코드에서 직접 계산하지 않는다.
4. 실데이터·목데이터·가정값을 구분하고 고객 목데이터를 실제 고객 정보처럼 표현하지 않는다.
5. LLM이 필요 없는 고정 응답·라우팅·표시 로직은 결정론적으로 구현해 비용과 지연을 줄인다.
6. .env·API 키·고객 로그인 비밀번호를 읽어서 출력하거나 커밋하지 않는다.
7. 루트 AGENTS.md·CLAUDE.md는 이재용 전용 잠금 파일이므로 수정하지 않는다.
```

## 3. 작업별 명령 프롬프트

### 3-1. 고객 데이터·서비스 연결 검증

```
[작업] 대표 고객 데이터가 Supabase/Auth, 로그인, 투자성향, 홈, 벤치마크, 챗봇에서 같은 사용자와 같은 값으로 연결되는지 점검해줘.
[제약] 시크릿을 출력하지 말고 개인식별정보 대신 시나리오 코드와 공개 필드로 검증해줘.
[검증] 데이터 계약, API 응답, 화면 표시를 순서대로 확인하고 불일치를 파일·필드 단위로 보고해줘.
[산출물] 원인과 최소 수정안 계획을 먼저 제시하고 승인 후 반영해줘.
```

### 3-2. 홈·챗봇 고객 UX 개선

```
[작업] 고객이 자신의 포트폴리오나 챗봇 답변을 빠르게 이해하도록 문구와 이동 흐름을 개선해줘.
[제약] 시황을 개인 진단처럼 표현하지 말고, 수치 판단은 기존 엔진·데이터만 사용해줘. 규칙으로 처리할 수 있는 응답에는 LLM을 새로 호출하지 마.
[검증] 정상 데이터·빈 데이터·차단 응답 회귀 테스트와 프론트 build/test를 실행해줘.
[산출물] 변경 문구와 라우팅 동작을 먼저 보여주고 승인 후 구현해줘.
```

### 3-3. 시연 골든패스 QA

```
[작업] 로그인 → 계좌 연동 동의 → 투자성향 → 홈 → 챗봇·연금계산기·벤치마크 흐름을 실제 앱에서 점검해줘.
[제약] 실제 주문·자동매매·실계좌 연결이 발생한다고 표현하지 마. 발견한 문제를 임의로 고치지 말고 재현 단계와 원인을 먼저 정리해줘.
[검증] 사용자별 데이터 전환, 뒤로가기·닫기, 오류 안내, 목데이터 표시를 확인해줘.
[산출물] 재현 절차·기대 결과·실제 결과·담당 영역을 표로 보고해줘.
```

## 4. AI와 일하는 법

- 한 번에 하나: `지금은 이 작업만 하고 다른 파일은 건드리지 마.`
- 쉽게 설명: `방금 한 걸 발표에서 말할 수 있게 쉽게 설명해줘.`
- 가짜 값 방지: `이 값의 코드·DB·공식 출처가 어디인지 보여줘.`
- 검증: `실제로 테스트하고 실패한 항목은 숨기지 말고 원인과 함께 보고해줘.`

## 5. 자가검증 프롬프트

```
방금 만든 걸 실제로 점검해줘.
1. 최신 origin/main에서 만든 전용 워크트리와 claim 범위에서 작업했나?
2. 고객 데이터가 인증·API·화면·챗봇에서 일관적인가?
3. 계산을 화면이나 LLM이 임의로 만들지 않았나?
4. 불필요한 LLM 호출을 추가하지 않았나?
5. 실/목 데이터 표시와 시크릿 보호가 유지됐나?
6. 관련 테스트와 문서 검증을 실행했나?
아니오가 있으면 원인을 설명하고 승인된 범위 안에서 수정한 뒤 다시 보고해줘.
```
