# 최호택 — AI 명령 프롬프트 가이드 (프론트엔드·서비스 UI)
> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다. 아래 블록을 순서대로 보내면 AI가 대신 한다.

## 0. 사용법 (사람이 읽는 부분)
1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 "이렇게 만들 계획이야" 하면, 이상 없으면 "진행해" 라고 한다.
4. 만들면 §5 자가검증을 보내 스스로 점검하게 한다.
5. 헷갈리면 §4 문장을 그대로 보낸다. 모르면 "쉽게 설명해줘"라고 해도 된다.
> 팁: 한 번에 다 시키지 말고 한 종류씩.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)
```
너는 연금 코파일럿의 프론트엔드(React PWA) 작업을 돕는다. 나는 최호택, 프론트엔드·서비스 UI 담당이며 로그인·온보딩·챗봇·홈 화면과 데모 UX를 맡는다. 설명은 쉽고 명확하게.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 내가 할 일 ② 내가 하면 안 되는 것
③ 꼭 지킬 핵심 규칙을 정리해줘. 아직 만들지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/team/최호택/최호택-담당업무.md 4.docs/30_스펙/아키텍처.md
환경: frontend/에서 npm 사용, 빌드 검증은 npm run build. 작업 폴더: frontend/(진재현과 공유 — 화면 분담 확인 후 작업).
```

## 2. 고정 규칙 (AI가 작업 때 지킬 것)
```
[고정 규칙]
1. 프론트는 REST 계약을 통해서만 데이터를 받는다 — 엔진·DB를 직접 계산 계층으로 쓰지 않는다.
2. 모든 화면 수치에는 출처·기준일·실/목 구분 표시(헌장 §1).
3. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시(가짜 값 금지).
4. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
5. 진재현이 같은 컴포넌트를 만지고 있을 수 있으니, 새 파일/컴포넌트 생성 전 담당 분담을 먼저 확인.
```

## 3. 작업별 명령 프롬프트 (복붙용, 한 종류씩)
### 3-1. 화면 REST 연결
```
[작업] {화면명}이 백엔드 {엔드포인트 경로}를 호출해 데이터를 표시하도록 frontend/src/api·pages를 연결해줘.
[제약] 응답 스키마가 백엔드 계약과 다르면 임의로 지어내지 말고 백엔드 담당(이호연)에게 확인이 필요하다고 표시.
[검증] npm run build 통과 + 실제 로컬 서버로 화면 동작 확인(브라우저에서 골든 경로·에러 경로 모두).
[산출물] 계획 먼저 → "진행해" 하면 생성.
```

### 3-2. PWA 캐시/상태관리 정책 초안
```
[작업] React PWA의 상태관리·데이터 패칭·캐시 정책 초안을 frontend/ 구조에 맞게 제안해줘.
[제약] 기존 4탭 골격을 깨지 않는 범위. 결정 안 된 부분은 TODO: 확인 필요로 남기고 이재용 승인 필요 표시.
[검증] 기존 화면에서 회귀가 없는지 npm run build + 수동 확인.
[산출물] 계획(정책 초안 문서 또는 코드) 먼저 → "진행해" 하면 반영.
```

## 4. AI와 일하는 법 (막히면 그대로 보내기)
- 한 번에 하나: `지금은 [이것]만 만들자. 다른 건 건드리지 마.`
- 쉽게 설명: `방금 한 걸 누구나 알아듣게 쉽게 설명해줘.`
- 가짜 값 방지: `이 값 추측이야 출처 있어? 추측이면 TODO로 바꿔줘.`
- 검증: `방금 만든 걸 실제로 실행해서 결과를 보여줘. 빠진 것도 확인해줘.`

## 5. 자가검증 프롬프트 (PR 전)
```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/테스트해서):
1. npm run build 통과했나?  2. 모든 수치에 출처·실/목 표시가 있나?  3. 진재현 작업 영역과 충돌 없나?
4. 한국어 안 깨졌나? 빠진 값 의도된 건가?
아니오가 있으면 고친 뒤 다시 보고해.
```
