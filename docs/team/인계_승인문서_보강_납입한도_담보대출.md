### 셸 (PowerShell) — 매 명령 앞에 반드시 붙인다

```powershell
$OutputEncoding = [System.Text.Encoding]::UTF8; [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; chcp 65001 > $null
```

- Python 한글 출력이 필요하면 `$env:PYTHONIOENCODING="utf-8"`도 추가한다.
- 파일 읽기는 반드시 `Get-Content -Encoding UTF8`. 안 붙이면 한글이 깨진다.
- Python은 반드시 `uv run python` / `uv run pytest`. 단독 `python` 금지.
- `Select-String`에는 `-Recurse`가 없다. `Get-ChildItem -Recurse | Select-String`을 쓴다.
- 복잡한 프로브는 here-string으로 `_x.py` 파일에 쓴 뒤 `uv run python _x.py`로 실행하고,
  끝나면 반드시 `Remove-Item`으로 지운다.

## 3. 보강할 내용 3건 (근거 확정됨)

### 3-1. 전체 납입한도 연 1,800만원 — 가장 중요

**대상 문서**: `docs/40_규제/연금계좌_세액공제.md` (§2 납입 한도 뒤에 새 절 추가 권장)

**현재 문제**: 문서에 **세액공제 한도 900만원만** 있다. 그래서 사용자가
"한도 넘게 넣으면 어떻게 돼?"라고 물으면 세액공제 한도로만 답한다.
실제로는 한도가 **두 층**인데 아래층이 통째로 빠져 있다.

**넣을 사실**:

| 구분 | 금액 | 성격 |
|---|---|---|
| 전체 납입한도 | 연 **1,800만원** (연금저축 + IRP 합산) | 이 금액까지 **넣을 수 있다** |
| 세액공제 대상 | 연 900만원 (연금저축 단독 600만원) | 이 금액까지만 **공제받는다** |

- 근거: 「소득세법 시행령」 제40조의2 제2항 제1호 가목. 현행 2026-07-01 시행본.
- 같은 항 본문이 **"연금계좌가 2개 이상인 경우 각 연금계좌의 납입액 합계액"**을
  기준으로 한다고 명시한다. 즉 계좌를 나눠도 개인별로 합산된다.
- **계좌 개수 자체에는 제한이 없다.** 여러 금융회사에 나눠 만들 수 있다.
  진짜 제약은 개수가 아니라 금액이다.
- 900만원을 넘고 1,800만원 이하인 납입액은 **넣을 수 있고 계좌 안에서 운용도 된다.**
  세액공제만 못 받는다. 1,800만원을 넘겨야 한도 초과다.
- 세액공제를 받지 않은 납입액은 나중에 인출할 때 세금 취급이 다르다는 점을
  함께 적되, 구체 세율은 `연금수령_과세.md`의 기존 서술을 넘어서지 않는다.

**공식 출처 URL** (문서 하단 출처 절에 추가):
- `https://www.law.go.kr/lsSc.do?menuId=1&query=소득세법시행령` (제40조의2)
- `https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7875` (국세청 연금계좌 세액공제)

### 3-2. 납입 중단·재개

**대상 문서**: `docs/20_리서치/연금_기초.md` (§5 세금 절 근처 또는 §6 제도 절에 신설)

**현재 문제**: "돈 없을 때 한 달 걸러도 돼?"가 세액공제 한도 문서로 답한다.
틀리진 않지만 **핵심("쉬어도 된다")을 직접 말하지 못한다.**

**넣을 사실**:
- **납입 중단은 해지가 아니다.** 계좌를 유지한 채 납입만 멈출 수 있고,
  여유가 생기면 다시 납입할 수 있다.
- **연금저축펀드(증권사)는 자유납입**이다. 정해진 금액을 매달 넣어야 할 의무가 없다.
- **연금저축보험은 다르다.** 미납이 이어지면 납입유예·실효·해지 관련 불이익이
  생길 수 있고, 유예 조건·기간·횟수가 상품마다 다르다. 상품 유형을 구분해 서술한다.
- 납입하지 않은 해의 세액공제 한도는 **다음 해로 이월되지 않는다.**
- IRP는 계좌 유지와 별개로 중도인출이 법정 사유로 제한된다는 점을 상기시킨다.

**공식 출처 URL**:
- `https://www.fsc.go.kr/po010101/71047` (금융위원회 연금저축 안내)
- `https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7885` (국세청 납입·인출 순서)

### 3-3. 담보대출 — 중도인출과 다른 제도

**대상 문서**: `docs/40_규제/퇴직연금_수령_중도인출.md` (§2 중도인출 절 뒤에 신설)

**현재 문제**: "급하게 돈 필요하면 담보대출도 돼?"가 중도인출 문서로 답한다.
그런데 문서에 담보대출 절이 없어서 **"적립금이 남는다 vs 줄어든다"는 결정적 차이**를
전하지 못한다. 자금이 잠깐 필요한 사용자에게 이 구분은 노후자금을 지키는 갈림길이다.

**넣을 사실**:

| 구분 | 담보대출 | 중도인출 |
|---|---|---|
| 적립금 | 계좌에 **그대로 남는다** | 인출한 만큼 **줄어든다** |
| 상환 | 필요하다 | 필요 없다 |
| 한도 | 통상 적립금의 **50% 이내** | 법정 사유별 한도 적용 |
| 노후자금 | 원칙적으로 보존된다 | 감소한다 |
| 법정 사유 | 필요하다 | 필요하다 |

- 근거: 「근로자퇴직급여 보장법」 제7조 및 같은 법 시행령. 퇴직연금 수급권은
  원칙적으로 양도·압류·담보 제공이 제한되고, 법정 사유에 한해 담보 제공이 허용된다.
- 법정 사유: 무주택자의 본인 명의 주택 구입, 주거 목적 전세금·임차보증금,
  본인·부양가족의 **6개월 이상 요양**, 최근 5년 이내 개인회생 개시결정,
  최근 5년 이내 파산선고, 천재지변 피해.
- **반드시 함께 적을 단서**: 50%는 법적으로 담보 제공이 가능한 한도일 뿐,
  모든 금융회사가 실제 대출상품을 운영해야 한다는 뜻이 아니다.
  취급 여부·한도·금리는 가입 금융회사에 확인해야 한다.
- **연금저축은 퇴직급여보장법 적용 대상이 아니다.** 금융회사 상품에 따라
  납입금 담보대출이 가능할 수 있으며, IRP·DC형 규칙을 그대로 적용하지 않는다.

**공식 출처 URL**:
- `https://www.easylaw.go.kr/CSP/CnpClsMainBtr.laf?ccfNo=3&cciNo=3&cnpClsNo=1&csmSeq=999&popMenu=ov`
- `https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=279829` (근로자퇴직급여 보장법)

## 4. 매니페스트 SHA-256 갱신 (빼먹으면 반드시 실패한다)

승인 문서를 고치면 `data/knowledge/approved_documents.json`의 해시가 어긋나
**로딩 자체가 막힌다.** 이건 문서 무단 변조를 막는 안전장치이며 정상 동작이다.

**현재 해시 (2026-07-26 기준)**:

| document_id | path | content_sha256 |
|---|---|---|
| `pension-basics` | `docs/20_리서치/연금_기초.md` | `74d7221a4f37b34d1e64ffb9138e88f1a46150f607852125bb5dfe14f11a2170` |
| `pension-tax-credit` | `docs/40_규제/연금계좌_세액공제.md` | `5dafbe86e5fecee127431dcd4e3f10bb6b3b7d88858933517548be9dbadfb698` |
| `retirement-pension-receipt-withdrawal` | `docs/40_규제/퇴직연금_수령_중도인출.md` | `81d9a441e8dcdb43431c38bb17d06db05a43c751370750fa65644980990bb850` |

**갱신 방법** — 해시는 `read_text(encoding="utf-8").strip()` 결과의 SHA-256이다.
`.strip()`을 빼먹으면 값이 달라지니 주의한다.

```python
import hashlib, pathlib
for path in (
    "docs/20_리서치/연금_기초.md",
    "docs/40_규제/연금계좌_세액공제.md",
    "docs/40_규제/퇴직연금_수령_중도인출.md",
):
    raw = pathlib.Path(path).read_text(encoding="utf-8").strip()
    print(path, hashlib.sha256(raw.encode("utf-8")).hexdigest())
```

출력된 해시로 매니페스트의 `content_sha256`을 교체한다.
문서를 고쳤다면 `as_of_date`도 함께 갱신할지 검토한다.

**검증**:

```python
from backend.app.retrieval.approved_documents import load_approved_documents
docs = load_approved_documents()
print(len(docs))  # 16개 나와야 한다
```

## 5. 라우팅 확인 (코드 수정은 아마 필요 없다)

아래 질문들은 **이미 올바른 주제로 라우팅된다.** 문서만 채우면 답이 좋아진다.

| 질문 | 라우팅되는 주제 | 대상 문서 |
|---|---|---|
| 한도 넘게 넣으면 어떻게 돼? | `tax_limit` | 연금계좌_세액공제.md |
| 1년에 한 번 몰아서 넣어도 돼? | `tax_limit` | 연금계좌_세액공제.md |
| 돈 없을 때 한 달 걸러도 돼? | `tax_limit` | 연금계좌_세액공제.md |
| 급하게 돈 필요하면 담보대출도 돼? | `withdrawal_requirements` | 퇴직연금_수령_중도인출.md |
| 계좌 여러 개 만들어도 돼? | `account_opening` | 연금_기초.md §4-2 |

주제 매핑은 `backend/app/chat/handlers/_shared.py`의 `_knowledge_topic()`에 있다.
각 주제는 `(topic, 검색어, 문서 제목, 헤딩, 필수문자열)`을 반환하며,
**헤딩 문자열이 문서와 정확히 일치해야 그 절이 뽑힌다.**

새 절을 추가하면서 그 절을 답변에 쓰고 싶다면, `_knowledge_topic()`의 헤딩 값을
새 절 제목으로 바꾸거나 새 주제를 추가해야 한다.
**규칙 순서가 곧 우선순위**이므로, 새 규칙은 기존 `위험자산`·`차이|비교` 규칙보다
뒤에 둔다. (앞에 두면 "연금저축펀드 위험자산 한도" 질문을 가로채 회귀가 난다.
선행 작업에서 실제로 겪은 사고다.)

4. `uv run pytest` 결과가 기준선 이상이다.
5. Draft PR이 열렸고 본문에 변경 사실·검증 결과가 한국어로 적혀 있다.

## 8. 하지 말 것

- 문서에 **없는 수치를 코드에 하드코딩**하지 않는다. 숫자의 SSOT는 승인 문서와 규칙 엔진이다.
- **미래 수익·절세 효과를 단정**하지 않는다.
- 특정 금융회사의 담보대출 상품을 **권유하거나 조건을 단정**하지 않는다.
- 사용자 노출 문구에 `교육용`·`목데이터`·`Mock`·`가상`·`샘플 데이터`·`테스트용` 등
  **구현 표식을 쓰지 않는다.**
- 루트 `AGENTS.md`·`CLAUDE.md`는 **이재용만 수정**한다. 건드리지 않는다.
