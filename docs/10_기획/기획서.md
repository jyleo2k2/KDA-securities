# 연금계좌 운용 가이드 — 프로젝트 기획서

> 버전 v2.7 · 2026-07-20 · 5대 핵심 기능·대표 고객 6명/로그인 후보 5명 시연 규칙 반영
>
> 대상: DC형 퇴직연금 · 개인형 IRP · 연금저축계좌
>
> 현재 단계: 핵심 기능·기술 스택 및 기존 Supabase·FSS/NAVER/RAG 원격 검증 완료 / ETF 실데이터 파이프라인·교육용 포트폴리오 엔진 로컬 검증 완료 / ETF 포트폴리오 위험·스트레스 및 원격 통합 대기

## 1. 제품 정의

**세 연금계좌의 자산과 납입 현황을 한곳에서 보여주고, 설명 가능한 AI 가이드·투자전략 비교·타 고객 포트폴리오 참고·세금계산을 연결해 이용자의 연금 운용 판단을 돕는 AI 연금가이드.**

- **문제**: 이용자는 계좌별 규칙, 전체 자산구성, 투자전략, 다른 이용자와의 차이, 세액공제 여지를 한 흐름에서 이해하기 어렵다.
- **타깃**: 연금계좌를 보유했지만 전체 구성과 운용 판단 기준이 부족한 직장인.
- **차별화**: 통합 자산 홈 × 설명 가능한 챗봇 × 계좌 규칙을 지키는 투자전략 × 익명 포트폴리오 참고 × 규칙 기반 세금계산.
- **원칙**: AI는 제안과 설명만 하며 실제 선택·주문은 이용자가 공식 채널에서 직접 수행한다.

> **기능명 상태**: 아래 5개 핵심 기능의 명칭은 2026-07-20 회의 기준 가칭이다. 사용자 테스트 후 메뉴명과 카피는 바꿀 수 있지만 기능의 목적과 이용자 보호 경계는 유지한다.

## 2. MVP 범위

### 골든패스

~~~text
목계좌 선택
→ 홈에서 통합 자산·계좌·납입 현황 확인
→ 홈의 핵심 기능 버튼에서 챗봇·MY투자/투자전략·타 고객 포트폴리오·세금계산 중 목적 선택
→ 챗봇에서 용어·상품·전략·세금 결과 질문
→ MY투자에서 현재 구성을 진단하고 여러 투자전략 비교
→ 타 고객 포트폴리오의 구성·비중을 내 포트폴리오와 비교하거나 시뮬레이션 초안에 적용
→ 세금계산에서 당해연도 납입 현황·공제 대상액·예상 세액공제액 확인
→ 이용자가 근거와 차이를 확인한 뒤 공식 금융회사 채널에서 직접 결정·실행
~~~

### 핵심 기능 P0

| 기능 | 사용자 경험 | MVP 출력 |
|---|---|---|
| **1. 나의 자산 홈(가칭)** | 전체 자산 상태를 보고 2~5번 기능으로 이동 | 총자산, 계좌·자산군 비중, 납입 현황, 일일·주간 가이드, 4개 핵심 기능 버튼 |
| **2. 챗봇(가칭)** | 용어·상품·종목·전략·세금 결과를 질문 | 상품 비교, 뉴스·외부 리서치 요약, 엔진 결과 설명, 근거·출처 |
| **3. MY투자 및 투자전략(가칭)** | 현재 포트폴리오를 진단하고 여러 전략을 비교 | 보유 구성, 규칙·성향 진단, 전략 후보, 변경 전후 비교·시뮬레이션 |
| **4. 타 고객 포트폴리오 따라하기(가칭)** | 익명 포트폴리오를 참고해 내 구성과 비교하고 적용 초안을 만듦 | 익명 목록·상세, 차이 보기, 비중 적용 시뮬레이션 초안 |
| **5. 세금계산(가칭)** | 소득과 연금계좌 납입액을 바탕으로 공제 현황 확인 | 공제율, 공제 대상 납입액, 남은 한도, 예상 세액공제액, 산식·출처 |

#### 1) 나의 자산 홈(가칭)

- DC형·IRP·연금저축을 합산한 자산군 원그래프와 계좌별 비중을 표시한다.
- 총자산, 평가손익, 계좌별 잔액, 자산군 비중, 당해연도 연금저축·IRP 납입 현황을 한 화면에서 요약한다.
- 챗봇, MY투자 및 투자전략, 타 고객 포트폴리오, 세금계산으로 이동하는 4개 핵심 기능 버튼을 제공한다.
- 일일 가이드는 당일 시장 일정과 포트폴리오 점검 항목을 짧게 제공한다.
- 주간 이상 가이드는 공식 지표와 기관 전망을 사실·전망·해석으로 구분한다.
- 모든 정보에 출처·기준일·업데이트 시각을 표시한다.

#### 2) 챗봇(가칭)

- 연금상품의 용어·특징·위험·비용·계좌 적격성을 설명하고 비교한다.
- 검색 종목·상품의 뉴스 사실과 외부 애널리스트 의견을 출처별로 구분한다.
- 목투자성향·기간·계좌 규칙에 맞는 자산군 전략과 세금계산 엔진 결과를 설명한다.
- 홈·MY투자·타 고객 포트폴리오·세금계산에서 보고 있던 결과를 대화 맥락으로 넘겨 후속 질문할 수 있게 한다.
- 사용자 요청상 ‘예상수익률’은 **미래 예측값이 아닌 승인된 가정의 시나리오 범위**로만 표시하며 손실 가능성을 함께 제시한다.

#### 3) MY투자 및 투자전략(가칭)

- 현재 보유 계좌·상품·자산군 비중과 평가 현황을 통합·계좌별로 제공한다.
- 투자성향, 은퇴까지의 기간, 계좌별 상품 적격성, DC형·IRP 위험자산 한도를 기준으로 현재 구성을 진단한다.
- 안정형부터 공격투자형까지 승인된 전략 후보를 동일한 기준으로 비교하되 이용자의 성향 밖 전략은 추천하지 않는다.
- 전략별 목표 자산군 비중, 현재 구성과의 차이, 과거 데이터 기반 위험지표, 스트레스 시나리오와 적용 근거를 제공한다.
- ‘전략 적용’은 실제 주문이 아니라 **변경 후 구성을 확인하는 시뮬레이션 초안 저장**을 뜻한다.

#### 4) 타 고객 포트폴리오 따라하기(가칭)

- 계좌 조합·연령대·성향·기간으로 익명 포트폴리오를 탐색한다.
- 비중·위험·과거 기간수익률을 동일 기준으로 비교한다.
- 상세 화면에서 자산군·ETF·운용사별 구성과 비중, 과거 성과 기준일, 위험지표를 확인한다.
- 기본 흐름은 **내 포트폴리오와 차이 보기 → 내 성향·계좌 규칙 검사 → 비중 적용 시뮬레이션 초안 생성**이다.
- ‘따라하기’는 타 고객의 실제 거래를 자동 추종하거나 상품을 원클릭 주문한다는 뜻이 아니다. 금액이 아니라 공개 가능한 구성·비중만 참고한다.
- 성향 밖 상품, 계좌 부적격 상품 또는 DC형·IRP 위험자산 한도 위반 구성은 그대로 적용하지 않고 경고·제외·대체 검토 대상으로 표시한다.
- MVP는 공개용 목데이터를 사용한다. 실제 이용자 게시·팔로우와 주문 연결은 후속 검토 범위다.

**대표 고객 6명·로그인 후보 5명 시연 규칙**

- 대표 시나리오 고객 6명은 모두 데이터와 계정을 유지한다. 이 중 1~5번 고객만 시연 로그인 후보이며, 6번 `pension_payout_transition` 고객은 로그인 후보에서 제외한다.
- 시연자는 로그인 후보 5명 중 그날 사용할 고객 1명을 임의로 선택해 해당 계정으로 로그인한다. 앱이 무작위로 계정을 선택하거나 자동 로그인하는 기능은 만들지 않는다.
- 타 고객 포트폴리오 목록은 로그인한 고객의 식별자를 제외하고 나머지 대표 고객 5명만 동적으로 조회한다.
- 로그인 후보 1~5번은 신한증권 개인 일반투자자 배점표 기반 5개 성향(안정형·안정추구형·위험중립형·적극투자형·공격투자형)을 한 명씩 담당한다. 안정형만 6번 고객과 중복되며 중복 고객은 시연 로그인 후보에서 제외한다.
- 목록에는 5명의 가명·연령대·투자성향·대표 자산군·동일 기간의 과거 수익률·추천(좋아요) 수와 각 고객이 1~2문장으로 직접 쓴 형식의 투자 이유·투자의견 및 운용 후기를 나열한다. 수익률에는 산정 기간·기준일·계산식·목데이터·미래 예측 아님을 함께 표시하고, 좋아요 수는 수익률과 무관한 합성 참여지표로 구분한다. 후기에는 실제 보유 ETF 중 성향과 판단을 잘 설명하는 1~2개 종목의 대표 테마를 표시하고, 자연스러운 경우 투자기간에 관찰한 국제정세·산업 흐름과 변동 위험을 함께 설명한다. 각 항목을 펼치거나 상세 화면에 들어가면 계좌 구성, ETF·운용사, 자산군, 평가 비중, 위험지표와 기준일을 확인할 수 있다.
- 로그인 계정을 다른 후보 고객으로 바꾸면 제외되는 본인과 표시되는 5명도 함께 바뀐다. 6번 고객은 로그인 후보가 아니지만 타 고객 포트폴리오에는 포함될 수 있다. 특정 고객 1명을 기준으로 목록을 하드코딩하지 않는다.
- 여섯 고객은 모두 발표·학습용 목데이터이며 실제 고객으로 오해할 수 없도록 목록과 상세에 `대표 시나리오 목데이터` 칩을 표시한다.

#### 5) 세금계산(가칭)

- 이용자의 귀속연도, 소득 유형, 총급여액 또는 종합소득금액, 당해연도 연금저축·개인형 IRP 공제 대상 개인 납입액을 입력으로 사용한다.
- 총급여액 5,500만원 이하 또는 종합소득금액 4,500만원 이하이면 지방소득세 포함 효과 16.5%, 그 밖에는 13.2%를 적용한다.
- 연금저축 세액공제 대상 인정액은 연 600만원, 연금저축과 퇴직연금계좌의 합산 세액공제 대상 인정액은 연 900만원을 넘지 않도록 계산한다.
- 연금저축과 개인형 IRP의 합산 연간 납입한도 1,800만원을 별도로 안내하고, **납입한도와 세액공제 대상 한도를 구분**한다.
- 현재 공제 대상 납입액, 한도 진행률, 계좌별 인정액·초과액, 남은 공제 대상 한도, 예상 세액공제액과 산식을 제공한다.
- 예상 세액공제액은 규칙 엔진 계산값이며 실제 환급액을 확정하거나 추가 납입을 권유하지 않는다. 귀속연도·소득구간·기준일·공식 출처를 함께 표시한다.

### 공통 기반

- 대표 고객 6명의 목계좌·목성향·소득·당해연도 납입액·로그인 매핑·공개용 목포트폴리오
- 계좌별 규칙, 통합 집계, 성향·위험자산·납입·세액공제 한도 가드레일
- 실데이터·목데이터·가정값 구분
- 출처·기준일·권리상태와 LLM 답변 검증
- 익명화·금액 마스킹·감사 로그

### 부가기능

- **P1**: 상세 계좌 진단 고도화, 적립 시뮬레이션, 체크리스트·알림, 퀴즈·미션, 즐겨찾기
- **P2**: 실계좌 연동, 실제 이용자 게시, 등록업무 범위의 개인화 자문, 주문 연결, 자동운용

부가기능의 후보와 보류 사유는 [확장 아이디어](./확장_아이디어.md)에서 관리한다.

## 3. 사용자 경험

MVP의 기본 진입 구조는 **홈의 4개 핵심 기능 버튼**이다. 하단 탭 명칭과 배치는 사용자 테스트 후 확정한다.

- 홈은 전체 상태와 정기 가이드, 챗봇·MY투자/투자전략·타 고객 포트폴리오·세금계산의 출발점이다.
- 각 기능은 현재 화면의 계좌·전략·세금계산 맥락을 챗봇에 넘겨 바로 후속 질문할 수 있게 한다.
- MY투자는 현재 구성 → 진단 → 전략 비교 → 변경 시뮬레이션 순서로 보여준다.
- 타 고객 포트폴리오는 수익률 순위보다 구성·위험·내 포트폴리오와의 차이를 먼저 보여준다.
- 대표 고객 시연에서는 선택한 로그인 고객을 제외한 다른 대표 고객 5명을 목록에 표시하고, 계정 전환 시 목록을 다시 구성한다.
- 세금계산은 입력값 → 적용 규칙 → 계산 결과 → 남은 한도 순서로 계산 근거를 추적할 수 있게 한다.
- 주요 CTA는 주문·납입 실행이 아니라 비교, 시뮬레이션 초안 저장, 공식 정보 확인이다.

화면과 분기는 [화면·유저 플로우](./화면_유저플로우.md)를 따른다.

## 4. 계산·데이터·AI 원칙

- 계산·한도 판정·성향 분류·전략 선택·세액공제 계산은 규칙 엔진이 담당한다.
- LLM은 엔진 결과와 검증된 외부 정보를 설명하며 새 숫자·목표가·매매의견을 만들지 않는다.
- 시장·제도·상품·기준연도 세제 규칙은 공식 실데이터, 사용자 계좌·소득·납입액과 공개 포트폴리오는 MVP 목데이터를 사용한다.
- 뉴스·리포트는 사실과 의견을 분리하고 발행기관·발행일·원문·이용권 상태를 보존한다.
- DC형·IRP 규칙과 연금저축 적격성 규칙을 분리한다.
- 세금계산은 납입한도, 세액공제 대상 한도, 예상 세액공제액, 실제 환급액을 서로 다른 개념으로 표시한다.

기술 계약은 [아키텍처](../30_스펙/아키텍처.md), 장기 계획가정은 [ETF 장기 계획수익률 모델](../30_스펙/ETF_장기_계획수익률_모델.md)에서 관리한다. 폐기된 연령별 고정수익률 표는 엔진 입력으로 사용하지 않는다.

## 5. 이용자 보호 경계

MVP에서 제공하지 않는다.

- AI 자체 매수·매도·목표가와 확정적 시장 전망
- 수익 보장 또는 단일 미래 예상수익률
- 성향·계좌 규칙을 벗어난 전략
- 실제 계좌·개인정보 수집, 주문, 자동 리밸런싱
- 타 고객 포트폴리오의 자동 추종·일괄 복제와 추가 납입 권유
- 예상 세액공제액을 실제 세액 또는 환급액으로 확정하는 표현
- 뉴스·리포트 원문의 무단 복제
- 실명·정확한 잔액 공개와 원클릭 복사 주문

실서비스 전 투자자문·권유, 적합성·설명의무, 개인정보, 콘텐츠 권리와 게시물 운영을 다시 검토한다. 상세 기준은 [컴플라이언스](../40_규제/컴플라이언스.md)를 따른다.

## 6. MVP 완료 기준

- [ ] 세 계좌 합계와 통합 원그래프가 일치한다.
- [ ] 홈에서 현재 자산·계좌·납입 요약을 확인하고 나머지 4개 핵심 기능에 진입할 수 있다.
- [ ] 일일·주간 가이드에 출처·기준일과 사실/전망 구분이 있다.
- [ ] 챗봇 수치와 의견이 엔진 또는 원 출처와 일치한다.
- [ ] MY투자의 전략 후보와 적용 초안이 성향·계좌 규칙을 준수하고 손실 가능성을 함께 표시한다.
- [ ] 타 고객 포트폴리오에 식별정보·정확한 잔액·복사 주문 CTA가 없고, 비중 적용 전 내 계좌 규칙을 검사한다.
- [ ] 대표 고객 6개 계정 중 어느 계정으로 로그인해도 본인은 목록에서 제외되고 다른 고객 5명만 중복 없이 표시된다.
- [ ] 로그인 계정을 바꾸면 타 고객 목록이 해당 계정 기준으로 다시 구성되며 특정 고객 기준의 하드코딩이 없다.
- [ ] 목록의 5명 모두 상세 포트폴리오에 진입할 수 있고 계좌·ETF·운용사·자산군 비중·위험지표·기준일과 목데이터 표시를 확인할 수 있다.
- [ ] 연금저축 공제 대상 인정액 600만원, 합산 공제 대상 인정액 900만원, 합산 납입한도 1,800만원이 구분된다.
- [ ] 소득구간별 16.5%·13.2% 예상 세액공제 결과가 규칙 엔진 테스트와 일치한다.
- [ ] 세금계산에 귀속연도·입력값·산식·기준일·공식 출처와 실제 환급액 비보장 문구가 표시된다.
- [ ] 이용자가 자신의 구성, 전략 근거, 타 고객과의 차이, 세액공제 계산 근거를 설명할 수 있다.

## 7. 구현 순서와 미확정

### 데이터 기반 구현 상태

| 번호 | 범위 | 현재 상태 |
|---|---|---|
| 1 | DB·스택 확정 | Supabase PostgreSQL/pgvector와 FastAPI 데이터 경계를 확정했다. |
| 2 | 스키마·마이그레이션 | 사용자·계좌·공시·규칙·감사·뉴스·RAG·챗봇 테이블, RLS와 인덱스를 구현하고 SQL 구문을 검증했다. |
| 3 | 목데이터 | 대표 고객 시나리오 6명과 고정 Auth 사용자·로그인 매핑을 준비했다. 기존 원격 목데이터는 6명·13계좌·26보유이며, 대표 ETF 상세화 결과 6명·13계좌·86보유는 로컬 검증 후 원격 적용 대기 상태다. |
| 4 | 공시 실데이터 | 통합연금포털 API 직접 호출·정규화·upsert 경로를 구현했다. 연금저축 88건과 퇴직연금 42개사·126행을 실호출·원격 적재로 확인했으며 fixture는 테스트 전용이다. |
| 5 | 규칙 엔진 골든패스 | DC형·IRP 위험자산 70% 한도와 법정 예외, 연금저축 분리 규칙, 근거 칩을 구현했다. |
| 6 | 규칙·감사 연결 | 규칙 버전·파라미터와 인증 사용자·실행 ID 기반 감사 저장 API를 구현했다. 원격 RLS·Data API 최소 권한과 사용자 소유권 격리를 검증했다. |
| 7 | 뉴스·RAG 기반 | NAVER 뉴스 저장, 지식 문서·청크 적재, 검색 저장소와 챗봇 출처 구조를 구현하고 BGE-M3 임베딩과 하이브리드 검색을 원격 검증했다. |
| 8 | ETF 분류·적격성 | 현재 상장·관측충분 945개를 분류하고 연금계좌 적격 861개, DC·IRP 적격 823개씩을 계좌별 파일로 분리했다. |
| 9 | 시장·종목 이벤트 | KRX ETF·대표 지수 8종, 한투 수정주가 897,330개 관측, KIND 현금분배·분배락, DART·법령 근거를 결합했다. 현금분배 8,048건 중 8,029건에 정확한 분배락일을 연결했다. |
| 10 | 총수익률·비용 | 연금 적격 ETF 861개의 계좌별 과거 총수익률·비용·유동성·추적품질 마스터를 생성했다. 미래수익률로 외삽하지 않는다. |
| 11 | 교육용 포트폴리오 | 대표 연령 4개 × 은퇴 시작 나이 2개 × 성향 5개 × 계좌 3개의 120개 시나리오를 생성했다. DC·IRP 위험자산 한도 위반과 후보 슬리브 누락은 0건이며 위험·상관관계는 한투 수정주가와 KIND 현금분배를 결합해 산출한다. |

Python 전체 테스트와 Ruff를 기준으로 로컬 검증하며, ETF 산출물의 로컬 성공은 해당 데이터의 원격 Supabase 통합 검증을 대신하지 않는다.

### 제품·UI 구현 순서

1. 포트폴리오 단위 변동성·하락위험·스트레스 산출
2. ETF 산출물과 규칙·출처 계약을 원격 Supabase에서 검증
3. 나의 자산 홈과 4개 핵심 기능 진입 구조
4. 구현된 챗봇 질문 유형과 화면별 후속 질문 연결
5. MY투자 현재 구성·진단·전략 비교·적용 시뮬레이션
6. 로그인한 대표 고객을 제외한 나머지 5명의 목록·상세·차이 보기·비중 적용 시뮬레이션
7. 세금계산 입력·납입현황·한도·예상 세액공제 화면
8. 5개 기능의 공통 검증과 사용자 과업 테스트

### 확정이 필요한 항목

- 대상 Supabase 프로젝트와 원격 마이그레이션 시점
- 5개 핵심 기능의 최종 이름, 하단 탭·홈 버튼의 정보구조
- ‘타 고객 포트폴리오 따라하기’의 사용자 노출 명칭과 시뮬레이션 초안 저장 범위
- 일일·주간 가이드의 기관·기간·갱신주기
- 뉴스·애널리스트 리포트 이용권
- 승인된 장기 계획가정(CMA)과 갱신·표현 정책
- 포트폴리오 위험·스트레스 정책 상한과 검증 기준
- 공개 필드·성과표시·신고 정책
- 세금계산의 종합소득자 입력 UX, 기준연도별 세제 규칙 갱신·검수 담당자
