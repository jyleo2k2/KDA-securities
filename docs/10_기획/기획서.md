# 연금계좌 운용 가이드 — 프로젝트 기획서

> 키움 디지털 아카데미 1차 프로젝트 · 투자·자산관리 주제
>
> 문서 버전: v2.3 · 갱신일: 2026-07-14
>
> 대상 계좌: **DC형 퇴직연금 · 개인형퇴직연금(IRP) · 연금저축계좌**
>
> 현재 단계: 핵심 기능·기술 스택 확정 / 데이터 기반 1~7 코드·로컬 계약 검증 완료(원격 Supabase 적용·통합검증 대기)

## 1. 제품 정의

### 1.1 한 줄 정의

**세 연금계좌의 통합 포트폴리오를 보여주고, 시장·상품 정보를 근거와 함께 설명하며, 공개 포트폴리오 벤치마킹으로 이용자의 연금 투자 판단을 돕는 AI 연금가이드**

### 1.2 해결할 문제

이용자는 연금계좌를 보유해도 계좌별 규칙, 전체 자산구성, 시장 변화가 자신의 연금에 미치는 영향을 한 흐름에서 이해하기 어렵다.

- DC형·IRP·연금저축은 납입 주체, 세제, 인출 조건과 위험자산 규칙이 다르다.
- 여러 계좌를 따로 보면 전체 주식·채권·현금성 비중과 중복 노출을 파악하기 어렵다.
- 뉴스·경제지표·애널리스트 리포트가 흩어져 있어 연금 관점의 해석이 어렵다.
- 금융상품 용어와 상품별 특징이 복잡해 검색 이후에도 비교 기준이 남지 않는다.
- 다른 이용자의 구성을 참고하고 싶어도 수익률 자랑이나 단순 따라 사기로 흐르기 쉽다.

이 프로젝트는 다음 세 질문에 답한다.

1. **내 연금 포트폴리오는 지금 어떻게 구성되어 있는가?**
2. **오늘과 이번 주의 시장·상품 정보가 내 연금 판단에 어떤 의미인가?**
3. **비슷한 이용자와 공개 포트폴리오를 비교하면 무엇을 점검할 수 있는가?**

### 1.3 핵심 타깃과 페르소나

1차 타깃은 **DC형·IRP·연금저축계좌 중 하나 이상을 보유하고, 직접 판단할 의향은 있지만 계좌 규칙과 시장·상품 정보를 연결하기 어려운 직장인**이다.

대표 페르소나 `김직장(35세)`:

- 회사 DC형, IRP, ETF를 보유한 연금저축계좌가 있다.
- 세 계좌를 합산한 자산군 비중과 중복 노출을 모른다.
- 시장 뉴스는 보지만 자신의 연금 포트폴리오에 어떤 의미인지 해석하기 어렵다.
- 상품 검색 시 용어·특징·리스크·리서치 의견을 한곳에서 비교하고 싶다.
- 다른 이용자의 배분을 참고하되 그대로 따라 사기보다 자신의 전략을 점검하고 싶다.

### 1.4 핵심 가치

| 핵심 기능 | 사용자 가치 | 서비스 역할 |
|---|---|---|
| 내 연금 포트폴리오 홈 | 세 계좌의 전체 구성을 한눈에 파악 | 원그래프, 일일 가이드, 주간 이상 매크로 전망 가이드 |
| 연금가이드 챗봇 | 제도·상품·시장 정보를 질문하고 근거 확인 | 용어·특징 비교, 종목·상품 정보 요약, 포트폴리오 전략 설명 |
| 공개 포트폴리오 | 다른 이용자 구성을 안전하게 벤치마킹 | 익명·동의 기반 공유, 유사 집단 비교, 차이 해석 |

> 서비스가 직접 매매하거나 수익을 보장하지 않는다. AI는 출처가 있는 정보와 규칙 엔진 결과를 설명하고, 실제 상품 선택과 주문은 이용자가 금융회사 공식 채널에서 직접 한다.

### 1.5 범위 해석

- **매크로 전망**은 AI가 시장을 예언하는 기능이 아니다. 공신력 있는 경제지표·기관 전망·리서치를 기간과 출처별로 요약하고 상승·기준·하락 시나리오를 구분한다.
- **투자의견 상세정보**는 AI가 새 매수·매도 의견을 만드는 기능이 아니다. 뉴스 사실, 애널리스트 의견, 컨센서스와 위험요인을 출처·발행일과 함께 구조화한다.
- **추천 포트폴리오 전략**은 규칙 엔진이 만든 자산군 단위 전략이다. 아카데미 MVP에서는 목성향·목계좌만 사용하며 특정 상품 주문 지시를 하지 않는다.
- **예상수익률**은 예측값이나 보장값이 아니라 명시된 자산군 가정으로 계산한 시나리오 범위다. 원금·가정수익·손실 가능성을 함께 표시한다.
- **공개 포트폴리오**는 공개 동의, 익명화, 금액 마스킹과 신고·검수 원칙을 전제로 한다. MVP에서는 실제 이용자 정보 대신 공개용 목포트폴리오로 시연한다.

### 1.6 하지 않는 것

- LLM이 독자적으로 생성한 매수·매도·목표가 의견
- 미래 수익률·시장 방향·손실 회복의 확정 또는 보장
- 성향을 벗어난 전략과 계좌 규칙을 위반한 자산배분
- 실제 계좌 연결, 주문, 자동 리밸런싱과 계좌 이전
- 애널리스트 리포트·뉴스 원문을 허가 없이 장문 복제하거나 재배포
- 동의 없는 포트폴리오 공개, 실명·정확한 잔액·계좌번호 노출
- 공개 포트폴리오의 원클릭 복사·주문 또는 수익률 순위만을 이용한 추종 유도
- 개인별 확정 절세액·세금·인출 순서 최적화

상세 규제 경계는 [금융권 규제 및 컴플라이언스 고려사항](../40_규제/컴플라이언스.md)을 따른다.

## 2. MVP 결정

### 2.1 골든패스

```text
데모 세션 진입·연금계좌 선택
  → 홈에서 세 계좌 통합 포트폴리오 원그래프 확인
  → 오늘의 연금 점검 가이드 확인
  → 주간 이상 매크로 전망과 자산군 영향 확인
  → 연금가이드 챗봇에서 용어·상품·종목 정보 검색
  → 목성향 기반 포트폴리오 전략과 가정수익 범위 확인
  → 공개 포트폴리오에서 유사 이용자 구성을 벤치마킹
  → 금융회사 공식 정보 확인 후 사용자가 직접 결정
```

> **통합 포트폴리오 × 출처 기반 투자정보 × 설명 가능한 전략 × 안전한 공개 벤치마킹**

### 2.2 핵심 기능과 부가기능

#### 핵심 기능 P0 — 반드시 완성

##### 1. 내 연금 포트폴리오 홈

- DC형·IRP·연금저축계좌를 합산한 자산군 비중을 원그래프로 표시한다.
- 총평가금액, 계좌별 비중, 현금성·주식·채권·혼합 비중과 주요 중복을 보여준다.
- **일일 가이드**는 당일 확인할 시장 일정·위험요인·포트폴리오 점검 항목을 짧게 제공한다.
- **주간 이상 매크로 전망 가이드**는 공식 경제지표와 기관·리서치 전망을 요약하고 자산군별 가능 영향을 시나리오로 설명한다.
- 모든 카드에 데이터 유형, 기준일, 출처, 업데이트 시각을 표시한다.

##### 2. 연금가이드 챗봇

세 가지 질문 유형을 지원한다.

1. **연금상품 용어·특징 설명과 비교**
   - DC형·IRP·연금저축, ETF·TDF·펀드·예금 등 용어와 계좌별 제약을 설명한다.
   - 비교 기준은 역할·위험·비용·유동성·계좌 적격성이다.
2. **검색 종목·상품 투자의견 상세정보**
   - 뉴스와 애널리스트 리포트에서 확인되는 사실·의견·컨센서스·위험요인을 분리한다.
   - 출처, 발행기관, 발행일, 기준 가격일과 정보 지연 여부를 표시한다.
   - AI 자체 매수·매도 의견이나 목표가를 만들지 않는다.
3. **성향 기반 포트폴리오 전략과 가정수익 범위**
   - 규칙 기반 성향·기간 결과에 따라 자산군 단위 전략을 제시한다.
   - DC형·IRP 한도와 연금저축 적격성 규칙을 먼저 적용한다.
   - 예상수익률은 엔진 가정에 따른 범위로 표시하고 변동성·손실 시나리오를 함께 보여준다.

##### 3. 공개 포트폴리오 벤치마킹

- 이용자가 공개에 동의한 연금 포트폴리오를 익명으로 공유하고 비교한다.
- 계좌 조합, 연령대, 투자성향, 투자기간 등 최소 필터로 유사 포트폴리오를 탐색한다.
- 자산군 비중, 위험 수준, 과거 기간수익률, 점검 행동을 비교하되 정확한 잔액과 식별정보는 숨긴다.
- ‘복사하기’ 대신 **내 포트폴리오와 차이 보기**를 기본 CTA로 둔다.
- 신고·차단·운영 검수와 과장 수익률 방지 기준을 둔다.
- 정보구조상 핵심 기능이므로 **하단 전용 탭 `벤치마크` 배치안을 우선 검토**한다. 최종 위치는 Figma 확정 전 `TODO: 확인 필요`로 남긴다.

#### 핵심 기능을 위한 공통 기반

다음은 별도 핵심 상품이 아니라 세 핵심 기능이 작동하기 위한 필수 기반이다.

- 데모 로그인·온보딩·계좌 선택
- 계좌별 규칙 검사와 통합 집계
- 목계좌·목성향·공개용 목포트폴리오
- 뉴스·리포트·경제지표의 수집 시각·출처·라이선스 메타데이터
- 모든 화면의 실데이터/목데이터·기준일·출처 표시
- 개인정보 마스킹, 성향·규칙 위반 차단, 감사 로그

#### 부가기능 P1 — 핵심 기능 완성 후 구현

- 계좌 역할·규칙 상세 비교
- 계좌별 편중·한도·중복 상세 진단
- 동일 연령대·성향별 통계 비교 카드
- 적립 what-if와 하락장 스트레스 테스트 상세 화면
- 다음 행동 체크리스트와 점검일 알림
- 연금 퀴즈·미션·학습 진도
- 공개 포트폴리오 팔로우·즐겨찾기
- 검증된 교육 콘텐츠 피드
- Profile·설정·공개 범위 관리

#### P2 — 실제 서비스 확장 검토

- 실제 계좌·마이데이터 연동
- 실시간·유료 뉴스와 리포트 라이선스 계약
- 실제 이용자 포트폴리오 게시·댓글·운영 도구
- 등록업무 범위와 적합성·설명의무를 충족한 개인화 상품 자문
- 금융회사 주문 연결과 계좌 이전
- 자동 리밸런싱·투자일임

## 4. 규칙 엔진·데이터·AI 설계

### 4.1 시스템 구조

```text
[React + TypeScript + Vite 모바일 PWA]
      │ REST
[FastAPI API·오케스트레이션]
      ├─ 포트폴리오·계좌 규칙 엔진 6모듈
      ├─ FSS 공시·NAVER 뉴스 수집/조회
      ├─ PostgreSQL 구조화 데이터 조회
      ├─ 공식 문서 RAG 검색(PostgreSQL 전문검색 + pgvector)
      └─ Claude API 설명·Q&A 하네스
      │
[Supabase PostgreSQL]
      ├─ 공시·목계좌·규칙·실행 근거·뉴스 메타데이터
      └─ 공식 지식 문서·청크·embedding
      │
[출처·기준일·감사 로그가 포함된 화면 출력]
```

> Supabase는 PostgreSQL·pgvector의 실행 기반이다. 현재 완료 표시는 로컬 코드·마이그레이션·테스트 범위에 한정하며, 원격 프로젝트 마이그레이션과 실데이터 적재는 연결 후 별도로 검증한다.

### 4.2 계산·판단 책임

- 계좌 분류, 자산군 분류, 비중·중복·한도 계산은 규칙 엔진이 수행한다.
- 성향 분류와 자산군 전략 선택은 버전형 기준표가 수행한다.
- 가정수익률·변동성·충격값은 승인된 가정 테이블에서만 가져온다.
- 뉴스·리포트의 의견 주체와 발행일을 보존하고 사실과 의견을 분리한다.
- 공개 포트폴리오 비교는 익명·지연·마스킹된 필드만 사용한다.
- 정확한 공시 수치·최신 뉴스 목록은 SQL/API로 조회하고, RAG는 검증된 공식 문서의 의미·제도·근거를 찾는 데 사용한다.
- 사용자 목계좌·성향·진단 결과는 구조화 SQL 데이터이며 RAG 문서나 embedding에 포함하지 않는다.
- LLM은 엔진 결과와 검색 근거를 요약·비교·설명하며 새 숫자·목표가·매매의견을 만들지 않는다.

### 4.3 데이터 경계

| 데이터 | MVP 구분 | 용도 |
|---|---|---|
| 통합연금포털(FSS) OpenAPI 공시 | 실데이터 | 서버가 직접 호출한 원본·정규화 수익률·수수료·적립금과 수집 이력 |
| 정부·KRX·금융회사 공개정보 | 실데이터 | 제도·상품·비용·시장 근거와 FSS 보조 |
| NAVER 검색 API 뉴스 | 실데이터 메타데이터 | 제목·요약·원문 링크·발행일을 이용한 최신 뉴스 조회·단기 캐시 |
| 정부·공공기관 공식 문서 | 검증 지식 데이터 | 제도·용어·규칙 근거를 위한 RAG 문서·청크·embedding |
| 기관 전망·리포트 메타데이터 | 실데이터 또는 라이선스 확인 데이터 | 일일·주간 가이드와 상품 정보 |
| 계좌 시나리오 3종 | 목데이터 | 내 연금 포트폴리오 |
| 투자성향·기간 입력 | 데모 입력 | 전략 범위 제한 |
| 공개용 이용자 프로필·포트폴리오 | 목데이터 | 벤치마킹 시연 |

FSS fixture는 파서·회귀 테스트에만 사용한다. 공시 테이블의 실 적재 결과는 API 실호출에서 생성하고, `ingestion_runs`에 호출 종류·조회기간·수집시각·건수·상태를 남긴다. NAVER 뉴스는 MVP에서 기사 전문을 저장·임베딩하지 않는다.

### 4.4 저장·검색 경계

| 질문·데이터 | 처리 책임 |
|---|---|
| 공시 수익률·수수료·적립금 조회 | PostgreSQL 정규화 공시 테이블 |
| 사용자 목계좌·보유자산·진단 결과 | PostgreSQL 구조화 테이블 + 규칙 엔진 |
| 최신 뉴스 목록 | NAVER 검색 API + 뉴스 메타데이터 테이블의 날짜 정렬 |
| 제도·용어·규칙 근거 질문 | 공식 문서 RAG + 출처 필터 |
| 계산 결과의 자연어 설명 | 규칙 엔진 출력 + RAG 근거를 받은 Claude API |

핵심 데이터 그룹은 출처·수집(`data_sources`, `ingestion_runs`), 공시, 목계좌, 규칙 버전, 엔진 실행·근거, 공식 지식 문서·청크, 챗봇·뉴스 메타데이터로 분리한다. 실제 테이블명과 제약은 [기술 아키텍처](../30_스펙/아키텍처.md)를 따른다.

- 과장 수익률·선별 기간·이해상충·자사상품 우선 노출 통제

## 6. 검증 기준

### 6.1 기능·데이터

- [ ] 세 계좌 포트폴리오 원그래프의 합계가 100%이며 계좌별 합계와 일치한다.
- [ ] 일일·주간 가이드에 출처·기준일·업데이트 시각이 있다.
- [ ] 매크로 카드가 사실·외부 전망·서비스 해석을 구분한다.
- [ ] 종목·상품 답변의 모든 투자의견에 발행기관·발행일·원문 링크가 있다.
- [ ] 챗봇이 출처에 없는 목표가·매매의견·수익률을 생성하지 않는다.
- [ ] 전략과 가정수익 범위가 성향·기간·계좌 규칙을 준수한다.
- [ ] 가정수익과 손실 시나리오가 같은 화면에 표시된다.
- [ ] 공개 포트폴리오에 실명·정확한 잔액·계좌번호가 없다.
- [ ] 공개 포트폴리오 화면에 복사 주문 CTA가 없다.
- [ ] 실데이터·목데이터·가정값이 화면에서 구분된다.

### 6.2 사용자 과업

5~8명의 테스트 이용자가 다음을 수행할 수 있어야 한다.

- 자신의 전체 연금 포트폴리오에서 가장 큰 자산군을 찾는다.
- 오늘의 가이드와 주간 전망 중 사실과 전망을 구분한다.
- 검색한 상품의 특징·위험·비용·계좌 적격성을 설명한다.
- 전략의 가정수익률이 보장값이 아님을 설명한다.
- 공개 포트폴리오와 자신의 구성 차이를 한 가지 찾는다.
- 실제 주문이 서비스 밖에서 이루어짐을 이해한다.

### 6.3 발표 시연

1. 홈 원그래프에서 전체 연금자산 구성을 설명한다.
2. 일일·주간 가이드의 출처와 시나리오를 연다.
3. 챗봇에서 연금 용어와 검색 상품 정보를 질문한다.
4. 목성향 전략의 근거와 가정수익·손실 범위를 보여준다.
5. 공개 포트폴리오와 내 포트폴리오의 차이를 비교한다.

| 4 | 통합연금포털 OpenAPI 실호출 후 공시 원본·정규화 적재 | 수집·upsert 코드 완료, 직접 호출 88개사/42개사·126행 확인; 원격 적재 대기, fixture는 테스트 전용 |
| 5 | 계좌 규칙 검사 중심의 규칙 엔진 골든패스 | 로컬 완료: DC·IRP 70%, 연금저축 미적용, 적격 예외 분리 |
| 6 | 엔진 실행 결과와 규칙·출처·수집 근거 연결 | 코드 완료: 규칙 버전·파라미터 대조, Supabase 인증 uid·run_id 연결; 원격 RLS 검증 대기 |
| 7 | 공식 문서 RAG·챗봇·NAVER 뉴스 메타데이터 스키마와 검색 골든패스 | 기반 코드 완료: 지식·청크 seed/writer, 전문검색, pgvector 자리, 뉴스 fetch/upsert, 근거 연결; 실제 PostgreSQL 검색·embedding 검증 대기 |

전체 로컬 검증은 `uv run pytest` 27건, Python 린트, migration·seed·내장 SQL 파싱을 통과했다. 이는 PostgreSQL에 실제 적용한 통합 테스트가 아니다. 원격 Supabase 프로젝트의 마이그레이션·seed 실행·RLS·실호출 적재·RAG 검색은 대상 프로젝트 확인과 실제 조회 검증이 끝난 뒤 완료 처리한다.

## 8. 로드맵과 미확정 사항

### 8.1 단계별 깊이

1. **Phase 1 — 아카데미 MVP**: 목계좌 홈, FSS/NAVER 공개 데이터 골든패스, 공식 문서 RAG 제한형 챗봇, 목 공개 포트폴리오
2. **Phase 2 — 콘텐츠·운영 고도화**: 원격 Supabase 운영, 수집 스케줄·재시도·모니터링, 라이선스 확보 콘텐츠, 공개 동의·신고·검수, 알림
3. **Phase 3 — 실서비스 검토**: 실계좌, 실제 이용자 공개 포트폴리오, 등록업무 범위 내 개인화 자문
4. **Phase 4 — 별도 승인 영역**: 주문 연결·자동 리밸런싱·투자일임
