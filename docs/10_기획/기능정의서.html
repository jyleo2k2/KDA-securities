01

제품 범위와 고정 원칙

기획 변경이나 화면 카피보다 우선하는 기능 경계입니다.

제품 한 줄 정의

DC형 퇴직연금·IRP·연금저축의 전체 자산구성과 계좌별 제약을 설명하고, 뉴스·상품 정보·전략 비교·세금계산을 연결해 이용자가 스스로 운용 결정을 내리도록 돕는 모바일 연금계좌 운용 가이드입니다.

행위 경계

정보·자문형 콘텐츠와 시뮬레이션을 제공하지만 일임·자동매매가 아닙니다. 실제 상품 선택과 주문은 이용자가 금융회사 공식 채널에서 직접 수행합니다.

계산 경계

성향 분류, 한도 판정, 집계, 세금, 계획 시뮬레이션은 규칙 엔진이 계산합니다. LLM은 검증된 결과를 설명하며 새 숫자를 만들지 않습니다.

계좌 규칙

DC·IRP 일반 위험자산은 원칙적으로 70%까지이며 법정 예외를 별도 처리합니다. 연금저축에는 같은 총량 한도를 적용하지 않고 상품 적격성 규칙을 별도로 사용합니다.

성과·위험 표현

수익률과 위험은 과거 실적 또는 승인된 계획 가정으로만 제시하고 기준일·가정·출처를 표시합니다. 미래 수익·손실을 예측하거나 보장하지 않습니다.

데이터 경계

시장·상품은 공식 원천, 뉴스는 NAVER 검색 메타데이터, RAG는 승인 문서, 사용자 계좌는 현재 시연 시나리오 데이터를 사용합니다. 개인 계좌 정보는 RAG에 넣지 않습니다.

모든 수치에는 출처·기준일 또는 가정을 붙이고, 저장된 투자성향 밖 상품은 제안하지 않습니다.

기능정의서 작성 기준

리서치한 요구사항·PRD 원칙을 이 문서 구조에 적용했습니다.

좋은 기능 요구사항의 조건

  • 한 항목에 하나의 기능만 쓰고 ID를 부여합니다.
  • 누가, 왜 쓰는지와 입력·업무 규칙·출력을 함께 적습니다.
  • “적절히”, “빠르게”, “등” 대신 관찰·측정 가능한 수용 기준을 사용합니다.
  • 요구사항 ↔ 화면/API ↔ 코드 ↔ 테스트를 양방향 추적합니다.
  • 가정·제약·비범위와 미결정을 완료 기능에서 분리합니다.

이 프로젝트에 적용한 상태 규칙

  • 완료 main에 코드가 있고 관련 회귀가 통과함
  • 부분 구현 화면·API가 있으나 목표 수용 기준 일부가 없음
  • 대기 문서 계약만 있거나 외부 환경 검증이 남음
  • Draft PR이 열려 있어도 main 완료로 계산하지 않음
  • 비범위 주문·일임·자동운용처럼 의도적으로 제공하지 않음
