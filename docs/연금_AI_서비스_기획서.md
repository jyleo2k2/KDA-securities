# 연금 리부트 — 방치형 DC 계좌 회복 데모 기획서

> 가칭 · 키움 디지털 아카데미 투자·자산관리 프로젝트
>
> 문서 버전: v0.1 · 작성일: 2026-07-13 · 상태: 첫 데모 제안

## 1. 한 줄 정의

**방치된 DC형 퇴직연금 계좌를 진단하고, 또래의 준비 행동·노후 월급·직업 위험·크루 경험을 근거로 설명한 뒤, 사용자가 리밸런싱을 모의 실행하고 개선 결과를 확인하는 연금 행동 코파일럿.**

> **핵심 메시지:** “남이 무엇을 샀는지가 아니라, 내 연금을 오늘 어떻게 다시 움직일지 보여드립니다.”

## 2. 데모 목표

첫 데모는 기능을 나열하지 않는다. **한 명의 방치형 사용자가 자기 계좌를 이해하고, 납득한 뒤, 한 번의 행동을 결정하는 이야기**를 보여준다.

### 이용자 목표

- 내 계좌가 왜 방치 상태인지 이해한다.
- 다른 사람의 상품이 아니라 장기 준비 행동을 참고한다.
- 노후에 필요한 월급과 현재 준비 수준의 차이를 확인한다.
- 내 직업과 연금이 같은 산업에 과도하게 노출됐는지 이해한다.
- 제안의 근거를 확인하고 모의 실행 여부를 직접 결정한다.

### 데모 성공 정의

사용자가 데모 종료 뒤 다음을 자기 말로 설명할 수 있다.

1. 현재 계좌의 가장 큰 문제 1개
2. 리밸런싱 제안의 근거 3개
3. 실제 금융사 앱에서 다음으로 확인할 행동 1개

## 3. 핵심 원칙

- **자문형:** AI는 제안만 하고, 최종 결정과 모의 실행은 사용자가 원탭으로 승인한다.
- **설명 우선:** 모든 제안에는 수치 근거 3개 이상과 출처·가정 칩을 제공한다.
- **규칙 엔진:** 계좌 진단, 적립 계산, 한도 검사, 섹터 노출 계산은 규칙 엔진이 수행한다. LLM은 설명과 Q&A만 담당한다.
- **성향 보호:** 투자성향 밖의 포트폴리오를 제안하지 않는다.
- **한도 강제:** DC형 위험자산 70% 한도를 제안 생성 전에 검사한다.
- **실/목 구분:** 사용자 계좌·또래·크루 후기는 목데이터, 시장 상품 수치와 제도 규칙은 실데이터 또는 공식 규칙으로 명확히 나눈다.

## 4. 데모 주인공과 목데이터

### 페르소나

**김직장, 36세, 반도체 업계 사무직, DC형 계좌 운용 초보**

- 회사에서 DC형 퇴직연금을 선택했다.
- 일반 주식 투자 경험은 있지만 연금계좌는 2년 넘게 점검하지 않았다.
- ‘안전하게 두자’는 생각으로 현금성 자산을 많이 유지했다.
- 과거에 유망하다고 생각한 국내 기술 섹터 상품을 일부 보유하고 있다.
- 은퇴 후 생활비를 구체적으로 계산해 본 적이 없다.

### 계좌 시나리오

아래 계좌는 **데모용 목데이터**다.

| 구분 | 비중 | 의미 |
|---|---:|---|
| 현금성·원리금보장 자산 | 55% | 장기간 운용 기준 없이 유지된 자금 |
| 국내 기술 섹터 관련 위험자산 | 35% | 근무 산업과 중복될 수 있는 노출 |
| 기타 분산 위험자산 | 10% | 소규모 분산 보유 |
| 위험자산 합계 | 45% | DC형 한도 이내이나 구성 점검 필요 |

> `[목데이터: 방치형 DC 계좌 시나리오]`
> 실제 상품명, 실제 보유금액, 실제 사용자 수익률은 데모에 사용하지 않는다.

## 5. 전체 데모 흐름

```text
방치 계좌 감지
  → 또래 준비 행동·과거 가상수익
  → 노후 월급 부족분
  → 직업-연금 중복노출
  → 리밸런싱 제안과 근거
  → 크루 후기 확인
  → 원탭 모의 체결
  → 개선 결과 표시
```

한 화면에는 문제 하나와 행동 하나만 보여준다.

## 6. 단계별 화면과 기능

### 6.1 방치 계좌 감지

**목적:** 사용자가 “내 계좌를 지금 확인해야 하는 이유”를 이해하게 한다.

**화면 메시지**

> “최근 점검 기록이 없고, 적립금의 55%가 운용 기준 없이 현금성·원리금보장 자산에 머물러 있어요.”

**표시 정보**

- 마지막 점검 시점: 목데이터 시나리오 값
- 현금성·원리금보장 자산 비중
- 위험자산 비중과 한도 여유
- ‘먼저 확인할 문제’: 방치 자금 또는 자산군 편중 중 하나

**다음 행동:** `내 계좌의 문제 보기`

### 6.2 또래 준비 행동과 과거 가상수익

**목적:** 상품 추종이 아니라 “지금 점검을 시작할 이유”를 만든다.

#### 또래 준비 행동

다른 이용자의 상품명·수익률·보유비중은 보여주지 않는다.

> “비슷한 은퇴기간의 연금 준비자는 상품을 따라 사기보다, 위험비중·수수료·점검일을 함께 확인해요.”

실제 집계 데이터가 없는 데모에서는 수치 없이 교육 문구만 사용한다. 실사용 단계에서는 연령대·투자성향·운용기간이 같은 익명 집계만 사용한다.

#### 과거 적립 가상체험

> “2년 전부터 매월 일정 금액을 분산 운용했다면, 지금의 적립 경로는 어떻게 달라졌을까요?”

표시 원칙:

- 과거 수익률은 실제 공시·시장 데이터와 수수료 가정으로 계산한다.
- 원금과 운용 결과를 분리한다.
- 특정 구간만 골라 유리하게 보여주지 않는다.
- “과거 결과는 미래 성과를 보장하지 않는다”를 명시한다.
- 과거 후회로 끝내지 않고 `오늘부터 계산하기`로 연결한다.

**다음 행동:** `내 노후 월급 영향 보기`

### 6.3 노후 월급 부족분

**목적:** 수익률이 아니라 생활 수준의 차이로 연금의 의미를 이해하게 한다.

**화면 구성**

| 항목 | 표현 방식 |
|---|---|
| 목표 노후 월급 | 이용자가 선택한 생활 목표 또는 데모 가정 |
| 현재 예상 노후 월급 | 엔진의 적립·인출 가정 결과 |
| 월 부족분 | 목표와 예상의 차이 |
| 오늘부터의 개선 경로 | 월 납입·기간·위험수준 변경 시 범위 비교 |

**화면 메시지**

> “지금의 계좌 구성만 유지할 경우와, 운용 기준을 세워 분산할 경우의 예상 노후 월급은 다를 수 있어요. 어느 결과도 보장되지 않으며, 가정과 위험을 함께 확인해 보세요.”

모든 금액은 다음 칩으로 표시한다.

- `[목데이터: 계좌 잔액·나이]`
- `[가정: 월 납입액·은퇴 나이·수익률·물가·인출 기간]`
- `[출처: 상품 수수료·공시 데이터, 기준일]`

**다음 행동:** `내 직업과 연금의 겹침 보기`

### 6.4 직업-연금 중복노출 진단

**목적:** 월급과 연금이 같은 업황에 동시에 흔들릴 가능성을 설명한다.

**입력**

- 이용자가 선택한 근무 산업
- 연금 포트폴리오의 산업별 노출
- 회사 주식·우리사주 보유 여부(데모에서는 미보유로 가정)

**화면 메시지**

> “김직장님의 월급은 반도체 업황의 영향을 받을 수 있고, 연금의 기술 섹터 비중도 높습니다. 업황이 나빠질 때 소득과 자산이 함께 영향을 받을 수 있는 중복노출을 점검해 보세요.”

**설명 원칙**

- 근무 산업이 같다는 사실만으로 손실을 단정하지 않는다.
- 고용 감소나 임금 하락을 숫자로 예측하지 않는다.
- 특정 반대 섹터에 집중하도록 권하지 않는다.
- 관련 산업 비중을 줄이고 폭넓게 분산하는 방향을 교육용으로 제시한다.

**다음 행동:** `분산 제안 보기`

### 6.5 리밸런싱 제안과 근거

**목적:** 사용자에게 ‘한 가지 정답 상품’이 아니라, 계좌의 중복위험과 방치자금을 줄이는 교육용 조정안을 보여준다.

#### 제안 방향

- 현금성·원리금보장 자산 중 장기 운용 목적 자금의 기준을 세운다.
- 기술 섹터 관련 위험자산의 과도한 편중을 낮춘다.
- 위험자산 안에서는 넓은 시장·자산군 분산을 우선 검토한다.
- 위험자산 합계는 투자성향별 한도와 DC형 법정 한도를 모두 통과해야 한다.

#### 데모용 조정안

| 구분 | 현재 | 교육용 조정안 | 설명 |
|---|---:|---:|---|
| 안전자산 | 55% | 40% | 비상자금과 계좌 규칙을 고려한 안전판 유지 |
| 기술 섹터 관련 위험자산 | 35% | 15% | 근무 산업과의 중복노출 완화 |
| 폭넓게 분산된 위험자산 | 10% | 45% | 단일 산업 쏠림 대신 분산 원칙 학습 |
| 위험자산 합계 | 45% | 60% | DC형 위험자산 70% 한도 이내 |

> `[MVP 교육용 가정: 중립 성향 시나리오]`
> 실제 상품 후보와 위험자산 분류는 금융사별 매매 가능 목록과 공시 데이터를 바탕으로 별도 검증한다.

#### 제안 근거 카드

제안에는 최소 세 가지 근거를 항상 함께 표시한다.

1. **방치 자금:** 현금성·원리금보장 자산 비중이 55%다. `[목데이터]`
2. **중복노출:** 근무 산업과 기술 섹터 위험자산이 겹친다. `[목데이터 + 산업 분류 가정]`
3. **계좌 규칙:** 조정 후 위험자산은 60%로 DC형 70% 한도 안이다. `[공식 규칙 + 엔진 계산]`

**다음 행동:** `크루의 운영 경험 보기`

### 6.6 크루 후기 확인

**목적:** 상품 추천이 아니라 ‘연금 관리를 시작한 사람의 경험’을 통해 불안을 낮춘다.

**대상 크루:** `DC 초보 리부트 크루` — 데모용 목데이터

**후기 화면 구성**

- 실제 참여자 여부를 나타내는 데모 배지
- 초보자 친화도, 정보 유용성, 질문 활성도, 동기부여 등 활동 경험 항목
- 장점·주의점 태그
- 최신순·도움순 정렬 예시
- 긍정·부정 내용을 함께 보여주는 요약

**후기 예시**

> “처음에는 상품을 고르는 곳인 줄 알았는데, 내 계좌부터 읽는 순서를 배워서 덜 불안했어요.” `[목데이터: 크루 후기 예시]`

> “질문에 답을 받기까지 시간이 걸렸지만, 체크리스트가 있어서 금융사 앱에서 직접 확인할 수 있었어요.” `[목데이터: 크루 후기 예시]`

**금지 사항**

- 상품 수익률 별점
- ‘수익이 좋다’는 후기 기반 추천
- 실제 보유금액·손익 인증
- 다른 사용자의 포트폴리오 따라 하기

**다음 행동:** `제안 검토 후 모의 실행하기`

### 6.7 원탭 모의 체결

**목적:** 실제 주문 없이 사용자가 제안을 검토하고 결정하는 경험을 제공한다.

**실행 전 확인 화면**

- 현재 비중과 조정안 비교
- 위험자산 한도 검사 결과
- 투자성향 적합성 결과
- 제안 근거 3개
- 모든 수치의 가정·출처 칩
- “실제 주문이 아닌 모의 체결입니다” 고지

**사용자 선택**

- `이 조정안을 모의 실행한다`
- `조정안을 다시 비교한다`
- `체크리스트만 저장한다`

승인은 사용자만 할 수 있으며, AI가 자동으로 체결하지 않는다.

### 6.8 개선 결과 표시

**목적:** 수익 보장이 아니라 ‘무엇이 어떻게 달라졌는지’를 이해시키고 다음 점검 행동을 남긴다.

**결과 화면**

- 현금성·기술 섹터·분산 위험자산 비중의 변화
- 위험자산 70% 한도 통과
- 소득-자산 중복노출 감소 설명
- 가정에 따른 예상 노후 월급 범위 변화
- 하락장 가정에서의 위험 분산 설명
- 다음 점검일과 체크리스트

**화면 메시지**

> “수익을 보장하는 조정은 아닙니다. 다만 방치자금과 특정 산업 쏠림을 줄이고, 현재 성향에서 감당 가능한 위험 범위 안으로 계좌 기준을 세웠습니다.”

## 7. 설명 Q&A

어느 화면에서든 다음 질문에 답할 수 있다.

- “왜 현금성 자산이 많으면 점검이 필요한가요?”
- “또래가 투자하는 상품을 보여주지 않는 이유는 무엇인가요?”
- “내 직업과 연금이 왜 함께 위험할 수 있나요?”
- “왜 기술 섹터를 전부 팔라고 하지 않나요?”
- “위험자산 70% 한도는 어떻게 확인하나요?”
- “이 조정안을 실행하면 수익이 보장되나요?”

응답은 엔진 결과와 승인된 콘텐츠만 사용하며, 수치가 포함될 때마다 가정 또는 출처를 표시한다.

## 8. 시스템과 데이터 구조

```text
[모바일 PWA]
  계좌 진단 · 시뮬레이션 · 크루 후기 · 모의 체결
        │
[FastAPI + LLM 하네스]
  엔진 호출 · 설명 생성 · 수치 대조 검증
        │
[규칙 엔진]
  자산군 분류 · 적립 계산 · 섹터 중복노출 · 한도 검사 · 제안 생성
        │
[데이터]
  사용자 계좌/후기: 목데이터
  시장 상품/수수료: 통합연금포털·KRX 등 실데이터
```

### 데이터 출처 칩 기준

| 칩 | 의미 |
|---|---|
| `[목데이터]` | 사용자 계좌, 페르소나, 크루 후기, 또래 행동 시나리오 |
| `[가정]` | 수익률, 물가, 납입액, 은퇴 나이, 인출 기간, 스트레스 수준 |
| `[출처]` | 시장 상품 수수료·수익률·제도 규칙의 실데이터 |
| `[엔진 계산]` | 목데이터·가정·실데이터를 입력해 계산한 결과 |

## 9. 데모 검증 기준

### 필수 완료 기준

1. 위 8단계가 끊김 없이 완주된다.
2. 모든 수치에 `[목데이터]`, `[가정]`, `[출처]`, `[엔진 계산]` 중 하나가 표시된다.
3. 제안 카드마다 근거가 3개 이상 표시된다.
4. 위험자산 70%를 넘는 조정안은 생성되지 않는다.
5. 실제 주문·계좌 연동·자동 일임은 발생하지 않는다.
6. Q&A 수치는 엔진 결과와 100% 일치한다.

### 사용자 테스트 질문

- 이 계좌의 가장 큰 문제는 무엇이었나요?
- 기술 섹터 비중을 줄인 이유는 무엇인가요?
- 조정안이 위험자산 한도를 넘지 않는 이유는 무엇인가요?
- 실제 금융사 앱에서 다음에 무엇을 확인하시겠어요?

## 10. MVP 범위와 이후 확장

### 첫 데모에 포함

- 방치형 DC 계좌 목데이터 1종

- 노후 월급 부족분 시뮬레이션
- 직업-연금 중복노출 진단
- 교육용 리밸런싱 제안
- 크루 후기 목데이터 조회
- 원탭 모의 체결

- 다양한 직업·산업 분류와 중복노출 데이터 고도화
- IRP·연금저축 통합 진단
